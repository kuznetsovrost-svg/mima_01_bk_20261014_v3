Часть I. Основы IDEF0
=====================


Глава 1. Элементы IDEF0
-----------------------

1.1 Function (Activity)

    Прямоугольник, изображает функцию/действие.
    Содержит:
    - Имя функции (по центру)
    - Номер блока (в нижнем левом углу)

1.2 Стрелки ICOM

    I — Input (слева)         — что преобразуется
    C — Control (сверху)      — правила, стандарты
    O — Output (справа)       — результат
    M — Mechanism (снизу)     — ресурсы, исполнители

1.3 ICOM-коды

    Соглашение: каждая стрелка имеет уникальный код в пределах
    диаграммы (I1, I2, C1, O1, M1, ...)

1.4 Уровни декомпозиции

    A-0 — контекстная (один блок, общая картина)
    A0 — декомпозиция A-0
    A1, A2, ... — декомпозиция блоков A0
    A11, A12, ... — декомпозиция блоков A1
    и т.д.


Глава 2. Соглашения по именованию блоков
----------------------------------------

2.1 Структура блока

    Канонический вид:

    ┌─────────────────────────┐
    │                         │
    │   Имя функции           │  ← функция (центр)
    │                         │
    │ A1.2                    │  ← номер (нижний левый угол)
    └─────────────────────────┘

2.2 Реализация в Excalidraw

    Блок = группа из 3 элементов:

    {
      "id": "block-A1-2",
      "type": "rectangle",
      "x": 100, "y": 100,
      "width": 200, "height": 100,
      "groupIds": ["group-A1-2"]
    },
    {
      "id": "func-A1-2",
      "type": "text",
      "text": "Разработка чертежей",
      "x": 120, "y": 140,
      "width": 160, "height": 20,
      "textAlign": "center",
      "groupIds": ["group-A1-2"]
    },
    {
      "id": "num-A1-2",
      "type": "text",
      "text": "A1.2",
      "x": 105, "y": 175,
      "width": 30, "height": 15,
      "textAlign": "left",
      "groupIds": ["group-A1-2"]
    }

2.3 Соглашения по ID

    Элемент           ID
    ─────────────────  ──────────
    Прямоугольник      block-<номер>
    Текст функции     func-<номер>
    Текст номера      num-<номер>
    Имя группы        group-<номер>

2.4 Размеры текста

    Функция: 16-20 px
    Номер: 10-12 px

2.5 ⚠️ Комментарий для скилла

    Скилл должен:
    - находить блоки по groupIds
    - извлекать номер (num-<X>) и имя (func-<X>)
    - строить маппинг номер → координаты блока
    - учитывать текст "На основании" / "получает" / etc.


Глава 3. Уровни диаграммы (Frame)
----------------------------------

3.1 Каждый уровень = Frame

    Имя Frame включает:
    - Код уровня (A-0, A0, A1, ...)
    - Описание функции
    - Parent (родительский блок)

    Формат имени: "A<n> <Описание> (parent: A<m>-<код>)"

3.2 Примеры имён

    "A-0 Контекст"
    "A0 Декомпозиция (parent: A-0)"
    "A1 Обработка заявки (parent: A0-2)"
    "A11 Подзадача (parent: A1-1)"

3.3 Связь parent-child

    В имени Frame указывается parent:
    - Frame "A1" связан с блоком A0-2
    - При валидации ICOM consistency проверяем
      соответствие ICOM блока A0-2 и ICOM диаграммы A1

3.4 ⚠️ Что я НЕ делаю с Frame

    - объект в одном Frame (уже обсуждали)
    - стрелки внутри Frame — нормально
    - стрелки между Frame — НЕТ (IDEF0 их не предусматривает)

3.5 ⚠️ Комментарий для скилла

    Скилл должен:
    - парсить имя Frame для извлечения кода уровня
    - извлекать parent из скобок "(parent: ...)"
    - строить дерево декомпозиции (A-0 → A0 → A1 → ...)
    - связывать Frame с блоком в parent диаграмме


Часть 4. Стрелки ICOM
----------------------

4.1 Грани стрелок

    Каждая стрелка присоединена к ОДНОЙ из граней блока:
    - левая (Input)
    - правая (Output)
    - верхняя (Control)
    - нижняя (Mechanism)

4.2 Определение грани (алгоритм)

    Конец стрелки:
    end_x = arrow.x + arrow.points[-1][0]
    end_y = arrow.y + arrow.points[-1][1]

    Блок:
    left = block.x
    right = block.x + block.width
    top = block.y
    bottom = block.y + block.height

    Какая грань ближе всего:
    distances = {
      "left": abs(end_x - left),
      "right": abs(end_x - right),
      "top": abs(end_y - top),
      "bottom": abs(end_y - bottom)
    }
    nearest_side = min(distances, key=distances.get)

4.3 Стрелки с одним свободным концом (граничные)

    - конец привязан к блоку
    - начало у границы Frame

    Это ICOM листа (вход/выход между уровнями)

4.4 Стрелки между блоками

    - оба конца привязаны к блокам
    - не являются граничными
    - описываются только внутри диаграммы

4.5 ⚠️ Комментарий для скилла

    Скилл должен:
    - точно определять грань по координатам
    - различать bound и free концы стрелки
    - учитывать что стрелка может быть привязана к углу
      (тогда нужна доп. логика)
    - для Frame учитывать что координаты относительные,
      если внутри другого Frame


Часть 5. ICOM Consistency Check (связность parent ↔ child)
-----------------------------------------------------------

5.1 Что проверяется

    Число, имена и род ICOM блока на parent должны совпадать
    с ICOM всей child диаграммы.

5.2 Пример

    Parent: блок A0-2 имеет:
      Inputs (слева): I1, I2, I3
      Controls (сверху): C1, C2
      Outputs (справа): O1, O2
      Mechanisms (снизу): M1, M2, M3, M4

    Child: диаграмма A2 (декомпозиция A0-2) должна иметь:
      Inputs (граничные слева): I1, I2, I3
      Controls (граничные сверху): C1, C2
      Outputs (граничные справа): O1, O2
      Mechanisms (граничные снизу): M1, M2, M3, M4

5.3 Алгоритм

    def check_icom_consistency(parent_block, child_frame):
        # 1. Извлечь ICOM блока на parent
        parent_icom = extract_icom_from_block(parent_block)

        # 2. Извлечь ICOM всей диаграммы
        child_icom = extract_icom_from_frame(child_frame)

        # 3. Сравнить по множествам
        errors = []
        for role in ["input", "control", "output", "mechanism"]:
            if set(parent_icom[role]) != set(child_icom[role]):
                errors.append(...)

        return errors

5.4 Типы ошибок

    - "Стрелка X отсутствует в child"
    - "Лишняя стрелка Y в child"
    - "Стрелка Z на неправильной грани"

5.5 ⚠️ Комментарий для скилла

    Скилл должен:
    - автоматически находить parent-child связи по имени Frame
    - извлекать ICOM из parent блока (по стрелкам к нему)
    - извлекать ICOM из child Frame (граничные стрелки)
    - сравнивать и выдавать отчёт
    - поддерживать туннели (см. Часть 6)


Часть 6. Туннелирование
------------------------

6.1 Что такое туннель

    Стрелка, которая НЕ декомпозируется в child диаграмме
    как обычно — она "проходит насквозь" и попадает в ICOM
    листа.

6.2 Нотация

    Визуально: пара круглых скобок ( ) вокруг точки привязки
    стрелки к блоку.

6.3 Разметка в Excalidraw

    Туннель обозначается в тексте стрелки:
    - "( I1 входной документ" — туннель на конце стрелки
    - "I1 входной документ )" — туннель на начале
    - "( I1 входной документ )" — туннель с обеих сторон
    - "I1 входной документ" — обычная (не туннель)

6.4 Согласованность с туннелями

    - туннелированная стрелка → должна быть в ICOM листа child
    - обычная стрелка → должна быть в блоках child
    - потерянная стрелка → ошибка
    - лишняя стрелка → ошибка

6.5 ⚠️ Комментарий для скилла

    Скилл должен:
    - парсить скобки ( ) в тексте стрелки
    - отличать скобки-маркеры от скобок в самом тексте
      (эвристика: скобки в начале или конце текста)
    - при анализе ICOM consistency учитывать туннели


Часть 7. Каталог объектов (Arrow Catalogue)
---------------------------------------------

7.1 Что это

    Обязательная таблица для каждой диаграммы, описывающая
    ВСЕ стрелки на этой диаграмме.

7.2 Формат таблицы

    | Имя стрелки    | Источник            | Получатель        | Тип |
    |----------------|---------------------|-------------------|-----|
    | Заявка клиента | Граница             | Блок 1            | I   |
    | Правила        | Граница             | Блок 1, 2, 3      | C   |
    | Отчёт          | Блок 2              | Граница           | O   |

7.3 Разметка в Excalidraw

    Вариант 1: Frame "Arrow Catalogue A2" внутри диаграммы
    Вариант 2: Прямоугольник + тексты внутри диаграммы
    Вариант 3: Sidecar JSON файл

7.4 Источник/Получатель

    - Имя конкретного блока
    - "Граница" — если стрелка касается границы Frame

7.5 ⚠️ Комментарий для скилла

    Скилл должен:
    - находить Frame "Arrow Catalogue <имя_диаграммы>"
    - парсить таблицу из текстов внутри
    - проверять полноту (все стрелки описаны)
    - проверять корректность (источник/получатель существуют)
    - генерировать каталог автоматически если отсутствует


Часть 8. Описание листа диаграммы (Node Description)
-----------------------------------------------------

8.1 Что это

    Связный "гуманизированный" текст, описывающий каждый
    блок диаграммы по стандартному шаблону.

8.2 Шаблон

    "Блок {номер}. {Имя}.
    На основании {Controls — сверху},
    получает {Inputs — слева},
    выдаёт {Outputs — справа},
    опираясь на {Mechanisms — снизу}."

8.3 Порядок обхода блоков

    Сначала блок с наименьшим номером (или самый левый).
    Далее по часовой стрелке.

8.4 Сортировка стрелок на грани

    - Сверху/снизу: слева направо
    - Слева/справа: сверху вниз

8.5 Формат перечисления

    - 1 элемент: "X"
    - 2 элемента: "X и Y"
    - 3+ элемента: "X, Y, Z и W"

8.6 Пример результата

    "Блок 1. Обработка заявки. На основании "Правила работы"
    и "Стандарты", получает "Заявка клиента", выдаёт
    "Заявка проверенная", опираясь на "Менеджер".

    Блок 2. Проверка. На основании "Правила", получает
    "Заявка проверенная", выдаёт "Отчёт", опираясь
    на "База данных"."

8.7 ⚠️ Комментарий для скилла

    Скилл должен:
    - сортировать блоки по (x, y)
    - для каждого блока находить стрелки по 4 граням
    - генерировать текст по шаблону
    - обрабатывать пустые стороны (не упоминать или
      "не указано")
    - выдавать результат абзацами


Часть 9. Соглашения по разметке (полный список)
-----------------------------------------------

9.1 ID элементов

    block-<номер>      прямоугольник
    func-<номер>       текст функции
    num-<номер>        текст номера
    group-<номер>      имя группы
    arrow-<id>         стрелка
    frame-<id>         Frame

9.2 Имена Frame

    "A-0 Контекст"
    "A0 (parent: A-0)"
    "A1 Описание (parent: A0-2)"
    "Arrow Catalogue A2"

9.3 Структура текста стрелки

    Без туннеля: "I1 Имя объекта"
    С туннелем: "( I1 Имя объекта" или "I1 Имя объекта )"

9.4 Размеры

    Блок: 200x100 px (рекомендация)
    Стрелка: свободная
    Frame: на 20-50 px больше содержимого
    Таблица каталога: 400x300 px

9.5 Стили (опционально)

    Стрелка Control: синий
    Стрелка Input: зелёный
    Стрелка Output: красный
    Стрелка Mechanism: оранжевый
    ⚠️ стили я читаю, но не использую для логики


Часть 10. Чеклист валидной IDEF0 диаграммы в Excalidraw
--------------------------------------------------------

[ ] Все блоки = группа из 3 элементов (rect + func + num)
[ ] Все блоки имеют уникальные номера в пределах диаграммы
[ ] Все стрелки имеют ICOM-коды (I1, C1, ...)
[ ] Стрелки присоединены к граням блоков (не к углам)
[ ] Каждый уровень = отдельный Frame
[ ] Frame содержит "(parent: ...)" для parent-child связи
[ ] Каталог объектов присутствует внутри каждого Frame
[ ] Каталог = Frame "Arrow Catalogue <X>"
[ ] Туннели обозначены скобками ( ) в тексте стрелки
[ ] Граничные стрелки корректно размещены у границ Frame
[ ] Описания блоков сгенерированы (или могут быть)
[ ] ICOM consistency между parent и child проверена
[ ] Нет потерянных стрелок при декомпозиции
[ ] Нет лишних стрелок в child

Часть 13. Скилл IDEF0-Excalidraw (будущая реализация)

13.1 Структура скилла

    skills/creative/idef0-excalidraw/
    ├── SKILL.md
    ├── scripts/
    │   ├── excalidraw_parser.py     # парсер .excalidraw
    │   ├── block_extractor.py       # извлечение блоков
    │   ├── arrow_extractor.py       # извлечение стрелок
    │   ├── side_detector.py        # определение грани
    │   ├── icom_checker.py          # ICOM consistency
    │   ├── tunnel_detector.py       # обнаружение туннелей
    │   ├── catalogue_parser.py      # парсер каталога
    │   ├── catalogue_generator.py   # генерация каталога
    │   ├── description_generator.py # генерация описаний
    │   └── validator.py             # главный модуль
    ├── references/
    │   ├── idef0-rules.md           # правила IDEF0
    │   ├── excalidraw-conventions.md # соглашения разметки
    │   └── examples.md              # примеры
    └── templates/
        └── idef0-template.excalidraw # пустой шаблон

13.2 Входы скилла

    - path: путь к .excalidraw файлу
    - operation: validate | generate-catalogue | generate-description | check-icom
    - options: дополнительные параметры

13.3 Выходы скилла

    - validate: список ошибок и предупреждений
    - generate-catalogue: таблица каталога объектов
    - generate-description: текст описания листа
    - check-icom: отчёт о consistency parent ↔ child

13.4 Ключевые функции

    1. Парсинг .excalidraw → структурированное представление
    2. Извлечение блоков (с номерами и именами)
    3. Извлечение стрелок (с гранями и ICOM-кодами)
    4. Определение туннелей (скобки в тексте)
    5. Валидация ICOM consistency
    6. Генерация каталога объектов
    7. Генерация описаний блоков

13.5 ⚠️ Граф зависимостей

    excalidraw_parser → block_extractor → arrow_extractor
              ↓                ↓                  ↓
        side_detector     icom_checker    tunnel_detector
              ↓                ↓                  ↓
              └────────────────┴──────────────────┘
                                ↓
                         validator (главный)
                                ↓
         ┌────────────────────┼────────────────────┐
         ↓                    ↓                    ↓
    catalogue_parser  catalogue_generator  description_generator

13.6 Этапы реализации

    Этап 1: парсер + извлечение блоков и стрелок
    Этап 2: определение граней + туннелей
    Этап 3: ICOM consistency check
    Этап 4: генерация каталога
    Этап 5: генерация описаний
    Этап 6: главный validator с CLI

13.7 API (черновик)

    # CLI
    hermes skills run idef0-excalidraw validate \
      --file path/to/diagram.excalidraw

    hermes skills run idef0-excalidraw generate-catalogue \

      --frame "A2"

    hermes skills run idef0-excalidraw check-icom \
      --file path/to/diagram.excalidraw \
      --parent "A0" \
      --child "A2"

    # Python API
    from idef0_excalidraw import Validator

    v = Validator("path/to/diagram.excalidraw")
    errors = v.validate_all()
    for err in errors:
        print(err)
