1. ГЛАВНОЕ ПРАВИЛО
═══════════════════════════════════════════════════════════════════

В Figma — ДВА (или больше) ОТДЕЛЬНЫХ Text-слоя:
  • Статический текст (никогда не меняется) — с именем txt.static.<...>
  • Динамический текст (плейсхолдер) — с именем {category.field}

В HTML это становится ОДНИМ логическим заголовком, но состоящим
из нескольких <span>-обёрток.

  ┌──────────────────────────────────────────────────────────────┐
  │ Figma:  [txt.static.prefix]   [{report.title}]               │
  │ HTML:   <span class="static">...</span>                      │
  │         <span class="dynamic">{{ title }}</span>             │
  └──────────────────────────────────────────────────────────────┘

2. ПОЧЕМУ ИМЕННО 2 СЛОЯ
═══════════════════════════════════════════════════════════════════

2.1. Разные стили
─────────────────
  Статика может быть одним шрифтом/цветом/размером, динамика —
  другим.

  Пример:
    Общая оценка здоровья проекта (чёрный, 32px)
    Космодром Жуковский внедрение ИСУП (синий, 32px) ← акцент

2.2. Разные плейсхолдеры
────────────────────────
  У статики нет плейсхолдера (это просто текст).
  У динамики — {report.title}.

2.3. Чистый экспорт плагина
────────────────────────────
  Плагин сгенерирует:
    <span class="report__prefix">Общая оценка здоровья проекта</span>
    <span class="report__project-name">{{ report.title }}</span>

  Можно стилизовать каждую часть отдельно через CSS.

2.4. Семантика для скринридеров
────────────────────────────────
  Два <span> с разными классами лучше для accessibility, чем
  один большой <span> со склеенным текстом.

2.5. SEO
─────────
  Поисковики лучше понимают структуру заголовка, если она
  семантически разбита.

3. КОНВЕНЦИЯ ИМЁН В FIGMA
═══════════════════════════════════════════════════════════════════

3.1. Статический текст
──────────────────────

  Префикс: txt.static.<role>

  Возможные имена:
    txt.static.report-prefix      "Общая оценка здоровья проекта"
    txt.static.report-suffix      "с точки зрения сроков"
    txt.static.section-prefix     "Раздел:"
    txt.static.page-prefix        "Страница"

3.2. Динамический текст
───────────────────────

  Стандартный placeholder: {category.field}

  Возможные имена:
    {report.title}               "Космодром Жуковский внедрение ИСУП"
    {report.subtitle}            "Квартальная сводка"
    {report.database}            "project_504-595_db"
    {section.title}              "Список замечаний по срокам"
    {page.title}                 "Название страницы"

3.3. Имена родительских Frame'ов
─────────────────────────────────

  Префиксы для типов контейнеров:
    sec.    <section>
    grp.    <div class="row"> или <div class="group">
    h1, h2, h3, h4, h5, h6  ← логические заголовки
    ph.     <div class="placeholder">

  Для всего заголовка отчёта:
    sec.header          ← секция с заголовком
    sec.header.h1       ← сам логический <h1>
    sec.header.meta     ← подзаголовок / мета

7. ПЛОХИЕ ПАТТЕРНЫ (чего НЕ делать)
═══════════════════════════════════════════════════════════════════

7.1. ❌ Всё в одном слое с конкатенацией
───────────────────────────────────────

  Text: "Общая оценка здоровья проекта {report.title}"

  Почему плохо:
    • Плагин не поймёт где статика, где плейсхолдер
    • Экспортируется как один большой <span>
    • Невозможно стилизовать части отдельно

7.2. ❌ Плейсхолдер в нестандартном формате
────────────────────────────────────────────

  Text: "{Report.Title}"           ← заглавные
  Text: "{report.title:default}"   ← значение по умолчанию
  Text: "{{report.title}}"         ← двойные скобки

7.3. ❌ Реальное название в макете
──────────────────────────────────

  Text: "Общая оценка здоровья проекта Космодром Жуковский"

  Почему плохо:
    • Это уже не шаблон, это конкретный отчёт
    • Нельзя переиспользовать для других проектов

7.4. ❌ Кириллица в placeholder-имени
────────────────────────────────────

  Text: "{отчёт.заголовок}"

  Почему плохо:
    • Парсер может не понять
    • Кодировка может потеряться
    • Лучше всегда латиница

7.5. ❌ Разный регистр в одном проекте
──────────────────────────────────────

  {Report.title} vs {report.Title}

  Почему плохо:
    • Будет два разных плейсхолдера
    • Путаница в шаблонизаторе

13. ВАЛИДАЦИЯ — ЧЕК-ЛИСТ ПЕРЕД ЭКСПОРТОМ
═══════════════════════════════════════════════════════════════════

Структура:
  [ ] Статика и динамика — РАЗНЫЕ Text-слои
  [ ] Все Text-слои в одном Auto Layout (horizontal или vertical)
  [ ] Auto Layout имеет явный gap
  [ ] Frame называется по конвенции (sec.header, h1, h2, ...)

Имена:
  [ ] Статика называется с префиксом txt.static.<role>
  [ ] Динамика называется {category.field}
  [ ] Все placeholder-имена lowercase
  [ ] Все placeholder-имена в snake_case
  [ ] Никаких кириллических placeholder-имён
  [ ] Никаких реальных значений в placeholder-имени

Стили:
  [ ] Каждый Text-слой имеет явный стиль (font, size, color)
  [ ] Используются Figma Text Styles (не inline-стили)
  [ ] Используются Figma Color Styles (не inline-цвета)
  [ ] Размеры: статика и динамика могут быть разными

Контент:
  [ ] Никаких реальных значений в динамических слоях
  [ ] Никаких реальных значений в статических слоях
  [ ] Никаких смешений в одном слое

15. ИНСТРУМЕНТ FIGMA — AUTO LAYOUT PROPERTIES
═══════════════════════════════════════════════════════════════════

Чтобы Auto Layout работал правильно:

  Primary axis (главная ось):
    - Horizontal layout: align = min/center/max/space-between
    - Vertical layout: align = min/center/max/space-between

  Counter axis (поперечная ось):
    - Horizontal layout: align = min/center/max/stretch
    - Vertical layout: align = min/center/max/stretch

  Padding:
    - Top / Right / Bottom / Left (можно задать каждый отдельно)
    - Или выбрать "Both axes" для одинакового

  Gap (itemSpacing):
    - Расстояние между детьми
    - Для заголовков рекомендую 4-8px

  Resizing:
    - Hug contents — Frame сжимается по контенту
    - Fill container — растягивается
    - Fixed — фиксированный размер
