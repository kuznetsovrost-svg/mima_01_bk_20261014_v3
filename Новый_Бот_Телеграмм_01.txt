# Как создать нового бота в Telegram — полный гайд 2026
## (для Hermes Agent, аналогичных Python-шлюзов и интеграций)

────────────────────────────────────────────────────────────────────────────
0. ЧТО В ИТОГЕ БУДЕТ
────────────────────────────────────────────────────────────────────────────

После прохождения всех шагов у тебя будет:

  • Зарегистрированный бот в Telegram с уникальным именем (@username)
  • Токен вида `110201543:AAHdqddcvI1J_xLj8S2K4au9bF8…`
  • Бот, который отвечает на /start и принимает сообщения
  • Бот, подключённый к Hermes Agent (или любому другому шлюзу)
  • Закрытые глаза: чеклист по безопасности и FAQ

Весь процесс занимает 5-10 минут. Без знания программирования на этапе
создания, но с минимальной командной строкой на этапе подключения.

────────────────────────────────────────────────────────────────────────────
1. ПРЕДУСЛОВИЯ
────────────────────────────────────────────────────────────────────────────

Нужно:

1.1. Аккаунт Telegram (тот же аккаунт станет «owner» бота).
1.2. Установленное мобильное приложение Telegram или Telegram Desktop
     (на web-версии создать бота тоже можно, но мобильное удобнее — там
     сразу можно загрузить аватарку).
1.3. Свободное имя для бота:
       - должно быть уникальным в пределах всех Telegram-ботов;
       - должно заканчиваться на `bot`, например `MyCoolBot`, `mima_g_01_bot`;
       - может содержать латиницу, цифры и подчёркивания;
       - 5-32 символа (на 2026 минимум 5, максимум 32);
       - регистронезависимо, но лучше snake_case, чтобы совпадало с @username.
1.4. Если бот будет работать в группе/канале — реши заранее, в каких
     именно. У Telegram два режима:
       - Privacy mode ON (по умолчанию) — бот видит ТОЛЬКО сообщения,
         начинающиеся с `/command` или с упоминания @botusername.
       - Privacy mode OFF — бот видит все сообщения. Нужно отключить
         через @BotFather → Bot Settings → Group Privacy → Turn off.
         (Для приватной переписки 1-на-1 это неважно.)

────────────────────────────────────────────────────────────────────────────
2. СОЗДАНИЕ БОТА ЧЕРЕЗ @BotFather (ОСНОВНОЙ СПОСОБ)
────────────────────────────────────────────────────────────────────────────

Шаг 1. Открой Telegram, в строке поиска введи: **@BotFather**
        — официальный бот Telegram для создания других ботов.
        У него синяя галочка верификации, это официальный аккаунт.

Шаг 2. Нажми /start (или Send Message). BotFather покажет список команд.

Шаг 3. Создай бота:
        Отправь команду: /newbot

Шаг 4. BotFather попросит ввести **имя** (display name) — то, что видит
        пользователь в чате. Это может быть любая строка, например:
            Mima Hermes Bot
        Нажми Send.

Шаг 5. BotFather попросит ввести **username** — уникальный @username бота,
        должен заканчиваться на `bot`. Например:
            MimaG01_bot
        Если это имя уже занято — BotFather скажет «Sorry, this username
        is already taken. Please try something different.»

Шаг 6. После успешного создания BotFather пришлёт **сообщение с токеном**.
        Токен — это длинная строка вида:
            110201543:AAHdqddcvI1J_xLj8S2K4au9bF8h…(около 46 символов)

        ВАЖНО:
          • Это ЕДИНСТВЕННЫЙ раз, когда токен показывают в открытом виде.
          • Никому его не показывай (кроме своего шлюза/CLI).
          • Сохрани сразу (в парольный менеджер / ~/.env с chmod 600).
          • Если потерял — отзывай через /revoke и получай новый.

Шаг 7. Бот создан. Можно сразу:
          • открыть чат с ботом по @username (через поиск),
          • отправить ему /start — он ответит стандартным приветствием,
          • по желанию настроить описание, аватар и т.п. (см. раздел 4).

────────────────────────────────────────────────────────────────────────────
3. БЫСТРАЯ ПРОВЕРКА ТОКЕНА (БЕЗ КАКОГО-ЛИБО КОДА)
────────────────────────────────────────────────────────────────────────────

Через 30 секунд после создания проверь, что токен рабочий:

  # В терминале (Linux / macOS / WSL):
  curl -s "https://api.telegram.org/bot<ТОКЕН>/getMe"

Замени `<ТОКЕН>` на свой — БЕЗ `<>`. Должен вернуться JSON:

  {
    "ok": true,
    "result": {
      "id": 110201543,
      "is_bot": true,
      "first_name": "Mima Hermes Bot",
      "username": "MimaG01_bot",
      "can_join_groups": true,
      "can_read_all_group_messages": false,
      "supports_inline_queries": false,
      ...
    }
  }

Если HTTP 200 и `"ok": true` — бот живой.

Если HTTP 401:
  • Токен скопирован с ошибкой (пробел, перенос строки, потерян символ).
  • Токен отозван (/revoke).
  • Ты используешь старый токен после создания нового.

Если HTTP 404:
  • api.telegram.org недоступен из этой сети. Проверь DNS, IPv6-only
    сети (Telegram не дружит с IPv6-only — нужен IPv4 или fallback IP).
  • На этом сервере (mima-g-01) рабочий fallback IP: 149.154.166.110
    (см. `~/.hermes/messages-bot/Telegram-fallback.md`, если есть).

────────────────────────────────────────────────────────────────────────────
4. НАСТРОЙКА БОТА В @BotFather (НЕОБЯЗАТЕЛЬНО, НО РЕКОМЕНДУЕТСЯ)
────────────────────────────────────────────────────────────────────────────

Все настройки делаются командами в чате с @BotFather.
Каждая команда вызывает мини-визард: бот спрашивает имя username, к которому
применить настройку.

────────────────────────────────────────────────────────────────────────
4.1. Описание (Description)
────────────────────────────────────────────────────────────────────────
Команда: /setdescription
Спросит: «Choose a bot to change the description.»
Введи: @MimaG01_bot
Затем: до 512 символов текста, который видит пользователь ДО того, как
       нажал Start.
Пример:
  «Бот-помощник для работы с инфраструктурой mima_g_01.
   Отвечает на вопросы, выполняет команды, ведёт логи.»


────────────────────────────────────────────────────────────────────────
4.2. About text (короткий «About»)
────────────────────────────────────────────────────────────────────────
Команда: /setabouttext
Текст: до 120 символов, виден в профиле бота (как bio).
Пример:
  «Ассистент для mima_g_01. Hermes Agent backend.»


────────────────────────────────────────────────────────────────────────
4.3. Аватар (Profile picture)
────────────────────────────────────────────────────────────────────────
Команда: /setuserpic
Загрузишь квадратное изображение (рекомендую 512×512, минимум 150×150).
Лучше всего — логотип или что-то опознаваемое.


────────────────────────────────────────────────────────────────────────
4.4. Commands (список команд для меню)
────────────────────────────────────────────────────────────────────────
Команда: /setcommands
Формат: `command - description` (каждый на новой строке).
Пример:
  start - Запустить бота
  help - Список команд
  status - Статус шлюза
  cancel - Отменить текущую операцию

Это появится в меню как список подсказок при наборе `/`.


────────────────────────────────────────────────────────────────────────
4.5. Privacy mode (для групп)
────────────────────────────────────────────────────────────────────────
Команда: /setprivacy
Варианты:
  Enable — бот видит только /commands и обращения по @username
           (по умолчанию).
  Disable — бот видит ВСЕ сообщения в группе.

Для личного чата 1-на-1 это неважно. Для группы — обычно нужно
«Disable», если бот — полноценный ассистент.


────────────────────────────────────────────────────────────────────────
4.6. Удалить / отключить бота
────────────────────────────────────────────────────────────────────────
/deletebot — полностью удаляет бота (необратимо).
/revoke — выпускает новый токен (старый перестаёт работать).
/token — перевыпустить токен (альтернатива /revoke).


────────────────────────────────────────────────────────────────────────
5. ПОДКЛЮЧЕНИЕ БОТА К HERMES AGENT
────────────────────────────────────────────────────────────────────────────

Это «наш» вариант использования. После создания бота подключаем его
к Hermes-шлюзу, который уже работает на этом сервере.

────────────────────────────────────────────────────────────────────────
5.1. Записать токен и chat_id
────────────────────────────────────────────────────────────────────────
Файл: /root/.hermes/.env (mode 600)

  TELEGRAM_BOT_TOKEN=<ваш токен полностью>
  TELEGRAM_ALLOWED_USERS=<ваш chat_id>

Как узнать свой chat_id:
  1. Напишите что-нибудь боту (хотя бы /start).
  2. В браузере откройте:
       https://api.telegram.org/bot<ТОКЕН>/getUpdates
  3. В JSON найдите блок:
       "chat": { "id": 123456789, "type": "private", ... }
     Это и есть ваш chat_id.
  4. Добавьте его в TELEGRAM_ALLOWED_USERS.

Несколько пользователей — через запятую:
  TELEGRAM_ALLOWED_USERS=123456789,987654321

────────────────────────────────────────────────────────────────────────
5.2. Убедиться, что webhook пустой
────────────────────────────────────────────────────────────────────────
Hermes работает через long-polling, а не через webhook. Если раньше бот
работал с webhook (например, через другой сервис) — нужно его снести:

  curl -s "https://api.telegram.org/bot<ТОКЕН>/deleteWebhook?drop_pending_updates=false"

Ответ должен содержать: "description":"Webhook is already deleted" или
"Webhook was deleted".

Проверить:
  curl -s "https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo"
  Должно вернуть "url":"" и "pending_update_count":0.

────────────────────────────────────────────────────────────────────────
5.3. Перезапустить Hermes-gateway
────────────────────────────────────────────────────────────────────────
После смены .env:

  systemctl --user restart hermes-gateway.service
  systemctl --user status hermes-gateway.service --no-pager

Проверить логи:
  journalctl --user -u hermes-gateway.service -n 30 -f

Должно появиться что-то вроде:
  INFO gateway.platforms.telegram: [Telegram] Started polling
  INFO gateway.platforms.telegram: [Telegram] Connected as @MimaG01_bot

────────────────────────────────────────────────────────────────────────
5.4. Тест
────────────────────────────────────────────────────────────────────────
Напишите боту в Telegram:
  /start
Должен прийти ответ от Hermes.

  /help
Должен прийти список команд (если настроили через /setcommands).

Если молчит — проверить:
  • TELEGRAM_ALLOWED_USERS содержит ВАШ chat_id (иначе Hermes
    игнорирует все сообщения — by design, защита).
  • Telegram polling conflict? В логах — `Telegram polling conflict
    (1/5)`. Означает, что другой инстанс Hermes с этим же токеном
    уже держит long-poll. Останови его.
  • Firewall: 443/tcp к *.telegram.org должен быть открыт (выход).

────────────────────────────────────────────────────────────────────────
6. ТЕХНИЧЕСКИЕ ДЕТАЛИ (ЧТО ПОД КАПОТОМ)
────────────────────────────────────────────────────────────────────────────

6.1. Что такое токен.
   Токен = `{bot_id}:{auth_key}`.
   bot_id — публичный числовой ID бота, виден в @username_info.
   auth_key — секретная часть. Все запросы к Bot API авторизуются
   по этому токену. Telegram-сервер сверяет auth_key и bot_id.

   Никогда не отдавай токен третьим лицам. С токеном можно:
     • читать любые сообщения, отправленные боту,
     • слать сообщения от его имени ЛЮБЫМ пользователям,
     • получать данные профилей, присоединяться к группам,
     • делать inline-запросы.

   Если токен утёк — срочно /revoke и перевыпустить.

6.2. Альтернативный Bot API — local Bot API server.
   Для очень крупных ботов (>30 МБ файлов, десятки тысяч пользователей)
   Telegram предлагает self-hosted Bot API server. Нам он не нужен.

6.3. Мини-приложения (Mini Apps).
   С 2022 есть Telegram Mini Apps (WebApp внутри чата). Бот может
   отправлять кнопку с WebApp-URL. Создаётся в BotFather → Bot Settings
   → Menu Button → Configure Menu Button → Edit Menu Button URL.
   Для Hermes это не нужно (мини-приложения — клиент, а Hermes —
   текстовый ассистент).

6.4. Bot API vs MTProto.
   Всё, что описано выше — это Bot API (HTTP). Для Hermes этого хватает.
   Существует также MTProto API (полноценный Telegram-клиент на уровне
   сессии). Он нужен, если ты хочешь не бот, а полноценный user-аккаунт
   (со статусом «онлайн», чтением каналов и т.п.). Отдельная тема, не
   связана с BotFather.

────────────────────────────────────────────────────────────────────────
7. БЕЗОПАСНОСТЬ И ГИГИЕНА
────────────────────────────────────────────────────────────────────────────

7.1. Токен — это пароль.
   Хранить в /root/.hermes/.env (mode 600), не в git, не в логах.
   На этом сервере действует hermes-санитизация: токены, попадающие
   в логи или в команды, автоматически заменяются на `***`. Это
   нормальное поведение, не ошибка.

7.2. ALLOWED_USERS — обязателен.
   Без whitelist'а бот отвечает ЛЮБОМУ, кто ему напишет. Если бот
   управляет инфраструктурой — это дыра. Всегда задавай:

   TELEGRAM_ALLOWED_USERS=<chat_id>

   В Hermes это работает в первую очередь для входящих сообщений.
   Исходящие отправляются всем.

7.3. Webhook для production.
   Long-polling (по умолчанию в Hermes) хорош для low-latency +
   коротких периодов неактивности. Для high-throughput (>100 сообщений
   в минуту) рекомендуется webhook. Настраивается через:

   curl -F "url=https://your-server.example.com/webhook/telegram" \
        -F "allowed_updates=[\"message\",\"callback_query\"]" \
        "https://api.telegram.org/bot<ТОКЕН>/setWebhook"

   Hermes-pipeline пока long-polling.

7.4. Privacy mode в группах.
   Если бот работает в группе — выключи privacy mode через /setprivacy.
   Иначе бот будет видеть только /commands и ответы на свои сообщения.

7.5. Self-destruct timer на чувствительных сообщениях.
   Можно использовать `protected_content`, чтобы бот не мог переслать
   sensitive содержимое (есть в Bot API).

7.6. Логи.
   Храни локальные логи Hermes-gateway неограниченно, а в Telegram
   не засылай чувствительное. У Hermes есть маскирование токенов
   (`***`), но лучше явно не дублировать.

7.7. Ротация токена.
   /revoke или /token перевыпускает токен. Старый — не работает через
   1-5 минут. Нужно обновлять /root/.hermes/.env и перезапускать Hermes.

────────────────────────────────────────────────────────────────────────
8. ЧАСТЫЕ ВОПРОСЫ
────────────────────────────────────────────────────────────────────────────

Q: Бот создан, но не отвечает на /start.
A: Проверь:
   1. token в .env правильный.
   2. webhook пустой (deleteWebhook).
   3. TELEGRAM_ALLOWED_USERS содержит твой chat_id.
   4. Hermes-gateway в состоянии "active (running)".
   5. В journalctl видно "Started polling".

Q: «Sorry, this username is already taken.»
A: Имена ботов глобально уникальны (как @username). Попробуй другой
   вариант: добавь цифры, измени окончание на _bot/Bot/BOT.

Q: «Too many requests. Please retry later.»
A: Rate limit от Telegram. По умолчанию — 30 msg/sec глобально и
   1 msg/sec per chat. Hermes с этим справляется. Если бот массово
   отвечает — добавь rate limiter.

Q: «polling conflict (1/5)» в логах.
A: Другой инстанс держит long-poll. Проверь, не запущен ли Hermes
   дважды (`pgrep -a hermes`). Если на разных машинах — останови один.

Q: Как удалить бота?
A: /deletebot в @BotFather. Необратимо.

Q: Можно ли изменить @username?
A: Нет, @username — навсегда. Только создать нового бота.

Q: Можно ли иметь несколько ботов?
A: Да. Каждому — свой токен, отдельный Hermes-профиль (по желанию).
   Главное — на каждый бот только ОДИН активный gateway.

Q: Бот пишет пользователям, которые ему не писали. Это нормально?
A: Технически да (бот сам инициирует переписку), но пользователь
   должен либо уже быть с ботом в чате, либо прислать /start.
   Telegram ограничивает «cold-init» сообщения.

Q: Бот не видит сообщения в группе.
A: Включи privacy mode (см. 4.5) — по умолчанию бот видит только
   /commands и обращения по @username.

Q: Хочу добавить кнопки к сообщениям.
A: Через Bot API — Inline Keyboard. Hermes умеет (через UI-события).
   В @BotFather это не настраивается — только программно.

────────────────────────────────────────────────────────────────────────
12. ЗАКЛЮЧЕНИЕ
────────────────────────────────────────────────────────────────────────────

Создание бота — это буквально 5 минут и 3 команды в @BotFather.
Самое главное:
  1. Username уникален и заканчивается на «bot».
  2. Токен — это пароль, не утекает.
  3. ALLOWED_USERS в .env задан, иначе бот игнорирует всех.
  4. Webhook пустой (deleteWebhook) перед стартом gateway.

Если что-то пойдёт не так — чеклист §10 диагностирует 90% случаев.
Остальные 10% — смотреть в journalctl и `getWebhookInfo`.
