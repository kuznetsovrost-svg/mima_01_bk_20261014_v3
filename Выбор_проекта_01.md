# Выбор проекта по имени (workflow)

Процедура поиска `ProjectId` в системе Форсайт ПМ Практики, когда пользователь
знает только **имя проекта (Name)** и не уверен в точном написании.

Цель: вернуть пользователю однозначный `ProjectId`, сделав не более двух
уточняющих вопросов.

## Предусловия

- MCP сервер `fst_pmpractice` доступен (`hermes mcp list` → `connected`)
- В сессии загружен SKILL `fst-pmpractice`
- У агента есть инструмент `mcp__fst_pmpractice__get_view`

## Шаг 1. Получить список проектов

Вызвать view с проектами, в порядке приоритета:

```python
mcp__fst_pmpractice__get_view(entityName="Project", viewName="MyProject")
# → {columns: [...], data: [{ProjectId, Code, Name, ...}, ...]}

# fallback если MyProject пустой или недоступен:
mcp__fst_pmpractice__get_view(entityName="Project", viewName="AllProject")
# последний fallback:
mcp__fst_pmpractice__get_view(entityName="Project", viewName="ProjectParameter")
```

⚠️ View может вернуть разный набор колонок. Минимально нужны три: `ProjectId`,
`Code`, `Name`. Если в `data` нет `ProjectId` — искать по ключу `id`.

## Шаг 2. Отфильтровать по подстроке

```python
SUBSTRING = "ФГК"  # то, что ввёл пользователь

matches = [
    r for r in data["data"]
    if SUBSTRING.lower() in str(r.get("Name") or "").lower()
]
```

Регистронезависимый поиск (`lower()` с обеих сторон).

## Шаг 3. Ветвление по количеству совпадений

### 3a. `len(matches) == 0`

Агент отвечает:

> Не найдено ни одного проекта с «ФГК» в названии.
> Ближайшие по контексту:
> 1. 501-682 — ФГК Адаптация ИС УПД
> 2. 504-034 — ФГК Сопровождение 2026-2027
>
> Уточни запрос или выбери из списка.

Показать 3-5 проектов с наибольшим лексическим совпадением (можно по первому
слову или по портфелю из view).

### 3b. `len(matches) == 1`

Сразу вернуть результат без дополнительных вопросов:

> ProjectId = **1682**
> Проект «ФГК Адаптация ИС УПД» (Code: `501-682`)

### 3c. `len(matches) > 1`

Агент задаёт уточняющий вопрос пользователю:

> Найдено несколько проектов с «ФГК» в названии:

| # | Code | Name |
|---|------|------|
| 1 | `501-682` | ФГК Адаптация ИС УПД |
| 2 | `504-034` | ФГК Сопровождение 2026-2027 |
| 3 | `501-610` | ФГК Сопровождение 2023-2026 |

> Знаешь ли ты **Code** нужного проекта?
> - Если да — пришли Code (например, `501-682`).
> - Если нет — выбери номер из таблицы (1, 2 или 3) или пришли часть названия.

## Шаг 4. Обработка ответа пользователя

### 4a. Ответ похож на Code (формат `<NNN>-<NNN>`)

Распознать Code по наличию дефиса. Искать точное совпадение в исходных `rows`
**до фильтра**, а не в `matches` (вдруг Code проекта не содержит подстроку).

```python
code = user_message.strip()  # "501-682"
target = next(
    (r for r in data["data"] if str(r.get("Code") or "").strip() == code),
    None
)
if target:
    return target["ProjectId"]
else:
    # Code не найден — сообщить и вернуться к шагу 3c с обновлённым списком
```

Если Code не найден:

> Code «501-682» не найден. Возможно, имелось в виду:
> 1. 501-682 — ФГК Адаптация ИС УПД
> ...
>
> Пришли другой Code или выбери из списка.

### 4b. Ответ — целое число от 1 до len(matches)

```python
idx = int(user_message) - 1
if 0 <= idx < len(matches):
    return matches[idx]["ProjectId"]
```

### 4c. Ответ — похож на подстроку Name

Перефильтровать `matches` по новой подстроке и вернуться к шагу 3.

```python
matches = [r for r in matches if user_message.lower() in str(r.get("Name") or "").lower()]
# → переход к шагу 3
```

### 4d. Не распознано

> Не понял ответ. Пришли Code (формат «501-682») или номер 1..N.

## Шаг 5. Возврат результата

Когда ProjectId однозначно определён, агент отвечает пользователю:

> **ProjectId = `4034`**
>
> Это проект **ФГК Сопровождение 2026-2027** (Code: `504-034`).

Опционально добавить контекст из view (если есть в `data`):

- Статус (индикатор)
- Стадия (`ActivityPhaseName`)
- Руководитель (`ProjectLeader`)
- Профиль (`ProjectProfileName`)
- Даты `StartPlan` / `FinishPlan`

## Edge cases и защита от ошибок

| Случай | Как обрабатывать |
|--------|------------------|
| View вернул пустой `data` | Сообщить: «Нет доступных проектов. Возможно, нет прав или view пустой» |
| В `data` нет поля `ProjectId` | Использовать поле `id` (как fallback) |
| Подстрока совпадает с >20 проектами | Ограничить таблицу 10 строками + «и ещё N, уточни запрос» |
| Code в нестандартном формате (`501/682`, `501.682`) | Нормализовать: заменить `/` и `.` на `-` перед поиском |
| Пользователь меняет решение | После каждого ответа заново пройти шаги 3-4 |
| Подстрока пустая или пробельная | Не запускать поиск, попросить ввести имя |

## Практический прогон (зафиксированный)

| Шаг | Действие | Результат |
|-----|----------|-----------|
| Запрос пользователя | «Назови ProjectId проекта, где в Name "ФГК"» | — |
| 1 | `get_view(Project, MyProject)` | 4 проекта |
| 2 | Фильтр `Name LIKE %ФГК%` | 3 совпадения |
| 3c | Ветвление: показать таблицу | Ответ пользователю с таблицей |
| 4b | Пользователь: «2» | Берём `matches[1]` |
| 5 | Возврат | `ProjectId = 4034`, проект «ФГК Сопровождение 2026-2027» |

## Связь с другими скиллами

- Базовый SKILL: `fst-pmpractice` — там описаны форматы вызовов
  `get_view`, `get_entity_data`, `save_entity`
- Tool `mcp__fst_pmpractice__get_view` — единственный используемый здесь
- Для последующей работы с найденным проектом:
  `describe_entity(Project, data_id=<found_id>)`

## Будущие расширения

- Кэширование списка проектов в сессии (если пользователь будет искать
  несколько раз подряд)
- Поиск не только по `Name`, но и по `Code`, `Description`, `PortfolioName`
- Экспорт результата в файл (если проектов много)
