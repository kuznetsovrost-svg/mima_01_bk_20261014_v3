# Размеры скиллов в Hermes

## Максимальный размер скилла не в токенах, а в килобайтах

### Грубый расчёт

| Параметр | Значение |
|---|---|
| Символов в 1 KB кириллицы | ~800-1000 |
| Токенов в 1 KB русского текста | ~350-500 |
| Context window MiniMax M3 | 200 000 токенов |
| Бюджет на один скилл (10% контекста) | ~20 000 токенов |
| **= ~40-50 KB** | **практический потолок** |

### Почему потолок 40-50 KB

| Фактор | Как считать |
|---|---|
| Скилл загружается в контекст чата | `skill_view` вставляет целиком |
| Занимает место у других данных | SOUL + MEMORY + USER + другие скиллы + история |
| Если скилл > 20K токенов | начинает «выдавливать» историю |
| Если скилл > 50K токенов | контекст быстро переполняется |

### Что это значит на моих примерах

| Скилл | Размер | Комментарий |
|---|---|---|
| memory-hygiene | 10 KB | типичный |
| failsafe-rules | 11 KB | типичный |
| officecli | 26 KB | крупный, нормально |
| bundled `github` | 20-30 KB | большие |
| **SKILL-FST-HOWPROJET** | **88 KB** | **огромный, но работает** |
| Скиллы в `fst-control` | 5-30 KB | стандарт |

### Рекомендация по размеру

| Размер | Категория | Рекомендация |
|---|---|---|
| < 5 KB | маленький | OK, но мало информации |
| 5-15 KB | средний | **оптимальный** |
| 15-30 KB | крупный | OK, проверь что нужен весь |
| 30-50 KB | большой | допустимо, но мониторь context |
| 50-100 KB | огромный | **раздели на скиллы + templates** |
| > 100 KB | гигант | **архитектурная проблема** |

### Жёсткие лимиты системы

| Откуда | Лимит |
|---|---|
| `read_file` | нет лимита (файл любого размера) |
| `skill_view` | возвращает весь файл — но он попадёт в context |
| SOUL.md | традиционно < 10 KB |
| Memory files | < 2 KB каждый |
| Context window | 200K токенов = 400-500 KB общего контента |

### Итого

| Метрика | Значение |
|---|---|
| **Жёсткий лимит** | нет |
| **Разумный максимум** | 50 KB |
| **Рекомендуемый** | 15-30 KB |
| **Если > 50 KB** | разбить на SKILL.md + references |

## Playbook по разбиению больших скиллов

### Когда разбивать

Разбивать нужно если:

| Сигнал | Действие |
|---|---|
| SKILL.md > 50 KB | разбить обязательно |
| SKILL.md > 30 KB и есть тематические разделы | разбить желательно |
| SKILL.md > 15 KB и редко все разделы нужны | разбить на references |
| Скилл часто используется частично | разбить |
| Несколько пользователей «живут» в разных подтемах | разбить |

### Не разбивать если

- SKILL.md < 15 KB и логически целостный
- Используется только целиком
- Меняется редко и не хочется поддерживать структуру

### Каноническая структура разбитого скилла

```
my-skill/
├── SKILL.md                  ← 15-25 KB, главное: что/когда/как
├── references/               ← подробности, подгружаются по запросу
│   ├── api.md
│   ├── recipes.md
│   ├── troubleshooting.md
│   └── ...
├── templates/                ← переиспользуемые шаблоны
│   ├── template-1.md
│   └── template-2.md
├── scripts/                  ← Python-скрипты
│   ├── main.py
│   └── helpers.py
└── assets/                   ← примеры, логотипы, изображения
    ├── example.md
    └── logo.png
```

### Что оставить в SKILL.md (CORE)

`SKILL.md` — это **карта скилла**. Содержит:

| Раздел | Размер | Что |
|---|---|---|
| Заголовок + назначение | 100-200 B | Название, что делает |
| When to use | 500-1000 B | Примеры запросов пользователя |
| Quick start | 1-2 KB | Минимальный пример |
| Overview | 2-3 KB | Архитектура, ключевые понятия |
| References index | 500-1000 B | Список `references/` с описаниями |
| Templates index | 500 B | Список `templates/` с описаниями |
| Scripts index | 500 B | Список `scripts/` с описаниями |
| Common pitfalls | 1-2 KB | Типичные ошибки |
| Related skills | 500 B | Связи с другими скиллами |

**Итого SKILL.md: 7-12 KB** — это идеальный размер.

### Что выносить в references/

`references/` — это **детали, нужные только в конкретных случаях**.

| Файл | Когда читать |
|---|---|
| `api.md` | Если нужны точные сигнатуры методов |
| `recipes.md` | Если нужен пошаговый рецепт |
| `troubleshooting.md` | Если что-то сломалось |
| `advanced.md` | Если задача нестандартная |
| `examples.md` | Если нужны реальные примеры |
| `architecture.md` | Если нужно понять внутренности |

**Каждый файл:** 3-15 KB. Это нормально.

### Что выносить в templates/

`templates/` — это **переиспользуемые заготовки**.

| Шаблон | Когда использовать |
|---|---|
| `report-template.md` | Готовый каркас отчёта |
| `email-template.md` | Шаблон письма |
| `config-template.yaml` | Шаблон конфига |
| `script-template.py` | Шаблон Python-скрипта |

**Каждый шаблон:** 1-5 KB.

### Что выносить в scripts/

`scripts/` — это **исполняемый Python**.

| Скрипт | Что делает |
|---|---|
| `main.py` | Главная логика |
| `validate.py` | Валидация входных данных |
| `transform.py` | Трансформация данных |
| `analyze.py` | Анализ и метрики |

**Скрипты:** любого размера, они не загружаются в контекст пока не нужны.

### Как писать ссылки в SKILL.md

```markdown
## Подробности

- **API методы** → `references/api.md`
- **Рецепты** → `references/recipes.md`
- **Поиск ошибок** → `references/troubleshooting.md`
- **Продвинутое использование** → `references/advanced.md`

## Шаблоны

- **Отчёт** → `templates/report-template.md`
- **Email** → `templates/email-template.md`

## Скрипты

- **Запустить анализ** → `scripts/analyze.py`
- **Проверить данные** → `scripts/validate.py`
```

### Пример рефакторинга

**Было:** один файл 80 KB

```yaml
# SKILL: my-huge-skill
# всё в одном файле: описание, api, рецепты, troubleshooting, примеры
```

**Стало:** структура каталогом

```
my-huge-skill/
├── SKILL.md                  ← 12 KB (карта)
├── references/
│   ├── api.md                 ← 18 KB
│   ├── recipes.md             ← 15 KB
│   ├── troubleshooting.md     ← 12 KB
│   ├── advanced.md            ← 14 KB
│   └── examples.md            ← 9 KB
├── templates/
│   └── report.md              ← 4 KB
└── scripts/
    └── process.py             ← 8 KB
```

Итого: 12 KB в SKILL.md, остальное подгружается по необходимости.

### Как проверить что скилл хорошо разбит

| Чек-лист | ✓ |
|---|---|
| SKILL.md < 25 KB | ☐ |
| Каждый reference < 15 KB | ☐ |
| Из SKILL.md понятно ЧТО делает скилл | ☐ |
| Из SKILL.md понятно КОГДА использовать | ☐ |
| Каждый reference самодостаточен | ☐ |
| Ссылки между файлами работают | ☐ |
| Есть quick start в SKILL.md | ☐ |
| Нет дублирования между SKILL.md и references | ☐ |

### Когда НЕ разбивать

| Причина | Пример |
|---|---|
| Скилл используется только целиком | простые утилиты |
| Логически целостный | короткий reference один раз |
| Часто меняется весь сразу | черновик, draft |
| Пользователь не знает что искать | для начинающих |

### Инструмент для автоматического разбиения

Если SKILL.md уже большой, можно разбить алгоритмом:

```bash
# 1. Сохранить оригинал
cp SKILL.md SKILL.md.original

# 2. Найти заголовки разделов
grep '^## ' SKILL.md

# 3. Для каждого раздела > 5 KB вынести в references/
python3 << 'EOF'
import re
with open('SKILL.md') as f:
    content = f.read()

# Парсить секции
sections = re.split(r'(^## .+$)', content, flags=re.MULTILINE)
# ... вынести большие секции в references/
EOF
```

Но лучше **вручную** — понимание структуры важно.

### Сводная таблица

| Размер | Действие |
|---|---|
| < 15 KB | оставить как есть |
| 15-30 KB | оставить, но проверь |
| 30-50 KB | разбить на SKILL.md + 2-3 references |
| 50-100 KB | обязательно разбить на SKILL.md + 5-8 references |
| > 100 KB | гигант — скорее всего это не один скилл, а несколько |

### Главное правило

> **SKILL.md = карта. References = подробности. Templates = шаблоны. Scripts = код.**
> 
> Если SKILL.md самодостаточен и запускает дальнейшую работу через ссылки — разбиение сделано правильно.
