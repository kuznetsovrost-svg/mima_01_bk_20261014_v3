1. ГЛАВНОЕ ПРАВИЛО
═══════════════════════════════════════════════════════════════════

Имя Color Style должно отвечать на вопрос ЗАЧЕМ этот цвет,
а не КАКОГО он оттенка.

  Status/Critical/Bg          ← фон для критического состояния
  Red 100                     ← просто оттенок красного (плохо)

Используй Figma Color Styles с осмысленными именами,
сгруппированными по СЕМАНТИКЕ (status, action, text),
а не по ОТТЕНКУ (red, blue, green).

═══════════════════════════════════════════════════════════════════
2. ПОЧЕМУ ЭТО ВАЖНО
═══════════════════════════════════════════════════════════════════

При экспорте плагин использует имена Color Styles для
генерации CSS-переменных.

Из хороших имён:
  :root {
    --status-critical-bg: #FEE2E2;
    --status-attention-bg: #FEF3C7;
    --status-healthy-bg: #D1FAE5;
  }
  .status-banner--critical {
    background: var(--status-critical-bg);
  }

Из плохих имён:
  :root {
    --color-red-600: #DC2626;
    --color-red-100: #FEE2E2;
    --color-amber-600: #D97706;
  }
  /* Непонятно что к чему относится */

3. ТРИ УРОВНЯ ОРГАНИЗАЦИИ ПАЛИТРЫ
═══════════════════════════════════════════════════════════════════

Уровень 1: СЕМАНТИЧЕСКИЙ (рекомендую)
─────────────────────────────────────
  Группировка по НАЗНАЧЕНИЮ, не по цвету.

  Status/     ← для badge'й состояния
  Text/       ← для всего текста
  Background/ ← для фонов
  Border/     ← для границ
  Action/     ← для кнопок и интерактива
  Brand/      ← фирменные

Уровень 2: TAILWIND-СТИЛЬ (хорошо для современных проектов)
───────────────────────────────────────────────────────────
  Группировка по оттенку, но с фиксированной шкалой 100-900.

  Red/100, Red/200, Red/500, Red/600, Red/800
  Amber/100, Amber/600, Amber/800
  Blue/100, Blue/600, Blue/800

Уровень 3: МИНИМАЛЬНЫЙ (для маленьких проектов)
──────────────────────────────────────────────
  Только основные цвета.

  Primary, Secondary, Success, Warning, Danger
  Text-Primary, Text-Muted, Bg-Page, Bg-Section

4. КОНВЕНЦИЯ ИМЁН (ПОДРОБНО)
═══════════════════════════════════════════════════════════════════

Структура имени:

  <Группа>/<Вариант>/<Роль>

Примеры:
  Status/Critical/Bg
  Status/Critical/Text
  Status/Critical/Border
  Status/Critical/Dot

  Text/Heading-Primary
  Text/Body
  Text/Muted

  Action/Primary/Bg
  Action/Primary/Hover

Правила:
  - Используй / как разделитель групп (Figma поддерживает)
  - Используй - внутри одной группы
  - Имена на английском (для совместимости с CSS-классами)
  - Lowercase (кроме аббревиатур: Bg, Dot, Hover)
  - Snake-case или kebab-case (консистентно)

11. КАК СОЗДАВАТЬ COLOR STYLES В FIGMA
═══════════════════════════════════════════════════════════════════

11.1. Открыть панель
────────────────────
  Windows/Linux: Ctrl + Shift + Y
  Mac: Cmd + Shift + Y

  Или: меню → View → Show Styles

11.2. Создать новый стиль
─────────────────────────
  1. Выделить любой элемент с цветом
  2. В панели Styles нажать "+" (Create new style)
  3. Ввести имя в формате:
     Group/Variant/Role

11.3. Иерархия через "/"
────────────────────────
  Figma автоматически создаёт иерархию:

  Color/Status/Critical/Bg      ← группа "Color"
                                  ├─ группа "Status"
                                     ├─ группа "Critical"
                                        └─ стиль "Bg"

  В панели видно как:
  Color/
  ├─ Status/
  │  ├─ Critical/
  │  │  ├─ Bg
  │  │  ├─ Text
  │  │  └─ Dot

11.4. Массовое создание
───────────────────────
  Через Figma Tokens Plugin:
  https://www.figma.com/community/plugin/843461159747178978

  Позволяет импортировать всю палитру из JSON:
  {
    "status": {
      "critical": {
        "bg":   { "value": "#FEE2E2" },
        "text": { "value": "#991B1B" },
        "dot":  { "value": "#DC2626" }
      }
    }
  }

  Плагин автоматически создаст Color Styles с именами
  status/critical/bg, status/critical/text, status/critical/dot.

12. ПЛОХИЕ ИМЕНА (ЧЕГО ИЗБЕГАТЬ)
═══════════════════════════════════════════════════════════════════

| Имя                     │ Почему плохо                                          │
│────────────────────────┼────────────────────────────────────────────────────────│
│ Red 600                │ Цвет, а не назначение                                │
│ Blue/Light              │ Слишком общо                                          │
│ Primary Blue            │ «Blue» не нужно (primary и так подразумевает цвет)  │
│ bg-1, bg-2, bg-3        │ Без семантики                                         │
│ #FF0000                 │ Hex в имени не помогает                               │
│ Color 1, Color 2        │ Бесполезно                                            │
│ Red                     │ Слишком общо (есть много оттенков красного)          │
│ Status/Red              │ Смешение семантики и оттенка                          │
│ Header Color            │ Не указан вариант/состояние                           │
│ Critical Color          │ Не указана роль (bg/text/border/dot?)                │
│ temp, draft, test       │ Временные метки, забываются                           │
│ Новый Цвет              │ Кириллица в имени (плохо для CSS)                    │
|─────────────────────────────────────────────────────────────────────|

13. АНТИ-ПАТТЕРНЫ ИСПОЛЬЗОВАНИЯ ЦВЕТОВ
═══════════════════════════════════════════════════════════════════

❌ Анти-паттерн 1: inline-цвета в каждом элементе
   Каждый раз выбираешь #FEE2E2 вручную в Color Picker.
   Нет единого источника правды.
   → Используй Color Style один раз, применяй везде.

❌ Анти-паттерн 2: дублирование похожих цветов
   Создал #FE0000, потом «такой же но чуть светлее» #FE1111.
   Не понимаешь какой где использовать.
   → Используй Color Style, переиспользуй.

❌ Анти-паттерн 3: только 2-3 цвета без группировки
   Создал: Critical, Background, Primary.
   Всё в одной куче, не понятно что к чему.
   → Группируй через /.

❌ Анти-паттерн 4: имена по shade вместо по смыслу
   red-100, red-200, ..., red-900.
   Плагин не понимает зачем тебе 10 оттенков красного.
   → Группируй по смыслу: Critical/Bg, Critical/Text, Critical/Dot.

❌ Анти-паттерн 5: смешение российской и английской нотации
   Critical/Фон, Внимание/Текст.
   Не работает в CSS.
   → Только английский.

15. ЧЕК-ЛИСТ ПЕРЕД ЭКСПОРТОМ
═══════════════════════════════════════════════════════════════════

Структура:
  [ ] Все цвета оформлены как Figma Color Styles (не inline)
  [ ] Имена семантические (Status/Critical/Bg, не Red 100)
  [ ] Группировка через / в именах
  [ ] Каждое состояние имеет 4-7 цветов (bg/text/border/dot/accent/...)
  [ ] Нет дублирования цветов
  [ ] Нет оттенков «похожих но чуть других»

Имена:
  [ ] Только английский (не кириллица)
  [ ] Lowercase (кроме аббревиатур)
  [ ] Консистентно snake-case или kebab-case
  [ ] НЕ содержит hex-код (#DC2626)
  [ ] НЕ содержит общие названия (Color 1, Primary Blue)

Контрастность:
  [ ] Все комбинации текст/фон проходят WCAG AA (≥ 4.5:1)
  [ ] Крупный текст (≥18px) проходит AAA (≥ 3:1)
  [ ] Status-цвета читаемы

Тёмная тема (если нужна):
  [ ] Для каждого цвета есть -Dark или -Inverse вариант
  [ ] Контрастность проверена и в тёмной теме
  [ ] Status-цвета в тёмной теме читаемы

═══════════════════════════════════════════════════════════════════
16. ШПАРГАЛКА
═══════════════════════════════════════════════════════════════════

Структура имени:
  <Группа>/<Вариант>/<Роль>
  Пример: Status/Critical/Bg

Группы верхнего уровня:
  Status/, Text/, Background/, Border/, Action/, Brand/

Варианты для Status:
  Critical (красный, проблема)
  Attention (жёлтый, требует внимания)
  Healthy (зелёный, ok)
  Info (синий, информация)

Роли для Status:
  Bg (фон)
  Text (текст)
  Border (граница)
  Dot (точка-индикатор)
  Accent (яркий акцент)
  Bg-Hover (фон при hover)
  Text-Muted (вторичный текст)

Роли для Text:
  Heading (заголовки)
  Body (основной текст)
  Muted (приглушённый)
  Disabled (отключённый)
  Link (ссылки)
  Code (в коде)

Роли для Background:
  Page (страница)
  Section (секция)
  Card (карточка)
  Subtle (едва заметный)
  Overlay (затемнение)
  Inverse (инверсный)
