1. ПОСТАНОВКА ЗАДАЧИ
═══════════════════════════════════════════════════════════════════

В будущем skill потребуется вычислять относительное отклонение
по датам. Имеем:

  • Начальная дата   (start)    — когда фактически начали
  • Плановая дата    (planned)  — когда планировали закончить
  • Прогнозная дата  (forecast) — прогноз реального окончания

Требуется вычислить ОТНОСИТЕЛЬНОЕ ОТКЛОНЕНИЕ ПРОГНОЗА:

  относительное_отклонение = |прогнозная - плановая| / |плановая - начальная|

Все вычисления в календарных днях.

Пример:
  начальная    = 2026-07-01
  плановая     = 2026-07-15  (через 14 дней от начальной)
  прогнозная   = 2026-07-20  (через 19 дней от начальной)

  |прогнозная - плановая| = |20 - 15| = 5 дней
  |плановая - начальная|  = |15 - 1|  = 14 дней
  относительное отклонение = 5 / 14 = 0.357 = 35.7%

Смысл: прогноз отклоняется от плана на 35.7% от общей
запланированной продолжительности. Это можно интерпретировать
как «работа займёт на треть больше времени, чем планировалось».

2. ВАРИАНТ A — ТЕКСТОВОЕ ОПИСАНИЕ В SKILL.md
═══════════════════════════════════════════════════════════════════

Что пишем в SKILL.md:

  ## Алгоритм: относительное отклонение по датам

  Входные данные:
    - start_date    — начальная дата (формат YYYY-MM-DD)
    - planned_date  — плановая дата завершения
    - forecast_date — прогнозная дата завершения

  Шаги:
    1. Преобразовать все три даты в календарные дни от эпохи
       (например, от 1970-01-01 через datetime.timestamp())
    2. Вычислить abs(forecast - planned) — отклонение прогноза от плана
    3. Вычислить abs(planned - start) — общая запланированная
       продолжительность
    4. Если шаг 3 == 0 → вернуть None или ошибку (деление на ноль)
    5. Разделить шаг 2 на шаг 3 — относительное отклонение
    6. Вернуть результат как float (0.0 = точное совпадение,
       1.0 = двукратное превышение)

  Пример вычисления:
    start    = 2026-07-01  → day 19515
    planned  = 2026-07-15  → day 19529
    forecast = 2026-07-20  → day 19534

    |forecast - planned| = 5
    |planned - start|   = 14
    относительное = 5 / 14 = 0.357

  Особые случаи:
    • planned == start → деление на ноль → вернуть None
    • forecast < planned → отрицательное отклонение (раньше плана)
      → использовать abs() чтобы получить положительное
    • forecast > planned → положительное отклонение (позже плана)

  VERIFICATION:
    - [ ] Все даты в формате YYYY-MM-DD
    - [ ] Результат в диапазоне [0, ∞)
    - [ ] При planned == start — обработано (None)

Плюсы варианта A:
  + Просто написать — одна страница в SKILL.md
  + Агент может «понять» и адаптировать (например, считать в
    рабочих днях вместо календарных, если попросят)
  + Не требует отдельного файла scripts/

Минусы варианта A:
  - Агент делает ВЫЧИСЛЕНИЯ ВРУЧНУЮ через mental math или bash
  - При большом количестве дат — медленно и ненадёжно
  - Ошибки округления при ручных вычислениях
  - Нельзя прогнать 1000 записей за разумное время
  - Зависит от внимательности агента

3. ВАРИАНТ B — PYTHON-СКРИПТ В scripts/

Содержимое scripts/date_deviation.py:

  #!/usr/bin/env python3
  """
  Compute relative date deviation for forecast vs plan.

  Usage:
      python date_deviation.py --start 2026-07-01 \\
                               --planned 2026-07-15 \\
                               --forecast 2026-07-20
      # → 0.35714285714285715

      # batch mode (CSV with columns start,planned,forecast):
      python date_deviation.py --csv dates.csv
      # → writes dates_with_deviation.csv
  """

  from __future__ import annotations
  import argparse
  import csv
  import sys
  from dataclasses import dataclass
  from datetime import date, datetime
  from typing import Optional

  DATE_FMT = "%Y-%m-%d"


  def parse_date(s: str) -> date:
      """Parse YYYY-MM-DD, raise ValueError on bad input."""
      return datetime.strptime(s, DATE_FMT).date()


  @dataclass(frozen=True)
  class DateDeviation:
      start: date
      planned: date
      forecast: date
      deviation_days: int       # |forecast - planned|
      baseline_days: int        # |planned - start|
      relative: Optional[float] # deviation / baseline, None if baseline==0

      def is_negative(self) -> bool:
          """True if forecast is earlier than planned (good)."""
          return self.forecast < self.planned

      def category(self) -> str:
          """Categorize deviation severity."""
          if self.relative is None:
              return "undefined"
          r = abs(self.relative)
          if r < 0.05: return "on_track"      # < 5%
          if r < 0.20: return "minor"         # 5-20%
          if r < 0.50: return "moderate"     # 20-50%
          return "critical"                   # > 50%


  def compute_deviation(
      start: date,
      planned: date,
      forecast: date,
  ) -> DateDeviation:
      deviation = abs((forecast - planned).days)
      baseline = abs((planned - start).days)
      relative = (deviation / baseline) if baseline > 0 else None
      return DateDeviation(
          start=start,
          planned=planned,
          forecast=forecast,
          deviation_days=deviation,
          baseline_days=baseline,
          relative=relative,
      )


  def main(argv: list[str]) -> int:
      parser = argparse.ArgumentParser(description=__doc__)
      g = parser.add_mutually_exclusive_group(required=True)
      g.add_argument("--start", help="start date YYYY-MM-DD")
      parser.add_argument("--planned")
      parser.add_argument("--forecast")
      g.add_argument("--csv", help="CSV file with start,planned,forecast")
      parser.add_argument("--out", help="output CSV for --csv mode")
      args = parser.parse_args(argv)

      if args.start:
          result = compute_deviation(
              parse_date(args.start),
              parse_date(args.planned),
              parse_date(args.forecast),
          )
          if result.relative is None:
              print("undefined (planned == start)", file=sys.stderr)
              return 1
          print(f"{result.relative:.4f}")
          print(f"# category: {result.category()}", file=sys.stderr)
          return 0

      # CSV mode
      with open(args.csv, newline="") as f:
          reader = csv.DictReader(f)
          rows = list(reader)
      out_path = args.out or args.csv.replace(".csv", "_with_deviation.csv")
      with open(out_path, "w", newline="") as f:
          writer = csv.DictWriter(
              f,
              fieldnames=list(rows[0].keys()) + [
                  "deviation_days",
                  "baseline_days",
                  "relative",
                  "category",
              ],
          )
          writer.writeheader()
          for row in rows:
              r = compute_deviation(
                  parse_date(row["start"]),
                  parse_date(row["planned"]),
                  parse_date(row["forecast"]),
              )
              row["deviation_days"] = r.deviation_days
              row["baseline_days"] = r.baseline_days
              row["relative"] = f"{r.relative:.4f}" if r.relative else ""
              row["category"] = r.category()
              writer.writerow(row)
      print(f"wrote {out_path}", file=sys.stderr)
      return 0


  if __name__ == "__main__":
      sys.exit(main(sys.argv[1:]))

Содержимое scripts/test_date_deviation.py:

  import pytest
  from datetime import date
  from date_deviation import compute_deviation, DateDeviation


  class TestComputeDeviation:
      def test_basic(self):
          r = compute_deviation(
              date(2026, 7, 1),
              date(2026, 7, 15),
              date(2026, 7, 20),
          )
          assert r.deviation_days == 5
          assert r.baseline_days == 14
          assert abs(r.relative - 5/14) < 1e-9

      def test_forecast_before_planned(self):
          r = compute_deviation(
              date(2026, 7, 1),
              date(2026, 7, 15),
              date(2026, 7, 10),
          )
          assert r.deviation_days == 5
          assert r.is_negative()

      def test_zero_baseline_returns_none(self):
          r = compute_deviation(
              date(2026, 7, 1),
              date(2026, 7, 1),
              date(2026, 7, 15),
          )
          assert r.relative is None
          assert r.category() == "undefined"

      def test_exact_match(self):
          r = compute_deviation(
              date(2026, 7, 1),
              date(2026, 7, 15),
              date(2026, 7, 15),
          )
          assert r.relative == 0.0
          assert r.category() == "on_track"

      def test_categories(self):
          assert compute_deviation(date(2026,7,1), date(2026,7,15),
                  date(2026,7,16)).category() == "on_track"
          assert compute_deviation(date(2026,7,1), date(2026,7,15),
                  date(2026,7,17)).category() == "minor"
          assert compute_deviation(date(2026,7,1), date(2026,7,15),
                  date(2026,7,20)).category() == "moderate"
          assert compute_deviation(date(2026,7,1), date(2026,7,15),
                  date(2026,7,30)).category() == "critical"

Плюсы варианта B:
  + Точность — никаких ошибок ручного вычисления
  + Скорость — 1000 записей за миллисекунды
  + Тестируемость — pytest покрывает edge cases
  + Расширяемость — легко добавить новые метрики (EVM, burndown)
  + Переиспользуемость — скрипт работает вне агента
  + CSV batch mode — для пакетной обработки
  + Категории severity — структурированный вывод

Минусы варианта B:
  - Больше кода писать (но он переиспользуется)
  - Нужно поддерживать (баги, обновления)
  - Зависимость от Python (но он уже есть на mima_g_01)
  - Агент должен знать, как вызвать (через `python scripts/X.py`)

8. EDGE CASES — ЧТО УЧЕСТЬ
═══════════════════════════════════════════════════════════════════

Скрипт должен обрабатывать:

  1. planned == start → деление на ноль → None или ошибка
  2. forecast < planned → отрицательное отклонение → abs()
  3. forecast == planned → 0.0 → "on_track"
  4. forecast > start → прогноз ПОЗЖЕ начальной (норма)
  5. forecast < start → прогноз РАНЬШЕ начальной (физически
     невозможно, но возможен баг в данных) → предупреждение
  6. Невалидный формат даты → ValueError → понятное сообщение
  7. Пропущенные поля в CSV → KeyError → понятное сообщение
  8. Очень большие отклонения (1000%) → не падать, выводить
     category="critical"

Все edge cases покрыты тестами в test_date_deviation.py.

11. ШПАРГАЛКА — КОГДА ЧТО ВЫБИРАТЬ
═══════════════════════════════════════════════════════════════════

  Простая арифметика, 1-2 записи     → вариант A (текст)

    • SKILL.md объясняет ЧТО и ЗАЧЕМ (текст)
