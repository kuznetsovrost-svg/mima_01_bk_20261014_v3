1. ОБЩАЯ КАРТИНА: КАК ВСЁ СВЯЗАНО
───────────────────────────────────────────────────────────────────────

Сайт — это набор HTML/CSS/JS-файлов в репозитории GitHub.
GitHub Pages — бесплатный хостинг от GitHub, который раздаёт
эти файлы в интернет по адресу:

    https://<username>.github.io/<repo-name>/

Весь цикл работы выглядит так:

   ┌──────────────────┐    ┌──────────────────┐    ┌──────────────────┐
   │  Hermes Agent    │───▶│  GitHub repo     │───▶│  GitHub Pages    │
   │  пишет файлы,    │    │  хранит исходники│    │  отдаёт в браузер│
   │  коммитит,       │    │  сайта           │    │  пользователю    │
   │  пушит           │    │                  │    │                  │
   └──────────────────┘    └──────────────────┘    └──────────────────┘
        (вы тут)              (github.com)         (интернет)

Hermes — это «рука», которая делает за вас: создаёт файлы, пишет
в них контент, делает git commit, делает git push. GitHub —
«склад», где лежат файлы. GitHub Pages — «витрина», которая
показывает файлы посетителям.

Никакого сервера, никакого PHP, никакой базы данных. Только
статические файлы (HTML, CSS, JS, картинки) и бесплатный хостинг.

ШАГ 1. СОЗДАТЬ РЕПОЗИТОРИЙ НА GITHUB
───────────────────────────────────────────────────────────────────────

У вас два пути:

  Путь A. Через сайт github.com (наглядно):
    1) Открыть https://github.com/new
    2) Repository name:  my-site   (или любое)
    3) Description:      "Мой первый сайт на GitHub Pages"
    4) Public / Private: Public (обязательно для бесплатных
       GitHub Pages; на приватных репах Pages работает
       только в платных планах)
    5) ☑ Add a README file
    6) ☑ Add .gitignore: None
    7) License: MIT (или любая; можно без)
    8) Нажать "Create repository"

  Путь B. Через gh CLI (быстро):
    $ gh repo create my-site --public --description "Мой сайт" --clone

  Путь C. Через API (если у вас уже есть токен):
    $ curl -X POST -H "Authorization: token $GITHUB_TOKEN" \
        https://api.github.com/user/repos \
        -d '{"name":"my-site","description":"Мой сайт","public":true}'

После создания у вас появится пустой репозиторий. Его URL:
    git@github.com:kuznetsovrost-svg/my-site.git

ШАГ 4. СВЯЗАТЬ СТРАНИЦЫ МЕЖДУ СОБОЙ (НАВИГАЦИЯ)
───────────────────────────────────────────────────────────────────────

В нашем примере навигация уже встроена в каждую страницу —
одинаковый блок <nav> с тремя ссылками. Этого достаточно для
простого сайта.

Для более серьёзного сайта, где страниц 20+, удобно вынести
навигацию в отдельный файл и подключать через JavaScript.
Но для учебного проекта копипаста <nav> на каждую страницу —
нормальное решение.

Важно:
  • Ссылки на другие страницы — относительные: about.html,
    а не https://example.com/about.html
  • Если страница лежит в подкаталоге, путь удлиняется:
    posts/first-post.html → ../index.html
  • Ссылка на общий CSS: assets/css/style.css

ШАГ 5. ЛОКАЛЬНАЯ ПРОВЕРКА
───────────────────────────────────────────────────────────────────────

Прежде чем пушить, откройте сайт локально. Проще всего —
запустить крошечный HTTP-сервер на Python.

  $ cd ~/my-site
  $ python3 -m http.server 8000

Затем откройте в браузере:
    http://localhost:8000/

Должна загрузиться главная. Клик по "О сайте" → about.html.
Клик по "Контакты" → contact.html. Стили подтянулись.
Картинки (если есть) — на месте.

Если всё ок — нажмите Ctrl+C, останавливайте сервер.

Альтернатива: просто открыть index.html двойным кликом в
файловом менеджере. Будет работать для простого HTML без
fetch'ей и без модулей.

ШАГ 6. ЗАКОММИТИТЬ И ЗАПУШИТЬ ЧЕРЕЗ HERMES
───────────────────────────────────────────────────────────────────────

Вот тут начинается самое интересное — мы делаем всю git-магию
через Hermes Agent, не открывая терминал руками.

Скажите Hermes что-то вроде:

  "Закоммить все файлы в текущей папке как 'Initial site' и
   запушь в origin main"

Hermes выполнит:

    $ git add .
    $ git status
    $ git commit -m "Initial site: index, about, contact pages + styles"
    $ git push -u origin main

Если push попросит авторизацию, а вы уже настроили SSH-ключ
(а на этом хосте он настроен), всё пройдёт гладко. Если нет —
Hermes подскажет, как добавить SSH-ключ на GitHub.

Пример диалога с Hermes (как это выглядит в Matrix):

  Вы:    сделай сайт с тремя страницами и задеплой на GitHub Pages
  Hermes: Создаю репозиторий my-site, пишу index.html, about.html,
          contact.html, style.css, делаю commit и push. Готово,
          ссылка будет: https://kuznetsovrost-svg.github.io/my-site/
          через 1–2 минуты после включения Pages.

ШАГ 9. ОБНОВЛЕНИЕ САЙТА (ЦИКЛ ПРАВОК)
───────────────────────────────────────────────────────────────────────

Цикл правок всегда один и тот же:

  1) Поправить файл(ы) локально
  2) $ git add .
  3) $ git commit -m "Описание правки"
  4) $ git push
  5) Подождать 10–30 секунд
  6) Обновить страницу в браузере — изменения уже онлайн

Через Hermes это сводится к одной фразе:

  "Поменяй заголовок на главной на 'Привет, мир' и задеплой"

Hermes:
  1. patch файла index.html
  2. git add + commit + push
  3. "Готово, обновите страницу через 30 секунд"

Через минуту изменения уже в продакшене. Это и есть сила
статического сайта + GitHub Pages + AI-ассистента: цикл
правки → деплой занимает меньше минуты.

10. БОНУС: КАСТОМНЫЙ ДОМЕН
───────────────────────────────────────────────────────────────────────

GitHub Pages поддерживает ваш собственный домен.
Например, вы купили myname.ru у регистратора.

  1) Settings → Pages → Custom domain: myname.ru
  2) Save
  3) В DNS вашего домена добавьте:
       CNAME  www    →  kuznetsovrost-svg.github.io
       A      @      →  185.199.108.153
                       185.199.109.153
                       185.199.110.153
                       185.199.111.153
  4) Подождать 5–30 минут, пока DNS пропишется
  5) ☑ Enforce HTTPS (появится чекбокс после привязки домена)

Домен будет жить на вашем репозитории бесплатно, с авто-HTTPS.

11. БОНУС: JEKYLL (ЕСЛИ ХОЧЕТСЯ БЛОГ/ДОКУ)
───────────────────────────────────────────────────────────────────────

Если сайт разрастётся до 50+ страниц и захочется:
  • автоматическую шапку/футер на всех страницах
  • блог-посты с датами и тегами
  • RSS-ленту
  • sitemap.xml

— подключите Jekyll. Это уже встроено в GitHub Pages.

  1) Создайте в корне файл _config.yml:
       title: Мой сайт
       theme: minima
  2) Создайте _layouts/default.html с шаблоном + {{ content }}
  3) Каждая страница начинается с front matter:
       ---
       layout: default
       title: О сайте
       ---
  4) Push — Pages сам пересоберёт сайт с шаблонами.

Jekyll поддерживает плагины, темы, переменные, циклы —
полноценный статический генератор.

12. ТИПИЧНЫЕ ОШИБКИ И КАК ИХ ЧИНИТЬ
───────────────────────────────────────────────────────────────────────

❌ "Repository not found" при push
   → Репо не существует или вы неправильно указали имя.
     Проверьте: git remote -v

❌ "Permission denied (publickey)"
   → SSH-ключ не настроен. Сгенерируйте:
     ssh-keygen -t ed25519 -C "kuznetsov.rost@gmail.com"
     затем скопируйте ~/.ssh/id_ed25519.pub в
     https://github.com/settings/keys

❌ Сайт открывается, но без стилей
   → Проверьте путь к CSS: <link href="assets/css/style.css" ...
     относительный путь от location страницы, не от корня сайта.

❌ Картинки не загружаются
   → Та же причина: путь относительный. Должно быть
     assets/img/logo.png, а не /assets/img/logo.png
     (абсолютный путь от корня сайта сработает только
     если сайт лежит в корне домена, не в подкаталоге).

❌ 404 на странице
   → Либо файл не закоммичен (проверьте git ls-files),
     либо в имени — заглавные буквы, а ссылка — строчные.
     На GitHub Pages имена файлов регистрозависимы.

❌ "Your site is live" появилось, но страница пустая
   → Возможно, в репе нет index.html в корне, или
     GitHub отдаёт README.md. Проверьте: имя файла
     именно index.html, не Index.html или index.htm.

❌ Сайт работает локально, но не на GitHub
   → Почти всегда — пути. Локально файл:///
     разрешает относительные пути иначе, чем
     http://kuznetsovrost-svg.github.io/my-site/.
     Всегда проверяйте локально через http.server.

❌ "There isn't a GitHub Pages site here"
   → Pages не включен (Шаг 7) или репа приватная
     (Pages на приватных репах — только платный план).
