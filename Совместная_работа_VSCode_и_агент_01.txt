Введение
--------

Этот playbook покрывает практику работы с VS Code + Hermes через ACP.
Главный сценарий: ты правишь SKILL.md руками, я проверяю структуру
и связи, ты запускаешь в новой сессии.

Документ не описывает установку расширений (это в скилле
vscode-integration v1.0.0) и не описывает создание нового скилла
с нуля (это в скилле hermes-agent-skill-authoring v1.1.0).
Здесь только рабочий цикл и его подводные камни.


Глава 1. Где что лежит
-----------------------

1.1 Скиллы (user-local)

    ~/.hermes/skills/<category>/<skill-name>/
        SKILL.md              # frontmatter + тело
        scripts/              # python / shell
        references/           # длинные части
        templates/            # шаблоны
        assets/               # бинарные ресурсы

    Категории — любые. Скилл виден всем профилям через SKILLS_DIR.

1.2 Память (для правил и фактов)

    ~/.hermes/memories/
        MEMORY.md             # мои заметки о тебе, окружении, conventions
        USER.md               # твой профиль (как общаться)
        <другие-файлы>.md

1.3 Профили

    ~/.hermes/profiles/<name>/
        SOUL.md               # специализация (или fallback на kernel)
        config.yaml           # модель, таймауты, тулсеты
        .env                  # токены (если нужны)
        skills/               # локальные скиллы (override global)
        memory/               # локальная память (если нужна)

1.4 Скиллы в репозитории Hermes (in-repo)

    /home/bb/hermes-agent/skills/...
    /usr/local/lib/hermes-agent/skills/...   # bundled, read-only

    Это исходники скиллов самого Hermes. Править напрямую — нельзя.
    Только читать и переносить копию в user-local.


Глава 2. Workflow «правишь → проверяешь → запускаешь»
----------------------------------------------------

2.1 Фаза 1 — правишь руками

Открываешь скилл в VS Code. Правь SKILL.md, scripts/*.py, references/*.md.
Сохрани (Ctrl+S). Файл сразу в файловой системе mima_g_01
(через Remote-SSH).

Что обычно правишь:
- description в frontmatter (что скилл делает)
- структура SKILL.md (заголовки, секции)
- scripts/*.py (логика)
- references/*.md (детали)

2.2 Фаза 2 — проверяешь со мной

В ACP чате попроси:
- прочитать SKILL.md (read_file)
- прочитать scripts/*.py (read_file)
- проверить frontmatter
- проверить структуру references
- проверить что скрипты не сломаны

Я делаю read-only анализ. НЕ запускаю скрипты.
Если нужно — даю рекомендации по улучшению.

2.3 Фаза 3 — запускаешь

⚠️ КРИТИЧНО: новая сессия.

Skill loader кэширует список скиллов при старте сессии.
Правки, сделанные во время сессии, не видны текущей сессии.
Нужно открыть новый чат / новую сессию, чтобы проверить.

Как запустить новую сессию:
- в VS Code ACP: dropdown → "New Session" или "Reset"
- через CLI: /reset
- перезапуск gateway (см. грабли в Главе 3)


Глава 3. Критические грабли
---------------------------

3.1 Reload gateway из-под сессии заблокирован

    hermes gateway restart    ← заблокировано tool security

    Причина: PPID-check. Gateway запущен в отдельном процессе,
    сессия не может его перезапустить (защита от случайного kill).

    Обход: запусти gateway restart из другого shell — отдельная
    SSH-сессия, не из чата с агентом.

3.2 write_file в memories/ заблокирован

    write_file ~/.hermes/memories/MEMORY.md   ← заблокировано

    Причина: consent-gate. Память — чувствительная зона.
    Используй memory tool:
        memory(action="add", target="memory", content="...")
        memory(action="replace", target="user", ...)
        patch(path=..., old_string=..., new_string=...)

3.3 write_file в profiles/<name>/... заблокирован

    Причина: cross-profile guard. Профили изолированы.
    Если нужно — пиши в общую директорию ~/.hermes/skills/ или
    используй --profile флаг при вызове hermes CLI.

3.4 Skill-loader кэшируется

    Правка SKILL.md в текущей сессии — не видна.
    Нужна новая сессия (см. 2.3).

3.5 Токены санитизируются в terminal output

    $TOK показывается как *** в выводе.
    Реальный токен в ~/.hermes/.env.
    Не пытайся grep по выводу — не найдёшь.

3.6 Confusable Unicode gate на кириллических именах файлов

    curl -F document=@Совместная...txt   ← может вызвать approval

    Обход: скопировать в ASCII-путь (/tmp/_x.txt) перед отправкой
    в Telegram.

3.7 Cross-profile guard в soft-режиме

    write_file в чужой профиль — soft block.
    По умолчанию отказывается. Для обхода нужен явный cross_profile=true
    И явное одобрение пользователя. Лучше избегать.


Глава 4. Рецепт проверки и запуска
----------------------------------

4.1 После правки SKILL.md

    a) Сохрани файл (Ctrl+S)
    b) В ACP чате: "прочитай ~/.hermes/skills/<cat>/<name>/SKILL.md,
       проверь frontmatter и структуру"
    c) Я делаю read_file + анализ
    d) Если есть замечания — поправь руками
    e) Если OK → запускай новую сессию для теста

4.2 После правки scripts/*.py

    a) Сохрани
    b) В ACP чате: "прочитай scripts/<file>.py, проверь что нет
       eval/exec, hardcoded secrets, shell=True"
    c) Если нужно — даю тест (команда для запуска в отдельном shell)
    d) Запускай тест из отдельного SSH — НЕ из чата

4.3 После правки references/*.md

    a) Сохрани
    b) В ACP чате: "прочитай references/<file>.md, проверь что
       согласовано с SKILL.md"
    c) Если есть противоречия — поправь

4.4 Полный цикл

    правишь → Ctrl+S → "проверь X" → правки → новая сессия →
    "запусти Y" → результат

4.5 Когда что-то не работает

    Симптом: скилл не виден / старая версия
    Причина: skill-loader cache
    Решение: новая сессия (dropdown в ACP)

    Симптом: hermes не отвечает
    Причина: gateway упал / перезагружается
    Решение: проверить ps aux | grep hermes в отдельном SSH

    Симптом: SSH отказывает
    Причина: ключ / config / IP
    Решение: ssh -v root@mima-g-01 hostname (из PowerShell)

Глава 7. Шпаргалка команд
-------------------------

Проверить структуру скилла:

    ls -la ~/.hermes/skills/<cat>/<name>/
    cat ~/.hermes/skills/<cat>/<name>/SKILL.md

Проверить что скилл загружен:

    hermes skills list | grep <name>

Запустить скилл:

    /skill-name           # slash-команда в ACP чате

Перезапустить gateway (из отдельного shell):

    systemctl --user restart hermes-gateway-default.service
    # или
    hermes gateway restart    # из отдельного SSH

Новая сессия в ACP:

    Ctrl+Shift+P → ACP: New Session

Найти что скилл не работает:

    hermes skills inspect <name>   # что в кэше
    hermes skills diff <name>      # отличия от bundled
    hermes skills audit            # полный аудит
