## 1. Исходный EN (то, что переводим)

```
Use when the user wants a health-check report on a specific PMForesight project (ИСУП «Форсайт», PMForesight) via its MCP server. Loads on 'здоровье проекта', 'оцени проект', 'health check', 'project status report', 'анализ проекта', or by Code/ProjectId. Produces a dual-format report (Markdown inline + HTML file via MEDIA:) covering: (1) КТ schedule compliance (red/yellow by PlanDate–ForecastDate deviation); (2) project data completeness (Куратор, Руководитель, Паспорт, стадия ЖЦ, трудозатраты, платежи); (3) look-ahead КТ relevance (overdue КТ where ForecastDate < today); (4) financial status (forecast, прогноз фин.результата по окончании и его отклонение от планового, отклонение текущей стоимости от плана); (5) technical metadata (date, time, MCP version, user). Verdict: БОЛЕН / ТРЕБУЕТ ВНИМАНИЯ / ЗДОРОВ by critical-remark count. Visible data is filtered by the user's permissions in the host Форсайт system.
```

**Длина:** 922 символа (EN), `description` для русского перевода лимита не имеет, но желательно удержать **±20% от длины оригинала**, чтобы смысл не размылся.

## 2. Полный перевод (как я предложил в чате)

> Загружай, когда пользователь хочет получить отчёт о здоровье конкретного проекта в PMForesight (ИСУП «Форсайт», PMForesight) через его MCP-сервер. Скилл активируется по запросам: «здоровье проекта», «оцени проект», «health check», «project status report», «анализ проекта» — либо когда указан код проекта (Code) или ProjectId. По результатам работы формируется отчёт в двух форматах (Markdown в чате + HTML-файл через `MEDIA:`), который охватывает: (1) соблюдение сроков контрольных точек (КТ) — отклонение между плановой и прогнозной датой с классификацией «красный/жёлтый»; (2) полнота заполнения данных проекта (Куратор, Руководитель, Паспорт, стадия жизненного цикла, трудозатраты, платежи); (3) актуальность прогнозов по КТ (просроченные КТ, у которых прогнозная дата раньше сегодняшней); (4) финансовый статус проекта (прогноз финансового результата по окончании и его отклонение от планового, отклонение текущей стоимости от плана); (5) технические метаданные (дата, время, версия MCP, пользователь). Вердикт: **БОЛЕН / ТРЕБУЕТ ВНИМАНИЯ / ЗДОРОВ** — определяется по количеству критических замечаний. Видимые данные ограничены правами пользователя в системе «Форсайт».

**Длина:** ~895 символов с пробелами (≈97% от EN). Подходит для `description: "…"` без лимита.

## 3. Что было адаптировано (таблица решений)

| Оригинал (EN) | Перевод (RU) | Зачем / Почему |
|---------------|--------------|----------------|
| `Use when` | `Загружай, когда` | Императив для скиллов в Hermes-стиле (русские скиллы обычно используют «Загружай»). Альтернатива: «Используй, когда» — менее специфично для Hermes |
| `Loads on` | `Скилл активируется по запросам` | Точнее по-русски. «Loads» в EN-конвенции = «загружается». В RU более гладко через «активируется» |
| `or by Code/ProjectId` | `либо когда указан код проекта (Code) или ProjectId` | Развёрнуто для ясности. Code — поле, ProjectId — id, пользователь должен понимать, что можно указать любое |
| `dual-format report` | `отчёт в двух форматах` | Естественнее. «dual-format» — англицизм |
| `Markdown inline` | `Markdown в чате` | Добавлено «в чате» для контекста MD-инлайна. Inline без перевода не очевидно для русскоязычного |
| `HTML file via MEDIA:` | `HTML-файл через MEDIA:` | Техническое `MEDIA:` оставлено как есть — это маркер платформы |
| `covering:` | `который охватывает:` | Согласование с «отчёт» (мужской род) |
| `КТ schedule compliance` | `соблюдение сроков контрольных точек (КТ)` | Полная расшифровка аббревиатуры при первом упоминании |
| `red/yellow` | `«красный/жёлтый»` | В кавычках — это статус-классификация, не цвет в графическом смысле |
| `PlanDate–ForecastDate deviation` | `отклонение между плановой и прогнозной датой` | Полная расшифровка полей |
| `project data completeness` | `полнота заполнения данных проекта` | Естественный PM-порядок слов в RU |
| `(Куратор, Руководитель, Паспорт, стадия ЖЦ, трудозатраты, платежи)` | оставлено как есть | Title-ы полей из UI Форсайт, перевод не требуется |
| `стадия ЖЦ` | оставлено как есть | Устоявшееся сокращение «жизненный цикл» |
| `look-ahead КТ relevance` | `актуальность прогнозов по КТ` | «look-ahead» — англицизм. В русской PM-практике — «актуальность прогнозов» (термин из SKILL.md раздел 2) |
| `overdue КТ where ForecastDate < today` | `просроченные КТ, у которых прогнозная дата раньше сегодняшней` | Полная расшифровка. «overdue» переводится как «просроченные» в PM-контексте |
| `financial status (forecast, прогноз фин.результата…` | `финансовый статус проекта (прогноз финансового результата…` | `forecast` (термин) → «прогноз финансового результата» полной формой для ясности |
| `отклонение текущей стоимости от плана` | оставлено как есть | Корректный PM-термин, не требует адаптации |
| `technical metadata (date, time, MCP version, user)` | `технические метаданные (дата, время, версия MCP, пользователь)` | Полная расшифровка |
| `Verdict:` | `Вердикт:` | Прямой перевод, без адаптации |
| `БОЛЕН / ТРЕБУЕТ ВНИМАНИЯ / ЗДОРОВ` | оставлено как есть | Устоявшаяся русская триада из исходного SKILL.md |
| `by critical-remark count` | `определяется по количеству критических замечаний` | Полная форма для ясности |
| `Visible data is filtered` | `Видимые данные ограничены` | Более гладко по-русски; «filtered» = «ограничены» в контексте прав |
| `in the host Форсайт system` | `в системе «Форсайт»` | Убрано `host` и `system` — естественнее; «хост Форсайт» звучит как сервер, а не как продукт |

## 4. Что **сохранено** без перевода (и почему)

| Термин | Почему оставлен |
|--------|-----------------|
| **PMForesight** | Бренд продукта из `serverInfo.name` |
| **ИСУП «Форсайт»** | Каноническая форма из `serverInfo.instructions` |
| **MCP** | Технологический термин (Model Context Protocol) |
| **MEDIA:** | Маркер платформы для отправки файлов |
| **Code**, **ProjectId** | Имена полей в Форсайт |
| **КТ** | Устоявшаяся аббревиатура (контрольная точка), расшифрована при первом упоминании |
| **Куратор**, **Руководитель** | Title-ы полей из UI Форсайт (не переводятся, чтобы пользователь узнал их) |
| **Паспорт** | Категория документа в Форсайт |
| **ЖЦ** | Устоявшееся сокращение «жизненный цикл» |
| **БОЛЕН / ТРЕБУЕТ ВНИМАНИЯ / ЗДОРОВ** | Устоявшаяся триада |
| **Красный/жёлтый** | В кавычках — статус-классификация |

## 5. Альтернативные варианты (если основной не подходит)

### 5.1. Сжатый вариант (~600 символов)

> Загружай по запросам «здоровье проекта», «оцени проект», «health check», «project status report», «анализ проекта» или при указании Code/ProjectId проекта в PMForesight. Формирует отчёт в двух форматах (MD в чате + HTML через `MEDIA:`): сроки КТ (красный/жёлтый), полнота данных (Куратор, Руководитель, Паспорт, стадия ЖЦ, трудозатраты, платежи), актуальность прогнозов, финансовый статус, технические метаданные. Вердикт: **БОЛЕН / ТРЕБУЕТ ВНИМАНИЯ / ЗДОРОВ**. Данные фильтруются по правам пользователя в «Форсайт».

**Когда использовать:** если `description` ограничен жёстким лимитом (не наш случай, но если понадобится).

### 5.2. Более формальный вариант (~950 символов)

> Используется, когда пользователь запрашивает комплексный отчёт о состоянии здоровья определённого проекта в системе PMForesight (ИСУП «Форсайт», PMForesight) посредством её MCP-сервера. Скилл активируется при следующих запросах: «здоровье проекта», «оцени проект», «health check», «project status report», «анализ проекта», а также при указании кода проекта (Code) или его идентификатора (ProjectId). По итогам выполнения формируется отчёт в двух форматах (Markdown в чате + HTML-файл посредством `MEDIA:`), содержащий следующие разделы: (1) соблюдение сроков контрольных точек (КТ) — отклонение между плановой и прогнозной датой с классификацией по цветам «красный/жёлтый»; (2) полнота заполнения данных проекта (Куратор, Руководитель, Паспорт, стадия ЖЦ, трудозатраты, платежи); (3) актуальность прогнозов по КТ (просроченные КТ, у которых прогнозная дата предшествует текущей); (4) финансовое состояние проекта (прогноз финансового результата по завершении проекта и его отклонение от планового, отклонение текущей стоимости от плана); (5) технические метаданные (дата, время, версия MCP, пользователь). Итоговый вердикт: **БОЛЕН / ТРЕБУЕТ ВНИМАНИЯ / ЗДОРОВ** — формируется на основании количества критических замечаний. Видимая информация ограничена правами пользователя в системе «Форсайт».

**Когда использовать:** для корпоративной документации / README.
