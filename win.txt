================================================================
 Hermes Agent — настройка соединения с Telegram на Windows
================================================================

Цель: поднять Telegram-gateway Hermes на Windows-машине и
обойти блокировку api.telegram.org со стороны хостера сервера
8.31.79.37 (twc1.net), где TCP-соединения к api.telegram.org
и 149.154.166.110:443 отваливаются по таймауту (HTTP 000,
total=6.0s).

Сценарий: ставим Hermes в WSL 2 (Ubuntu) и используем
Windows-хост как relay с прямым выходом в Telegram.

----------------------------------------------------------------
 0. Что понадобится
----------------------------------------------------------------

  - Windows 10 21H2+ или Windows 11
  - Виртуализация в BIOS (VT-x / AMD-V)
  - Минимум 4 ГБ RAM, 10 ГБ свободного места
  - Права администратора
  - SSH-ключ с сервера 8.31.79.37 (если есть белый IP дома)
  - 15–30 минут

----------------------------------------------------------------
 1. Установка WSL 2 + Ubuntu
----------------------------------------------------------------

PowerShell от администратора:

  PS> wsl --install
  PS> wsl --set-default-version 2
  # перезагрузка
  PS> wsl -l -v

Проверка systemd (нужен для gateway-сервиса):

  PS> wsl -d Ubuntu
  user@DESKTOP:~$ cat /etc/wsl.conf
    [boot]
    systemd=true
  user@DESKTOP:~$ systemctl --user status
    # не должно ругаться на "Failed to connect to bus"

Если systemd=false — поправь файл:
  user@DESKTOP:~$ sudo nano /etc/wsl.conf
  PS> wsl --shutdown
  PS> wsl -d Ubuntu

----------------------------------------------------------------
 2. Доступ к WSL снаружи (OpenSSH Server)
----------------------------------------------------------------

Вариант A — есть белый IP / проброс порта 22 на роутере:

  PS> Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
  PS> Start-Service sshd
  PS> Set-Service -Name sshd -StartupType 'Automatic'
  PS> New-NetFirewallRule -Name sshd -DisplayName 'OpenSSH Server' `
        -Enabled True -Direction Inbound -Protocol TCP `
        -Action Allow -LocalPort 22

  # Авторизуй ключ с сервера 8.31.79.37:
  PS> mkdir $env:USERPROFILE\.ssh -Force
  PS> notepad $env:USERPROFILE\.ssh\authorized_keys
    # вставь публичный ключ с сервера

  Проверка с сервера:
  $ ssh windows-user@домашний-ip

Вариант B — нет белого IP:
  Используй обратный SSH-туннель (relay = SOCKS через туннель,
  а не отдельный gateway). Команды см. в hermes-agent skill.

----------------------------------------------------------------
 3. Установка Hermes в WSL
----------------------------------------------------------------

  PS> wsl -d Ubuntu
  user@DESKTOP:~$ curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
  user@DESKTOP:~$ hermes --version          # 0.16.0

Если install.sh ругается на отсутствие pip:
  user@DESKTOP:~$ sudo apt update
  user@DESKTOP:~$ sudo apt install -y python3-venv python3-pip
  user@DESKTOP:~$ python3 -m venv ~/.hermes/venv
  user@DESKTOP:~$ source ~/.hermes/venv/bin/activate
  user@DESKTOP:~$ pip install hermes-agent

----------------------------------------------------------------
 4. Перенос .env и config.yaml с сервера 8.31.79.37
----------------------------------------------------------------

  $ scp ~/.hermes/.env        windows-user@домашний-ip:~/tmp-hermes/
  $ scp ~/.hermes/config.yaml windows-user@домашний-ip:~/tmp-hermes/

Или одной командой через WSL-SCP:
  PS> wsl bash -c "scp server-user@8.31.79.37:~/.hermes/.env \
                            ~/.hermes/ && \
                    scp server-user@8.31.79.37:~/.hermes/config.yaml \
                            ~/.hermes/ && \
                    chmod 600 ~/.hermes/.env"

  user@DESKTOP:~$ ls -la ~/.hermes/      # должны быть .env и config.yaml
  user@DESKTOP:~$ chmod 600 ~/.hermes/.env

----------------------------------------------------------------
 5. Поднимаем gateway
----------------------------------------------------------------

  user@DESKTOP:~$ hermes setup gateway
                  # Telegram уже configured (подхватит токен)
                  # Done → Y на рестарт
  user@DESKTOP:~$ hermes gateway install
  user@DESKTOP:~$ systemctl --user status hermes-gateway
                  # active (running)

  Тест доступа к Telegram:
  user@DESKTOP:~$ curl -sS -m 6 -o /dev/null -w "%{http_code} %{time_total}s\n" \
                  https://api.telegram.org/

  Логи:
  user@DESKTOP:~$ tail -f ~/.hermes/logs/gateway.log | grep -i telegram

Открой бота в Telegram, нажми /start.

----------------------------------------------------------------
 6. Гасим старый gateway на сервере 8.31.79.37
----------------------------------------------------------------

  $ hermes gateway stop
  $ systemctl --user disable hermes-gateway
  $ sudo systemctl --user mask hermes-gateway

----------------------------------------------------------------
 Подводные камни (набитые шишки)
----------------------------------------------------------------

1) WSL засыпает с ноутом.
   Power Settings → Screen and sleep → "Never" для
   "When plugged in, PC goes to sleep after".
   Иначе ночью бот уйдёт в офлайн.

2) WSL 2 + IPv6-фолбэк Telegram.
   Если на домашнем провайдере тоже ломается IPv6,
   в ~/.hermes/config.yaml выстави:
     network:
       force_ipv4: true

3) Файрвол Windows / антивирус.
   Kaspersky, ESET и встроенный Defender любят перехватывать
   порт 22. Проверь:
     PS> Get-NetFirewallRule | ? DisplayName -match ssh

4) Таймзона.
   WSL по умолчанию синхронизируется с Windows. Если Telegram
   шлёт "по UTC", а у тебя MSK:
     user@DESKTOP:~$ echo 'TZ=Europe/Moscow' | sudo tee -a /etc/environment
     PS> wsl --shutdown

5) CRLF в .env.
   Windows-редакторы сохраняют с \r\n. После копирования:
     user@DESKTOP:~$ file ~/.hermes/.env
       # → "ASCII text"                       OK
       # → "ASCII text, with CRLF line..."    ПЛОХО
     user@DESKTOP:~$ sed -i 's/\r$//' ~/.hermes/.env

6) Авто-обновление Windows.
   Иногда внезапно перезагружает машину и роняет gateway.
   Отключи:
     PS> Set-ItemProperty -Path "HKLM:\SOFTWARE\Microsoft\WindowsUpdate\UX\Settings" `
           -Name "FlightSettings" -Value 0

7) Несколько WSL-дистрибутивов.
   Закрепи Ubuntu по умолчанию:
     PS> wsl -s Ubuntu

8) Пути в WSL.
   ~/.hermes/                       ← Unix-путь, туда кладём всё
   /mnt/c/Users/.../                ← Windows-диск, НЕ класть сюда
                                      (будет тормозить + проблемы
                                       с правами)

9) PATH в WSL.
   Если "command not found: hermes":
     echo 'export PATH=$HOME/.local/bin:$PATH' >> ~/.bashrc
     source ~/.bashrc

10) Сетевые таймауты.
    Если `curl https://api.telegram.org/` на Windows-WSL тоже
    таймаутится — Windows-хост за тем же провайдером, что
    и сервер. Тогда либо SOCKS5-прокси, либо VPS.

----------------------------------------------------------------
 Быстрая проверка "всё ли ок"
----------------------------------------------------------------

  user@DESKTOP:~$ hermes doctor
  user@DESKTOP:~$ hermes status --all
  user@DESKTOP:~$ hermes gateway status

----------------------------------------------------------------
 Альтернативы, если WSL не подходит
----------------------------------------------------------------

  - VPS за $3-5/мес (Hetzner, DigitalOcean, Vultr).
    Команды те же, что для Linux-relay, без Windows-обёрток.

  - Raspberry Pi / мини-ПК дома — 24/7, не обновляется
    внезапно, не засыпает.

  - Mac mini / старый ноут — ок, если всегда включен.
