GUI ДЛЯ HERMES AGENT НА LINUX VPS — ОБЗОР ВАРИАНТОВ
====================================================
Версия: 1.0 · Ubuntu 24.04 · без GUI-сервера из коробки
Назначение: какой интерфейс к Hermes можно поднять на этом
VPS, плюс что на нём уже работает как "GUI" через messaging.

----------------------------------------------------------------
0. КОРОТКИЙ ОТВЕТ
----------------------------------------------------------------
Сам Hermes — терминальное приложение (использует prompt_toolkit,
требует TTY). Полноценного ОФИЦИАЛЬНОГО web-GUI / desktop-GUI
для Linux у Hermes нет. Из коробки в docs описаны 4 пути:

  1. Hermes Desktop — только Windows/macOS, не подходит.
  2. her mes acp + ACP-IDE (Zed и т. п.) — требует редактора
     на стороне клиента.
  3. her mes chat в tmux — это TUI, не GUI, но выглядит "как
     окно" при подключении.
  4. her mes chat -q "<prompt>" — one-shot, без интерактива.

Всё, что ниже, — это обходные пути, ранжированные от прагматичного
к костыльному.

2. ВАРИАНТ A. WEB-ТЕРМИНАЛ ЧЕРЕЗ ttyd (самый прагматичный)
----------------------------------------------------------------
2.1. Что это:
     ttyd (https://github.com/tsl0922/ttyd) пробрасывает
     произвольный TTY-процесс в браузер через WebSocket. Любой
     браузер на любом устройстве получает работающий TUI-чат
     прямо в окне. Без X-сервера, без VNC, без перекомпиляции.

2.2. Что нужно на сервере:
     apt-get update
     apt-get install -y ttyd tmux
     # her mes и tmux уже стоят

2.3. Запуск:
     # 1) удобный фоновый режим через systemd
     cat > /etc/systemd/system/ttyd-hermes.service <<'EOF'
     [Unit]
     Description=ttyd web terminal for Hermes chat
     After=network.target
     [Service]
     Type=simple
     User=root
     ExecStart=/usr/bin/ttyd -p 7681 -i 0.0.0.0 \
               tmux new-session -A -s hermes -x 120 -y 40 \
               'HERMES_TMUX=1 hermes chat'
     Restart=on-failure
     RestartSec=3
     [Install]
     WantedBy=multi-user.target
     EOF
     systemctl daemon-reload
     systemctl enable --now ttyd-hermes.service

     # 2) открыть в браузере
     #    http://<vps-ip>:7681

2.4. Подводные камни:
     - Порт 7681/tcp должен быть открыт в firewall
       (ufw allow 7681/tcp или cloud-provider security group).
     - Без TLS логин и команды идут plain-text. Если VPS
       публичный — ОБЯЗАТЕЛЬНО повесить nginx/Caddy с TLS
       перед ttyd, либо заходить через SSH-туннель:
         ssh -L 7681:localhost:7681 root@<vps>
         # и открывать http://localhost:7681 в браузере.
     - ttyd без -c basic-auth пускает всех. Добавьте:
         -c admin:<password>   # НЕ пишите пароль в cmdline —
                               # см. ниже про sanitization.
     - Из-под root her mes chat работает, но если запускать
       от обычного пользователя — переменная $HOME другая,
       и ~/.hermes будет свой. Учитывайте при выборе User=.

2.5. Проверка:
     systemctl status ttyd-hermes.service
     curl -sS -m 5 -o /dev/null -w "ttyd HTTP=%{http_code}\n" \
          http://localhost:7681
     # Должен быть 200; в браузере — окно с prompt_toolkit.

3. ВАРИАНТ B. OPEN WEBUI + HERMES API SERVER ADAPTER
----------------------------------------------------------------
3.1. Что это:
     В скилле hermes-agent и в официальной документации
     упомянуто: "Open WebUI connects via the API Server adapter".
     Open WebUI (https://github.com/open-webui/open-webui) —
     это полноценный web-чат с историей, сессиями, файлами,
     голосом, RAG, и т. п. Подключается к Hermes через
     gateway/platforms/apiserver.py как к OpenAI-совместимому
     API endpoint'у.

3.2. Что нужно:
     # Open WebUI ставится через pip venv или docker.
     # Предпочтительно через uv, т.к. системный python=3.12.3
     # без pip (PEP 668).
     apt-get install -y docker.io docker-compose-plugin
     # или
     pipx install open-webui

3.3. Запуск (docker-вариант):
     docker run -d --name open-webui \
       -p 8080:8080 \
       -v open-webui-data:/app/backend/data \
       --restart always \
       ghcr.io/open-webui/open-webui:main

3.4. На стороне Hermes:
     her mes gateway setup        # включить API Server platform
     # или вручную в ~/.hermes/config.yaml:
     #   gateway.platforms.apiserver.enabled: true
     #   gateway.platforms.apiserver.port:     9000
     her mes gateway restart
     # Open WebUI на 8080, Hermes API на 9000. Связать через
     # "OpenAI API" endpoint: http://localhost:9000/v1

3.5. Подводные камни:
     - Docker может быть недоступен на этом VPS (нужно
       проверить: docker info, есть ли /var/run/docker.sock).
     - open-webui пробрасывает свои пути к моделям; Hermes
       использует свой ~/.hermes. Конфигурация моделей не
       пересекается, но в Open WebUI нужно вручную добавить
       endpoint и API-ключ (можно сгенерировать фиктивный,
       если adapter не проверяет).
     - Это НЕ официальный GUI Hermes, а сторонний интерфейс
       поверх API Server adapter. Внешний вид и фичи
       определяются Open WebUI, а не Hermes.

3.6. Проверка:
     curl -sS -m 5 -o /dev/null -w "openwebui HTTP=%{http_code}\n" \
          http://localhost:8080
     her mes gateway status | grep -i apiserver
     her mes mcp list            # api server не путать с MCP

4. ВАРИАНТ C. X11-FORWARDING ЧЕРЕЗ SSH + ACP-IDE
----------------------------------------------------------------
4.1. Что это:
     На локальной Linux/Mac-станции поднимается X-сервер
     (XQuartz на Mac, обычный X.org на Linux). SSH-форвардинг
     X11 тянет GUI-окна на локальную машину. На сервере
     запускается IDE (Zed) и подключается к Hermes через
     her mes acp.

4.2. Что нужно:
     # Локально (Linux):
     sudo apt-get install -y xauth
     ssh -X root@<vps>            # или ssh -Y для trusted forwarding
     # На сервере:
     apt-get install -y xauth libx11-xcb1
     # Установить Zed на сервер:
     curl -fsSL https://zed.dev/install.sh | sh
     # (если у них сейчас .deb — лучше скачать .deb)
     zed &
     # В Zed — настроить ACP-подключение к Hermes:
     #   "Hermes ACP" → host: localhost, command: hermes acp
     # Это экспериментальная интеграция; может потребоваться
     # плагин.

4.3. Подводные камни:
     - Zed на серверной Ubuntu — тяжёлая зависимость: GTK4,
       cargo (~600 МБ), build-deps. Долгая компиляция из исходников.
     - X11-форвардинг медленный по WAN. Если у вас VPS в
       другой стране — Zed будет лагать.
     - her mes acp + Zed — экспериментальная интеграция. В
       скилле Hermes упомянуто вскользь; готового plug-and-play
       нет. Готовьтесь читать исходники.
     - Если у вас локально Windows — путь сильно другой
       (WSLg или VcXsrv/WSL2).

4.4. Альтернатива попроще: VSCode Remote-SSH.
     VSCode умеет Remote-SSH без X-форвардинга — он сам
     тянет remote-server и работает локально как тонкий клиент.
     В Remote-окне ставите расширение "Hermes" (если есть в
     marketplace) или подключаетесь к her mes acp через
     custom command. Сложно, но работает.

5. ВАРИАНТ D. NOVNC + XVFB (тяжёлая артиллерия)
----------------------------------------------------------------
5.1. Что это:
     На сервере поднимается виртуальный X-сервер (Xvfb),
     внутри openbox-сессия, в ней xterm с her mes chat, VNC
     пробрасывается через websockify в браузер как noVNC-страница.
     Получается настоящий web-рабочий стол с окном терминала.

5.2. Что нужно:
     apt-get install -y xvfb x11vnc openbox xterm websockify novnc
     # Xvfb и libx11 на сервере уже стоят; не хватает
     # x11vnc, openbox, xterm, websockify, novnc.

5.3. Запуск (всё в фоне, через systemd для боевого деплоя):
     Xvfb :99 -screen 0 1280x800x24 -ac &
     DISPLAY=:99 openbox-session &
     DISPLAY=:99 xterm -fa 'Monospace' -fs 12 \
                     -e 'tmux new-session -A -s hermes her mes chat' &
     x11vnc -display :99 -forever -nopw -rfbport 5900 &
     websockify --web /usr/share/novnc 6080 localhost:5900 &

     # В браузере: http://<vps-ip>:6080/vnc.html

5.4. Подводные камни:
     - Тяжело: жрёт RAM (~300 МБ на Xvfb+openbox+терминалы).
     - Нет шифрования по умолчанию — VNC plain-text. Нужен
       SSH-туннель ИЛИ nginx/Caddy с WebSocket-проксированием.
     - Из пушки по воробьям ради текстового TUI. Имеет смысл
       только если вы хотите в одном окне видеть ещё и другие
       GUI-приложения (например, GUI-IDE, файловый менеджер).
     - На headless-сервере без /dev/dri и без GPU всё равно
       работает (Xvfb — софтрендер), но производительность
       оставляет желать лучшего.

5.5. Когда выбирать:
     - Нужно "настоящий рабочий стол" с несколькими окнами
       (терминал + браузер + IDE).
     - У вас VPS с 4+ ГБ RAM и 2+ CPU.
     - Вы готовы потратить день на настройку и отладку.

----------------------------------------------------------------
6. ВАРИАНТ E. БРАУЗЕР-СКИЛЛ HERMES КАК "GUI"
----------------------------------------------------------------
6.1. Что это:
     В скиллах Hermes есть browser-тулзеты (browser, image_gen,
     vision). Hermes сам поднимает headless-браузер и управляет
     web-интерфейсами. Это НЕ "GUI для оператора" — это "GUI
     как ещё один tool для агента".

6.2. Когда это уместно:
     - Агент сам заходит на сайты (например, заполняет формы,
       скрейпит данные, делает скриншоты).
     - Вам нужно, чтобы агент мог ОТОБРАЖАТЬ результат своей
       работы в виде web-страницы (например, сгенерированный
       отчёт).
     - Вам нужен скриншот интерфейса для последующей работы.

6.3. Это не альтернатива операторскому GUI — это дополнение.

8. РЕКОМЕНДАЦИЯ ДЛЯ ЭТОГО VPS
----------------------------------------------------------------
- Matrix уже работает, Telegram заблокирован upstream'ом —
  в первую очередь использовать Matrix-комнату.
- Если нужен именно браузер/web — ставить ttyd (2 команды,
  1 минута, ~30 МБ RAM).
- Если нужен полноценный чат с историей/сессиями/файлами —
  поднимать Open WebUI + API Server adapter (потребуется
  docker.io или pipx).
- X11-форвардинг и noVNC — для редких случаев, когда нужен
  именно "рабочий стол" с несколькими окнами.
