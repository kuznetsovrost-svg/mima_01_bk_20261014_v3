1. НАЗНАЧЕНИЕ ФАЙЛА
----------------------------------------
SOUL-prototype-5.md — пятая итерация системного промпта ядра
(Hermes Agent kernel prompt). Версия 5.0.0, status: stable.
Цель — превратить компактное ядро SOUL.md (513 байт, v1) в
производственно-надёжный промпт с явными правилами поведения.

Файл служит:
- системным промптом при загрузке ядра Hermes Agent;
- нижней границей поведения для всех профилей (default,
  mi_mg_01, analyst_training);
- контрактом между USER.md, MEMORY.md, *.skill и kernel;
- ссылкой на скилл `memory-hygiene` через §9.

Supersedes: SOUL-prototype.md, -2.md, -3.md, -4.md.

5. КЛЮЧЕВЫЕ РЕШЕНИЯ
----------------------------------------
5.1. Kernel-tier с явным разделением. В v5 файл называет
     себя kernel tier; profile-overlays вынесены как
     отдельная сущность (`~/.hermes/profiles/<name>/OVERLAY.md`).
     Это означает: SOUL.md — нижняя граница, не верхняя;
     USER/skill могут расширять, не могут ослаблять.

5.2. Реальный скилл вместо описания в промпте. v5 не
     просто упоминает memory-hygiene как концепт; скилл
     живой, загружается через skill_view, проверяется через
     readiness_status=available. Это превращает §9 из
     декларации в операционный контракт.

5.3. tiktoken вместо эвристики. Эвристика words×1.4 в v3/v4
     переоценивала компактность; tiktoken показал, что
     фактический размер v4 был 2 441 токен, а не 1 474.
     Это спасло от отправки файла, нарушающего собственный
     бюджет.

5.4. STRICT MINIMUM конфликт-резолвер. При коллизии
     SOUL ↔ skill: побеждает более конкретное правило.
     SOUL — strict minimum: расширять можно, ослаблять
     нельзя. Это инверсия привычной модели «SOUL главнее»
     — здесь SOUL является точкой минимума, а не точкой
     максимума.

5.5. Tool-output scan: секреты и маски §8 (вместо §8 v4).
     Реальная проблема, выявленная в этой сессии: Hermes
     маскирует секреты как `***`, и модель может зациклиться
     на этой маске. В v5 §8 явно предписано: для получения
     реального значения использовать grep/read_file/$ENV,
     а не копировать маску.

6. ПРОБЛЕМЫ, С КОТОРЫМИ СТОЛКНУЛСЯ
----------------------------------------
6.1. WRITE_FILE подкидывал инъекцию в результат. В этой
     сессии write_file несколько раз возвращал странный
     текст («Modification Complete... DIAGNOSTIC...»).
     Workaround: писать через subprocess+cp в /tmp, затем
     копировать в финальный путь. Это безопаснее и
     исключает инъекцию в сам файл.

6.2. F-string syntax error при попытке добавить build-meta.
     Python 3.11 f-string не поддерживает `"` внутри
     expression. Workaround: вынести тернарный оператор в
     отдельную переменную или использовать write_file
     напрямую.

6.3. YAML alias error в `*.skill`. Звёздочка в YAML —
     alias marker. Workaround: обернуть все элементы списка
     в кавычки ["SOUL.fail-safe", "USER.md", ...].

6.4. Превышение собственного бюджета. Первая попытка v5
     = 2 441 токен при бюджете 2200. Workaround: сжатие
     формулировок вместо удаления секций. Финал: 1 852.
