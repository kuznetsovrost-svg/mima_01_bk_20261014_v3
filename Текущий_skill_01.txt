Как при работе профиля попросить Hermes использовать конкретный скилл этого профиля
====================================================================================

Короткий ответ
--------------
Hermes выбирает скиллы **в момент построения системного промпта сессии** из
`HERMES_HOME/skills/` той сессии, в которой он запущен. Поэтому, чтобы
профиль использовал «свой» скилл, нужно, чтобы этот скилл физически лежал
в `skills/` именно этого профиля и чтобы сессия стартовала под этим
профилем. После старта сессии можно дополнительно «загрузить» скилл
командой `/skill <name>` или флагом `--skills` — иначе модель видит только
названия и описания из `<profile>/skills/` (lightweight discovery), а
полный текст SKILL.md подгружается в контекст только когда скилл выбран.

1. Где живут скиллы профиля
---------------------------
Каждый профиль — это изолированный `HERMES_HOME` (см. `hermes_cli/profiles.py`).
Путь к скиллам профиля:

    default       →  ~/.hermes/skills/<skill-name>/SKILL.md
    <имя_профиля> →  ~/.hermes/profiles/<имя_профиля>/skills/<skill-name>/SKILL.md

Важные следствия:
  • Папка `profiles/<name>/skills/` создаётся только при `hermes profile create <name>`
    (или вручную через `mkdir -p`). Если её нет, `hermes skills list` внутри
    профиля молча показывает ноль скиллов — это не ошибка.
  • Bundled-скиллы (которые идут с Hermes) засеиваются в каждый профиль
    автоматически; своя кастомизация живёт рядом с ними.
  • Файл-маркер `~/.hermes/profiles/<name>/.no-bundled-skills` отключает
    авто-сидинг bundled-скиллов в этот профиль.
  • Активный профиль — sticky: определяется содержимым
    `~/.hermes/active_profile`. Проверить можно:
        cat ~/.hermes/active_profile
        hermes profile list
        echo $HERMES_HOME
        hermes doctor | head -20

2. Положить скилл в нужный профиль — 3 способа
----------------------------------------------
Способ A — вручную:
    mkdir -p ~/.hermes/profiles/<profile>/skills/<skill-name>
    $EDITOR        ~/.hermes/profiles/<profile>/skills/<skill-name>/SKILL.md
    # затем проверить:
    hermes -p <profile> skills list
    hermes -p <profile> skills inspect <skill-name>

Способ B — из hub/registry, прицельно в профиль:
    hermes -p <profile> skills install <owner/repo>
    # поддерживается и прямой URL на SKILL.md:
    hermes -p <profile> skills install https://…/SKILL.md --name <skill-name>

Способ C — программно из агентской сессии (skill_manage):
    # По умолчанию пишет в АКТИВНЫЙ профиль.
    # Если целевой профиль не совпадает с активным — сначала переключитесь:
    hermes profile use <profile>
    # и затем уже:
    skill_manage(action="create", name="...", content="...")

    # Известный pitfall: skill_manage иногда пишет в ~/.hermes/skills/
    # независимо от HERMES_HOME, если контекст закрепил default. В этом
    # случае надёжнее — ручной mkdir + write_file в нужный профиль.

3. Как попросить Hermes использовать конкретный скилл
----------------------------------------------------
После того как SKILL.md лежит в правильном месте, есть три точки входа,
чтобы «активировать» скилл в текущей сессии:

A) Внутри сессии (интерактивный CLI или gateway-сессия профиля):
       /skill <skill-name>
   Подгружает полный текст SKILL.md в контекст. Команда определена в
   `hermes_cli/commands.py`. В Telegram/Discord/Slack и т. п. она
   недоступна напрямую — см. способ C.

B) Флаг запуска (разово, при старте сессии):
       hermes -p <profile> --skills <skill-name> chat -q "..."
       # можно несколько через запятую или повторяя --skills:
       hermes -p <profile> --skills a,b --skills c chat -q "..."
   В one-shot режиме `hermes chat -q "..."` это самый чистый способ:
   профиль выбран, нужные скиллы загружены, сессия короткоживущая.

C) В сообщении агенту (естественным языком, в любом канале):
       "Используй скилл <skill-name> для этой задачи."
       "Примени профильный скилл <skill-name> из моего профиля <profile>."
   Hermes посмотрит, какие скиллы доступны в текущей сессии (т. е. в
   активном профиле), и вызовет `skill_view(name="...")` для нужного.
   Если скилл лежит в НЕ активном профиле — он не виден, см. ниже.

D) Плагин `skills` в skills_config (config.yaml):
       skills:
         platforms:
           matrix:
             enabled:
               - <skill-name>
   Включает скилл для всех matrix-сессий глобально. Для per-profile —
   редактируйте `~/.hermes/profiles/<profile>/config.yaml` аналогично.

4. Скилл из НЕ активного профиля — что делать
----------------------------------------------
`skill_view()` и `skill_manage()` работают в рамках той `HERMES_HOME`,
которая зашита в текущую сессию. Из default-сессии нельзя «просто так»
прочитать скилл из profiles/work/ — путь другой, и движок не ищет
скиллы по всем профилям подряд.

Решения:
  1) Переключиться: `hermes profile use <profile>` и стартовать новую
     сессию (в CLI — `/reset`; в gateway — перезапуск под нужным
     профилем).
  2) Скопировать/симлинкнуть SKILL.md в активный профиль (если это разовая
     задача и допустимо смешивать каталоги).
  3) Запустить разовую сессию прицельно:
         hermes -p <profile> --skills <skill> chat -q "..."
  4) В cron-задаче задать `profile: "<profile>"` — тогда задача выполнится
     под нужным профилем со всеми его скиллами.

5. Пошаговый рецепт: «профиль X должен автоматически подключать скилл Y»
------------------------------------------------------------------------
  1) Убедиться, что профиль существует:
         hermes profile list
     (если нет — `hermes profile create X`).
  2) Положить SKILL.md:
         mkdir -p ~/.hermes/profiles/X/skills/Y
         write ~/.hermes/profiles/X/skills/Y/SKILL.md   # или skill_manage
  3) Проверить:
         hermes -p X skills list          # Y должен быть в списке
         hermes -p X skills inspect Y     # превью без загрузки
  4) Стартовать сессию под X:
         hermes -p X                      # интерактивно
         hermes -p X chat -q "..."        # one-shot
         tmux new -s x 'hermes -p X'      # долгоживущая
  5) Внутри сессии попросить:
         /skill Y
     или в сообщении: «используй скилл Y».
  6) Альтернативно, зашить скилл в config.yaml профиля, чтобы он
     подгружался без ручного `/skill`:
         # ~/.hermes/profiles/X/config.yaml
         skills:
           platforms:
             <ваша-платформа>:
               enabled: [Y]

6. Типовые грабли
-----------------
  • «Поставил скилл, а его не видно» → установили не в тот профиль.
    Проверяйте `hermes -p <profile> skills list` для каждого профиля
    отдельно, активный профиль может быть не тот, в который вы ставили.
  • Изменения в skills/ подхватываются только при старте новой сессии
    (CLI — `/reset`, gateway — перезапуск процесса). `/reload-skills`
    пересканирует каталог в рантайме.
  • `hermes update` синхронизирует bundled-скиллы во ВСЕ профили, при
    этом файлы, помеченные как user-modified, не перезаписываются.
  • `hermes -p X` стартует сессию под X, но one-shot `hermes chat -q …`
    без `-p` использует активный профиль. Не путайте «активный
    профиль оболочки» (export HERMES_HOME=…) с «активным профилем
    Hermes» (active_profile) — они должны совпадать.
  • Скиллы, не упомянутые в `--skills` и не вызванные через
    `skill_view()`, видны модели только как имя+описание из
    frontmatter. Если нужен полный текст — либо `/skill`, либо явная
    просьба в сообщении, либо предзагрузка через `--skills`.

Итого, формула: «положить SKILL.md в `<profile>/skills/<name>/`,
стартовать сессию под этим профилем, попросить `/skill <name>` или
передать `--skills <name>` при запуске, либо дать инструкцию в
сообщении агенту».
