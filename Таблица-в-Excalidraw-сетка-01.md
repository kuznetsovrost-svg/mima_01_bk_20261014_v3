Глава 1. Как объединить объекты в группы (контекст)
----------------------------------------------------

В .excalidraw группы хранятся в поле groupIds.

JSON структура:
{
  "elements": [
    {
      "id": "rect1",
      "type": "rectangle",
      "groupIds": ["group-A"],
    },
    {
      "id": "rect2",
      "type": "rectangle",
      "groupIds": ["group-A"],
    },
    {
      "id": "text1",
      "type": "text",
      "groupIds": ["group-A"],
    }
  ]
}

Все объекты с одинаковым groupIds — одна группа.

Способы объединения в UI:
1. Выделить несколько объектов → Ctrl+Shift+G
2. Frame (Add to frame) — визуальная рамка с заголовком
3. Контейнерные фигуры — вложение через containerId

Что я вижу при анализе файла:
- groupIds: ["X"] у нескольких → это группа
- frameId: "X" у объектов + frame в elements → это frame
- containerId: "X" → вложен в другую фигуру
- boundElements: [{id, type}] → связи (стрелка → target)

Рекомендация для схемы которую я буду описывать:
- Frame — для визуальных блоков схемы (заголовок + рамка)
- Group — для логических единиц (без визуала)
- Стрелки с binding — для связей
- Именовать Frame через name — чтобы я понимал назначение

Когда я открою .excalidraw через read_file:
1. Найду все группы (уникальные значения в groupIds)
2. Найду все frame (элементы с type=frame или с frameId)
3. Построю описание — перечислю объекты по группам/фреймам

Чего я не проверял:
- Реальное поведение Excalidraw UI — не делал
- Документацию — не открывал
- Версия в VS Code extension — не проверял


Глава 2. Может ли объект входить в две группы (контекст)
---------------------------------------------------------

Короткий ответ: да, объект может входить в несколько групп
и фреймов одновременно. groupIds — массив, может содержать
несколько ID.

Пример:
{
  "id": "skill-A1-B2",
  "type": "text",
  "text": "Навык X",
  "groupIds": ["topic-2", "stage-3"],
  "frameId": null,
}

Важный нюанс — frameId vs groupIds:

frameId    — string или null — ОДИН frame на объект
groupIds   — array — МНОГО групп
containerId — string или null — ОДИН родитель

То есть frame технически один, но group — несколько.

Контекст задачи: таблица навыков в Excalidraw.
- Строки = темы обучения (тема 1, тема 2, ...)
- Столбцы = ступени (ступень 1, ступень 2, ...)
- В клетках — навыки (отдельные объекты)
- При написании текста нужно перечислить навыки по теме N и ступени M.

Три варианта решения:

Вариант 1: через groupIds (массив)
{
  "id": "skill-1",
  "text": "Анализировать данные",
  "groupIds": ["topic-data-science", "stage-3-advanced"],
}

Тогда я могу найти пересечение — навыки темы X на ступени Y.

Вариант 2: через Frame — только одна координата
Frame — только один. Нельзя объект поместить в два frame.

Вариант 3: через координаты (x, y)
{
  "id": "skill-1",
  "x": 200,
  "y": 300,
}
Если строки и столбцы фиксированы, я вычисляю принадлежность
по координатам.

Сравнение способов:
- Способ 1 (groupIds массив): чистая структура, ручная правка JSON
- Способ 2 (Frame): только одна координата, не подходит
- Способ 3 (координаты): не нужно править JSON, вычисление

В UI Excalidraw добавление объекта в две группы сложно —
обычно Ctrl+Shift+G даёт одну группу. Для множественных
групп нужно править JSON вручную.


Часть II. Способ "строгая сетка" — детальный playbook
=====================================================


Введение
--------

Этот playbook описывает работу с таблицей навыков в Excalidraw
через координатную сетку. Это самый простой способ — не нужно
править JSON, не нужны множественные группы, всё видно в UI.

Идея: расположить навыки в строгой сетке, где:
- X (горизонталь) = ступень обучения
- Y (вертикаль) = тема
- Каждая клетка имеет фиксированные координаты

При чтении файла я вычисляю принадлежность навыка к теме и
ступени по его позиции (x, y).


Глава 3. Структура таблицы
-------------------------

3.1 Параметры сетки

    Ширина столбца (ступень): 150 px (рекомендация)
    Высота строки (тема): 100 px (рекомендация)
    Левый отступ: 50 px (для подписей тем)
    Верхний отступ: 50 px (для подписей ступеней)

    Пример для 3 ступеней и 4 тем:
    - X для ступеней: 50, 200, 350, 500
    - Y для тем: 100, 200, 300, 400

3.2 Заголовки

    Верхний ряд (Y=50) — подписи ступеней:
    - "Ступень 1" в X=125 (центр первой клетки)
    - "Ступень 2" в X=275
    - "Ступень 3" в X=425

    Левый столбец (X=50) — подписи тем:
    - "Тема 1" в Y=150 (центр первой строки)
    - "Тема 2" в Y=250
    - "Тема 3" в Y=350
    - "Тема 4" в Y=450

3.3 Клетки с навыками

    В каждой клетке — объект с текстом навыка.
    Позиция: центр клетки.

    Пример для навыка в теме 2, ступени 3:
    - X = 50 + (3-1) * 150 + 75 = 425 (центр столбца)
    - Y = 50 + (2-1) * 100 + 50 = 200 (центр строки)

    Или проще:
    - X клетки = 200 + (ступень-1) * 150
    - Y клетки = 100 + (тема-1) * 100


Глава 4. Создание таблицы в Excalidraw
-------------------------------------

Шаг 1. Создать заголовки ступеней

    1. Выбрать Text tool
    2. В верхнем ряду создать подписи "Ступень 1", "Ступень 2", ...
    3. Выровнять по горизонтали
    4. Зафиксировать Y для всех = 50

Шаг 2. Создать заголовки тем

    1. Выбрать Text tool
    2. В левом столбце создать "Тема 1", "Тема 2", ...
    3. Зафиксировать X для всех = 50

Шаг 3. Нарисовать сетку (опционально)

    1. Rectangle tool
    2. Нарисовать прямоугольник вокруг таблицы
    3. Стиль: dashed (пунктир), без заливки

Шаг 4. Заполнить клетки навыками

    1. Text tool
    2. В каждой клетке — текст навыка
    3. Размер шрифта: 16 px (компактно)
    4. Ширина текста: до 130 px (внутри столбца 150 px)

Шаг 5. Сохранить файл

    Ctrl+S
    Формат: .excalidraw

Глава 6. Алгоритм анализа (как я это делаю)
-------------------------------------------

Когда ты скажешь "перечисли навыки темы 2 на ступени 3",
я выполняю:

6.1 Определить параметры сетки

    cell_width = 150   # ширина столбца
    cell_height = 100  # высота строки
    offset_x = 50      # левый отступ
    offset_y = 50      # верхний отступ

6.2 Определить целевые координаты

    target_topic = 2
    target_stage = 3

    target_x_min = offset_x + (target_stage - 1) * cell_width
    target_x_max = offset_x + target_stage * cell_width

    target_y_min = offset_y + (target_topic - 1) * cell_height
    target_y_max = offset_y + target_topic * cell_height

    Например, для темы 2 ступени 3:
    target_x: от 350 до 500
    target_y: от 150 до 250

6.3 Найти все объекты в этой клетке

    matching = []
    for elem in elements:
        if elem.type == "text":
            # центр объекта в клетке?
            cx = elem.x + elem.width / 2
            cy = elem.y + elem.height / 2
            if (target_x_min <= cx <= target_x_max and
                target_y_min <= cy <= target_y_max):
                matching.append(elem.text)

6.4 Вернуть список

    ["Навык A", "Навык B", "Навык C"]


Глава 7. Соглашения о структуре
-------------------------------

Чтобы алгоритм работал стабильно, нужно соблюдать:

7.1 Фиксированный шаг сетки

    Шаг между столбцами и строками должен быть ОДИНАКОВЫМ
    на всей таблице. Не делай "одна строка выше, другая ниже".

7.2 Все навыки в клетках

    Все объекты с текстом навыков должны быть строго внутри
    своих клеток. Если вылезает за границы — мой алгоритм
    может не найти или найти неправильно.

7.3 Не использовать arrow bindings для группировки

    Стрелки — для связей между сущностями, не для обозначения
    принадлежности к клетке.

7.4 Заголовки вне основной сетки

    Подписи "Ступень N" и "Тема N" находятся в отдельных зонах
    (сверху и слева). Не включай их в алгоритм — у них может
    быть специальная маркировка (см. 7.5).

7.5 Маркировка заголовков

    Заголовки помечать groupIds:
    - ступени: groupIds: ["headers-stages"]
    - темы: groupIds: ["headers-topics"]
    - навыки: groupIds: ["skills"] или пусто

    Это позволяет мне отделить заголовки от навыков при анализе.

Глава 12. Шпаргалка координат
-----------------------------

12.1 Формулы

    X клетки ступени N (левый край):
        x_left = 50 + (N - 1) * 150

    X центра столбца ступени N:
        x_center = 50 + (N - 1) * 150 + 75 = 125 + (N - 1) * 150

    Y клетки темы M (верхний край):
        y_top = 50 + (M - 1) * 100

    Y центра строки темы M:
        y_center = 50 + (M - 1) * 100 + 50 = 100 + (M - 1) * 100

12.2 Проверка попадания объекта в клетку (тема M, ступень N)

    obj_cx = obj.x + obj.width / 2
    obj_cy = obj.y + obj.height / 2

    is_in_cell = (
        50 + (N - 1) * 150 <= obj_cx <= 50 + N * 150 and
        50 + (M - 1) * 100 <= obj_cy <= 50 + M * 100
    )

12.3 Пример: таблица 4 темы × 5 ступеней

    Темы: Y = 100, 200, 300, 400 (центры)
    Ступени: X = 125, 275, 425, 575, 725 (центры)

    Клетка (тема 2, ступень 3):
    X: от 350 до 500
    Y: от 150 до 250
    Центр: (425, 200)

    Навык "Планирование эксперимента":
    - должен иметь x в [350, 500]
    - должен иметь y в [150, 250]
    - центр (x + width/2, y + height/2) внутри


Глава 13. Типичные ошибки
--------------------------

13.1 Сетка не выровнена

    Симптом: я не нахожу навык в клетке.
    Причина: x или y не кратны шагу.
    Решение: проверить координаты в JSON.

13.2 Объект слишком большой

    Симптом: его центр выходит за клетку.
    Причина: width > cell_width.
    Решение: уменьшить текст или разбить на 2 строки.

13.3 Навык в "ничьей" зоне

    Симптом: попадает на границу двух клеток.
    Причина: x ровно = границе между столбцами.
    Решение: округлить координаты.

13.4 Frame сдвигает координаты

    Симптом: мои формулы не совпадают с реальным положением.
    Причина: объекты внутри frame могут иметь координаты
    относительно frame, не глобальные.
    Решение: учитывать frame.x, frame.y как offset.

13.5 Много мелких объектов в одной клетке

    Симптом: я возвращаю 5 навыков хотя ты думал их 3.
    Причина: каждый мелкий объект считается отдельно.
    Решение: группировать мелкие объекты в один (groupIds).


Глава 14. Альтернативы (если сетка не подходит)
-----------------------------------------------

14.1 Когда выбрать другой способ

    - много пересечений (одна строка длинная) → координаты
    - неравномерные строки → groupIds массив
    - нужно визуально выделить группы → Frame

14.2 Способ "label в тексте"

    В тексте навыка писать:
    "[T2-S3] Навык X"

    Тогда я парсю регуляркой:
    import re
    m = re.match(r"\[T(\d+)-S(\d+)\] (.+)", text)
    if m:
        topic, stage, name = m.groups()

    Преимущества:
    - Видно в UI
    - Не зависит от позиции
    - Можно двигать объект

14.3 Способ "groupIds массив"

    В JSON вручную:
    {
      "id": "skill-t2-s3",
      "text": "Навык X",
      "groupIds": ["topic-2", "stage-3"],
    }

    Преимущества:
    - Самая чистая структура
    - Я могу точно фильтровать
    - Стандартно для данных

14.4 Что выбрать

    - Строгая сетка → этот playbook (просто)
    - Свободное расположение → label
    - Точная фильтрация → groupIds массив
