# Графические оболочки для визуального формирования LaTeX-шаблонов
Версия 04, 2026-07-08. Продолжение LaTex_02.txt (теория), LaTex_03.txt (готовый отчёт).
Здесь — обзор UI-инструментов, которые позволяют собрать LaTeX-шаблон мышкой
и~потом использовать его многократно.

## 0. Главный вопрос — что именно нужно от UI

Прежде чем выбирать инструмент, определись, какой из~этих сценариев тебе ближе:

| Сценарий | Что ожидается от UI | Подходящие инструменты |
|---|---|---|
| A. Собрать шаблон «один раз и навсегда», набивать данными | WYSIWYG-конструктор .cls/.tex + меню вставки блоков | LyX, TeXmacs, Overleaf + свой шаблон |
| B. Редактировать LaTeX «как Word» с подсветкой, автодополнением, просмотром PDF | Полноценный IDE | TeXstudio, TeXmaker, VS Code + LaTeX Workshop |
| C. Собирать отчёты из данных без правки .tex руками | Шаблон + Jinja2/Pandoc/Quarto + веб-интерфейс кнопки «Сгенерировать» | Quarto, Pandoc + Shiny/Streamlit, Observable |
| D. Дать дизайнеру/аналитику без знания LaTeX собрать шаблон | Визуальный конструктор без кода | LyX, Typst Pad, Quarto Studio (в планах) |
| E. Генерировать PDF по шаблону из корпоративной системы | Серверный движок + админка | Typst Cloud, docxtpl, Pandoc API, LaTeX CI |

Большинство реальных задач = комбинация A + C. Под~каждый сценарий — свой инструмент.

## 1. Веб-редакторы (collaborative online)

### 1.1. Overleaf — лидер рынка
**URL:** https://www.overleaf.com (бывший ShareLaTeX, объединились в~2017)

**Что умеет:**
- Двухпанельный редактор: LaTeX слева, PDF справа в~реальном времени.
- Совместная работа в~реальном времени (как~Google Docs), комментарии, история версий.
- **Галерея шаблонов** — 6000+ готовых шаблонов: статьи для~журналов (IEEE, ACM, Springer, Elsevier, Nature), диссертации (MIT, Harvard, Оксфорд, МГУ), резюме, презентации Beamer, постеры, бизнес-документы, лабораторные.
- «Link to project» — шаблон можно сделать публичным и~использовать как~стартовую точку для~новых проектов.
- Реферерная система: ты делаешь шаблон, делишься ссылкой, при~открытии пользователь получает копию.
- Git/GitHub-интеграция.
- Compile API — можно дёргать сборку из~внешней системы.
- Импорт из~Zotero, Mendeley, CiteDrive для~библиографии.
- Плагины: Grammarly, Figura (drag-and-drop графики), Knitr для~R.

**Тарифы (на~2026):**
- Free: 1 компилятор, 60~секунд таймаут, проекты публичные.
- Standard (\$15/мес): приватные проекты, больше памяти.
- Pro (\$30/мес): версия в~один клик, real-time track changes, 10~компиляторов.
- Pro+: до~30~компиляторов, история версий.

**Плюсы:** самый низкий порог входа, не~надо ничего устанавливать, мгновенный просмотр PDF, огромная галерея шаблонов.
**Минусы:** в~Free-версии проекты видны всем по~ссылке, нет локальной версии, привязка к~облаку, цифровая блокировка по~санкциям в~РФ (нужен VPN), платный для~команд.

**Резюме:** стандарт де-факто для~академии. Если делаешь шаблон «один раз и~для~всех» — Overleaf Gallery. Если нужен приватный self-hosted — Papeeria или CoCalc.

### 1.2. Papeeria — self-hosted-friendly аналог
**URL:** https://papeeria.com

**Что умеет:**
- Двухпанельный редактор, похожий на~Overleaf.
- **Бесплатные приватные проекты** (редкость на~рынке).
- Импорт/экспорт из~Overleaf.
- Поддержка XeLaTeX, LuaLaTeX, Plain TeX, biber.
- Плагины: Asymptote, dot/graphviz.
- Свой Git-сервер для~проектов.

**Плюсы:** бесплатные приватные проекты, более гибкая политика хранения, есть offline-режим.
**Минусы:** меньше шаблонов в~галерее, меньше фич, чем в~Overleaf Pro.

**Резюме:** хороший выбор, если нужен Overleaf-подобный UX, но~проекты должны быть приватными и~бесплатными.

### 1.3. CoCalc — для~научных вычислений
**URL:** https://cocalc.com

**Что умеет:**
- LaTeX-редактор + Jupyter + SageMath + R-консоль в~одном окне.
- **Side-by-side PDF** с~автоперезагрузкой.
- Поддержка `knitr`, `Sweave`, PythonTeX, RMarkdown.
- Совместная работа с~chat и~whiteboard.
- Self-hosted версия (для~университетов).
- Импорт .tex из~GitHub.

**Плюсы:** научный workflow (LaTeX + данные + расчёты в~одном месте), хорош для~технических отчётов с~графиками.
**Минусы:** дорого (от~\$14/мес), интерфейс перегружен, не~так~удобен для~«чистого» LaTeX, как~Overleaf.

**Резюме:** выбирай, если делаешь отчёты с~расчётами на~Python/R/Julia и~нужна live-среда.

### 1.4. Authorea — для~научных статей
**URL:** https://www.authorea.com

**Что умеет:**
- WYSIWYG-редактор статей (как~Google Docs), но~с~LaTeX-движком под~капотом.
- Drag-and-drop вставка формул, таблиц, рисунков.
- **Шаблоны журналов** с~предзаполненными стилями.
- Совместная работа с~track changes.
- Экспорт в~LaTeX, PDF, DOCX.

**Плюсы:** не~надо знать LaTeX вообще; идеален для~соавторов-гуманитариев.
**Минусы:** ограниченная кастомизация, дорого (\$\$ для~команд), меньше контроля над~итоговым .tex.

**Резюме:** если заказчик хочет писать текст, как~в~Word, но~получать LaTeX-PDF.

### 1.5. TeXpen — минималистичный
**URL:** https://texpen.app
Простой онлайн-редактор без~collaboration. Полезен для~быстрых правок.

## 2. Десктопные IDE (полноценные редакторы)

### 2.1. TeXstudio — мой выбор для~десктопа
**URL:** https://texstudio.org
**Платформы:** Windows, macOS, Linux.

**Что умеет:**
- Подсветка синтаксиса, автодополнение команд и~ссылок.
- Структура документа (outline) в~боковой панели.
- Встроенный просмотр PDF (с~synctex — клик в~PDF → курсор в~.tex).
- **Мастера вставки:** таблиц (booktabs, siunitx, tabularx, longtable), рисунков, формул, библиографии, перекрёстных ссылок.
- **Готовые сниппеты** (auto-completion) — набираешь `\tab` и~получаешь шаблон таблицы.
- Профили сборки: pdfLaTeX/XeLaTeX/LuaLaTeX/latexmk.
- Проверка грамматики (через LanguageTool).
- Свои .tex как~шаблоны проектов.

**Плюсы:** мощный, бесплатный, офлайн, не~зависит от~санкций.
**Минусы:** нужно устанавливать TeX Live рядом, не~такая быстрая collaboration, как~в~Overleaf.

**Резюме:** основной выбор для~десктопа в~РФ. Можно сохранять свои шаблоны через `File → New from template` или `Tools → Templates`.

### 2.2. TeXmaker — проще TeXstudio
**URL:** https://www.xm1math.net/texmaker
**Что умеет:** почти всё то~же, что TeXstudio (TeXstudio форк TeXmaker'а). Интерфейс легче, но~меньше фич.
**Плюсы:** лёгкий, быстрый.
**Минусы:** меньше мастеров и~сниппетов.

### 2.3. VS Code + расширение LaTeX Workshop
**URL:** https://code.visualstudio.com + расширение `James-Yu.latex-workshop`
**Что умеет:**
- Всё богатство VS Code: Git, отладка, терминал, multi-cursor.
- LaTeX Workshop добавляет: автокомпиляцию, synctex, code folding, форму-просмотрщик, IntelliSense по~командам.
- **Сниппеты** — свои шаблоны блоков кода.
- Поддержка различных движков (pdfLaTeX/XeLaTeX/LuaLaTeX/bibtex/biber).
- Recipes — цепочки компиляции (latex → bibtex → latex ×2).

**Плюсы:** знакомый редактор, отличная интеграция с~Git, терминалом, AI-помощниками (Copilot, Continue).
**Минусы:** не~специализирован — некоторые фичи TeXstudio нужно собирать руками.

**Резюме:** выбирай, если уже работаешь в~VS Code и~хочешь единое окружение.

### 2.4. Sublime Text + LaTeXTools
**URL:** https://www.sublimetext.com
Быстрый редактор для~опытных. Плагин `LaTeXTools` добавляет сборку и~просмотр. Меньше визуальной помощи, но~скорость работы выше.

### 2.5. Vim/Neovim + vimtex
Плагин `vimtex` даёт полноценный LaTeX-режим: компиляция, просмотр, перекрёстные ссылки, fold, motion. Для~фанатов Vim — лучший опыт.

### 2.6. Emacs + AUCTeX + RefTeX
Классика. AUCTeX — превосходная поддержка LaTeX в~Emacs. RefTeX — менеджер ссылок и~библиографии. Органический режим Org-mode + LaTeX-экспорт — отличный путь для~длинных документов.

## 3. WYSIWYG-редакторы (без знания LaTeX)

### 3.1. LyX — самый известный «LaTeX без LaTeX»
**URL:** https://www.lyx.org
**Платформы:** Windows, macOS, Linux.

**Что умеет:**
- WYSIWYG-редактор, но~с~LaTeX-движком под~капотом.
- Вставка формул, таблиц, рисунков через графический интерфейс.
- Структура документа видна как~outline.
- **Шаблоны классов** — выбираешь класс (article, book, beamer, KOMA-Script, IEEEtran), LyX подгружает пресет.
- Экспорт в~чистый LaTeX, PDF, DOCX, HTML.
- Импорт LaTeX (LyX покажет документ «как~будто он~WYSIWYG»).
- Можно вставлять raw LaTeX-блоки, когда WYSIWYG не~справляется.

**Подход к~шаблонам:** LyX хранит шаблоны в~`~/.lyx/templates`. Ты создаёшь `.lyx` файл, оформляешь стили, секции, заголовки, преамбулу — и~сохраняешь как~template. При~создании нового документа можно выбрать этот шаблон.

**Плюсы:** не~надо знать LaTeX для~рутинных вещей; можно «приоткрыть капот» и~вставить LaTeX-код; бесплатный, офлайн, без~санкций.
**Минусы:** не~всё WYSIWYG: тонкая настройка всё равно требует LaTeX; иногда кривоватый рендеринг формул; «не~настоящий» LaTeX — часть LaTeX-мастеров считает LyX «костылём».

**Резюме:** для~шаблонов, которые будут наполнять люди без~LaTeX-компетенции, LyX — лучший выбор.

### 3.2. TeXmacs — структурный редактор
**URL:** https://www.texmacs.org
**Платформы:** Linux, macOS, Windows (неофициально).

**Что умеет:**
- WYSIWYG-редактор с~TeX-подобной типографикой.
- Встроенный CAS (система компьютерной алгебры): Maxima, Axiom, Mathematica-интерфейс.
- Расширяемые стили документов — свои «секции», «окружения» через Scheme.
- Экспорт в~LaTeX, PDF, HTML, MathML.

**Плюсы:** для~математиков и~физиков — настоящий рай; встроенные расчёты.
**Минусы:** сложный для~освоения, не~такой популярный, как~LyX, меньше шаблонов.

**Резюме:** для~чисто научных документов с~формулами и~расчётами.

### 3.3. Scientific Word / Scientific WorkPlace
**URL:** https://www.mackichan.com
**Платформы:** Windows.

**Что умеет:** WYSIWYG для~LaTeX с~встроенным Maple/Mathematica.
**Плюсы:** очень дружелюбный для~учёных-гуманитариев.
**Минусы:** платный (\$~500), только Windows, нишевая аудитория.

## 4. Конструкторы таблиц (отдельный подкласс UI)

### 4.1. Tables Generator
**URL:** https://www.tablesgenerator.com
**Что умеет:** визуальный конструктор `tabular`, `tabularx`, `longtable`, `booktabs`. Drag-and-drop ячейки, выбор стилей (`\toprule`, `\midrule`, `\bottomrule`), цвета строк/столбцов.
**Плюсы:** мгновенно генерирует готовый LaTeX-код; можно копировать в~свой шаблон; есть импорт из~CSV/Excel.
**Минусы:** не~делает весь документ, только таблицы.
**Резюме:** для~шаблона с~таблицами — добавляешь сгенерированный код в~\texttt{report.tex} через `\input{tables/quarterly.tex}`.

### 4.2. Excel2LaTeX (плагин Excel)
**Что умеет:** выделяешь таблицу в~Excel, экспортируешь в~LaTeX с~настройками стилей.
**Плюсы:** знакомый Excel, можно хранить данные в~Excel, а~LaTeX-таблицу генерировать по~кнопке.
**Минусы:** Excel-only.

### 4.3. Pandas / DataFrame → LaTeX
```python
import pandas as pd
df = pd.DataFrame({'A': [1, 2], 'B': [3, 4]})
print(df.to_latex(index=False, column_format='lrr',
                  caption='Test', label='tab:test',
                  position='htbp'))
```
Встраивается в~Python-конвейер (см.~LaTex_02.txt раздел 7).

### 4.4. booktabs.de
Германский сайт с~генератором booktabs-таблиц. Простой и~быстрый.

## 5. Конструкторы отчётов из данных (no-code/low-code)

### 5.1. Quarto — современный стандарт
**URL:** https://quarto.org
**Что умеет:**
- Документ описывается в~Markdown с~чанками кода (Python, R, Julia, Observable JS).
- На~выходе — PDF (через LaTeX), HTML, DOCX, презентация, сайт, книга.
- **Шаблоны** — формат (PDF/HTML/DOCX) + шаблон (article, beamer, IEEE, ACM, Springer, и~свои).
- Параметры YAML: title, author, date, theme.
- **Файлы шаблонов** в~`_extensions/` — можно положить свой .tex и~использовать как~format.
- Pandoc под~капотом + Jinja2 для~шаблонизации.

**Пример `report.qmd`:**
```yaml
---
title: "Анализ продаж Q2"
author: "Иванов И.И."
format:
  pdf:
    pdf-engine: xelatex
    template: mycompany-template.tex
    keep-tex: true
---
```
```markdown
## Сводка по регионам
{{python}}
import pandas as pd
df = pd.read_csv("sales.csv")
print(df.to_markdown(index=False))
{{endpython}}
```

**Плюсы:** современный, мультиязычный, мощный, подходит для~data science; шаблоны легко переносить.
**Минусы:** требует знания Markdown и~базово YAML; шаблоны .tex для~формата PDF всё~равно нужно писать.

**Резюме:** если ты делаешь data-driven отчёты — Quarto лучший выбор на~2026~год.

### 5.2. R Markdown
**URL:** https://rmarkdown.rstudio.com
R-эксклюзив, но~мощный. Если данные в~R — идеален. Иначе — Quarto.

### 5.3. Jupyter Notebook + nbconvert
```bash
jupyter nbconvert --to pdf report.ipynb
```
Шаблон `pdf.tplx` от~Jupyter можно кастомизировать, но~API громоздкое.

### 5.4. Streamlit / Dash — отчёты-приложения
**Streamlit** + `streamlit-pdf-viewer` или экспорт через `weasyprint` — интерактивный отчёт с~кнопкой «Скачать PDF». Не~чистый LaTeX, но~часто проще.

### 5.5. Observable / Observable Plot
JavaScript-блокноты с~генерацией PDF через headless Chrome. Для~визуально-насыщенных отчётов.

## 6. Современные альтернативы LaTeX (не LaTeX, но~с тем же UX)

### 6.1. Typst — главный конкурент LaTeX в~2026
**URL:** https://typst.app

**Что это:** новый язык разметки, вдохновлённый LaTeX, но~с~чистым синтаксисом, компилятором на~Rust и~онлайн-редактором.

**Сравнение:**

| | LaTeX | Typst |
|---|---|---|
| Скорость компиляции | 0.5–5~с | 0.1–0.5~с (в~10–20~раз быстрее) |
| Синтаксис | `\section{...}` | `= ...` (Markdown-like) |
| Кривая обучения | крутая | пологая |
| Онлайн-редактор | Overleaf (платный) | Typst.app (бесплатный) |
| Шаблоны | 6000+ | 1000+, растёт |
| Расширения | CTAN (тысячи) | `#let` функции, пакеты через `import` |
| Экосистема | мощная, старая | молодая, растёт |
| Кириллица | работает (XeLaTeX) | работает из~коробки |
| Таблицы | пакеты (booktabs, tabularx) | встроенные (grid, table) |
| Формулы | мощно, но~сложно | проще, но~менее гибко |
| Графика | TikZ (сложно) | CeTZ (проще) |

**UI:**
- Онлайн-редактор typst.app — WYSIWYG-ish, real-time preview, шаблоны, import .tex, экспорт PDF.
- Десктоп: VS Code плагин `Typst LSP`, Neovim `typst.vim`, emacs typst-mode.
- Self-hosted компилятор: бинарник на~Rust, лёгкий (~30~МБ, без~GB TeX~Live).

**Плюсы:** скорость, простой синтаксис, приятный онлайн-редактор, шаблоны.
**Минусы:** меньше пакетов, не~все тонкости LaTeX реализованы, для~публикации в~IEEE/ACM пока нужны обходные пути.

**Резюме:** если начинаешь новый проект с~нуля в~2026 — рассмотри Typst. Если шаблон должен работать в~академической экосистеме — LaTeX.

### 6.2. Pandoc + пользовательский шаблон
**URL:** https://pandoc.org
**Что это:** универсальный конвертер документов. Markdown → PDF через LaTeX.
**Шаблоны:** `pandoc -D latex` показывает дефолтный; `pandoc --template=mytemplate.tex report.md -o report.pdf` использует свой.
**Плюсы:** разделение «текст в~Markdown» и~«оформление в~шаблоне». Можно править шаблон один раз, потом менять только .md.
**Минусы:** не~все возможности LaTeX доступны через Pandoc-шаблон.

### 6.3. AsciiDoc + Asciidoctor PDF
Markdown-альтернатива с~более богатым синтаксисом. PDF через Prawn (Ruby) — без~LaTeX. Менее гибкая типографика, но~проще.

| Typst | Web + CLI | Free | 1000+ | ✅ | ✅ (бинарник) | ✅ | Новые проекты |

## 8. Рекомендации по~выбору

### 8.1. Если ты — единственный автор отчётов в~компании
- **Десктоп:** TeXstudio или VS Code + LaTeX Workshop.
- **Шаблоны:** создаёшь в~каталоге `templates/`, используешь через `\input{}` или меню.
- **Данные:** Jinja2 + Python-конвейер (LaTex_02.txt раздел 7).

### 8.2. Если шаблон набивают другие люди (аналитики, менеджеры)
- **Слабый навык LaTeX:** LyX (десктоп) или Authorea (веб).
- **Средний навык:** TeXstudio + готовый шаблон, в~котором правятся только данные через `\newcommand`.
- **Сильный навык:** VS Code + Git, шаблон в~общем репозитории.

### 8.3. Если нужно делать отчёты из~данных регулярно
- **Quarto** — лучший выбор на~2026~год.
- **Pandoc + шаблон** — если Quarto избыточен.
- **Jinja2 + Python** — если нужна максимальная гибкость.

### 8.4. Если это научная статья для~журнала
- **Overleaf** — журнал IEEE/ACM/Springer/Elsevier почти наверняка имеет официальный шаблон в~Overleaf Gallery. Открываешь → меняешь данные → отправляешь в~журнал. Стандарт академии.

### 8.5. Если нужна коллаборация в~реальном времени
- **Overleaf** — золотой стандарт.
- **Papeeria** — если Overleaf недоступен.
- **ShareLaTeX** — мёртв, вошёл в~Overleaf.

### 8.6. Если начинаешь новый проект и~не~привязан к~LaTeX
- **Typst** — рассмотри серьёзно. В~2026 это зрелый инструмент с~большой экосистемой. Если через год окажется, что не~хватает гибкости LaTeX — переход возможен, но~с~переписыванием шаблонов.

## 9. Как собрать собственный шаблон в~каждом инструменте

### 9.1. В~Overleaf
1. Создать проект `mycompany-template`.
2. Оформить структуру (титул, стили, пакеты, переменные через `\newcommand`).
3. Сделать ссылку публичной: Share → «Anyone with the link can edit a copy».
4. Все новые проекты начинаются с~этой ссылки.

### 9.2. В~TeXstudio
1. `Tools → Templates → Save current document as template`.
2. Шаблон сохраняется в~`~/.config/texstudio/templates/`.
3. `File → New from template` — выбираешь свой шаблон.

### 9.3. В~VS Code
1. Создаёшь каталог `templates/`.
2. `File → New File from Template` (плагин File Templates).
3. Или просто копируешь `templates/my-report.tex` в~новый проект.

### 9.4. В~LyX
1. `File → Templates → Save as Template`.
2. Шаблон в~`~/.lyx/templates/`.
3. `File → New from Template` — выбираешь свой.

### 9.5. В~Quarto
1. Создаёшь каталог `_extensions/mycompany/`.
2. В~нём `template.qmd` + `_metadata.yml` + `template.tex` (если нужен PDF).
3. В~новом проекте указываешь:
   ```yaml
   format:
     pdf:
       template: mycompany
   ```

### 9.6. В~Typst
1. Создаёшь `template.typ` с~функцией `project()`.
2. В~новом файле: `#import "template.typ": project; #show: project`.
3. Шаблон можно опубликовать через `typst init` и~`typst login` в~официальном реестре.

## 10. Связь с~предыдущими файлами

- **LaTex_02.txt** — общая теория (движки, пакеты, конвейер).
- **LaTex_03.txt** — заполненный шаблон отчёта, который можно использовать как~стартовую точку в~любом из~перечисленных UI.
- **LaTex_04.txt** (этот файл) — выбор UI-оболочки для~визуальной работы с~шаблонами.

**Практический workflow для~компании:**

1. Сделать «эталонный» шаблон в~\texttt{report.tex} (как~в~LaTex_03.txt) — преамбула, переменные, стили, секции.
2. Загрузить в~TeXstudio или Overleaf как~template.
3. Для~автогенерации из~данных — обернуть в~Jinja2-шаблон (см.~LaTex_02.txt раздел 3.3) или использовать Quarto.
4. Для~дизайнерских правок (другая шапка, логотип, шрифт) — править преамбулу эталона. Изменения применятся ко~всем производным отчётам, потому что они `\input{}`-ят преамбулу.

## 11. Что НЕ~является UI-оболочкой, но~часто путают

- **MiKTeX** — это не~редактор, а~дистрибутив TeX для~Windows (сборщик). Устанавливается рядом с~TeXstudio.
- **TeX Live** — то~же для~Linux/macOS.
- **Ghostscript** — просмотрщик/конвертер PostScript/PDF, не~LaTeX.
- **pandoc** — конвертер документов, не~редактор, но~может рендерить LaTeX в~PDF.
- **TeX Live Utility** (macOS) — GUI для~обновления пакетов TeX Live.

## 12. Тренды на~2026

1. **Typst растёт.** Всё больше журналов и~университетов публикуют Typst-шаблоны. Если ты начинаешь новый проект — рассмотри.
2. **Overleaf усиливает AI-фичи** (встроенный GPT для~LaTeX, автодополнение формул).
3. **VS Code** остаётся самым популярным выбором среди~молодых LaTeX-авторов.
4. **Quarto** становится стандартом в~data science (R/Python/Julia).
5. **LyX 2.4** (2024) получил обновлённый UI и~улучшенную работу с~LuaLaTeX.
6. **Obsidian + Pandoc Plugin** — для~тех, кто ведёт заметки в~Markdown и~хочет экспортировать в~LaTeX-PDF.

## 13. Итог

UI-оболочка — это не~просто «ещё один редактор», а~инструмент под~конкретный workflow:

- **«Мне нужны шаблоны для~команды»** → Overleaf (если есть интернет и~санкции не~проблема) или TeXstudio + templates (если offline-режим).
- **«Мне нужно делать отчёты из~данных регулярно»** → Quarto.
- **«Я вообще не~хочу знать LaTeX»** → LyX (desktop) или Authorea (web).
- **«Хочу WYSIWYG, но~LaTeX под~капотом, и~бесплатно»** → LyX.
- **«Я один, пишу в~своё удовольствие, и~мне нравится LaTeX»** → TeXstudio или VS Code + LaTeX Workshop.
- **«Хочу самый быстрый современный инструмент»** → Typst.

Самый практичный совет: **не~привязывайся к~одному UI**. Шаблон — это `.tex` файл. Он~откроется в~любом редакторе. Меняй UI под~задачу: Overleaf для~совместной работы над~статьёй, TeXstudio для~локальных отчётов, Quarto для~data-driven документов, LyX для~не-технических соавторов.
