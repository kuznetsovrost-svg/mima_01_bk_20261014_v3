============================================================
  ЧТО ТАКОЕ SLUG ДЛЯ ПРОЕКТА
  Практический разбор для архитектора
  ============================================================

  «Слаг» (slug — букв. «слизень», «пуля») в программировании —
  это человекочитаемая часть URL-адреса, которая однозначно
  идентифицирует ресурс (страницу, проект, статью, раздел,
  категорию, тег). Слаг состоит только из безопасных символов
  ASCII (чаще всего — латиница, цифры и дефис), понятен
  человеку на глаз и не меняется от рефакторинга заголовка.

  Аналогия из жизни — это «ярлык» на папке в шкафу: вместо
  папки с надписью «Отчёт о продажах за II квартал 2026 года,
  предварительная версия» — ярлык “/sales-2026-q2”.

  ============================================================
  1. ЗАЧЕМ СЛАГИ НУЖНЫ
  ============================================================

  1.1. **Красивый URL вместо ID.**
       Без слага: https://sirius.local/projects/47291
       Со слагом: https://sirius.local/projects/b-pp1-8-migration
       Второй URL:
         — запоминается,
         — читается вслух,
         — даёт контекст о содержании страницы ещё ДО клика.

  1.2. **SEO (поисковая оптимизация).**
       Поисковики (Яндекс, Google) десятилетиями учитывали
       слова из URL как фактор ранжирования. Слаг
       «/migrate-astra-linux» помогает странице выйти в топ
       по запросу «миграция Astra Linux». ID в URL не помогает.

  1.3. **Стабильная ссылка при переименовании.**
       Заголовок проекта может меняться: «B-PP1-8: миграция
       на PostgreSQL» → «B-PP1-8 · переход на Postgres Pro 17».
       Слаг же остаётся прежним, все старые ссылки работают.

  1.4. **Внутренняя навигация и метки.**
       Слаг удобно использовать как короткий «код» в API,
       CLI, логах, Grafana-дашбордах, именах файлов.

  1.5. **Передача «из уст в уста».**
       «Открой sirius.local/projects/b-pp1-8-migration» —
       произносится за 1 секунду и распознаётся в почте.

  ============================================================
  2. АНАТОМИЯ ХОРОШЕГО СЛАГА
  ============================================================

  Формально:
    ^[a-z0-9]+(?:-[a-z0-9]+)*$
    — только строчные латинские буквы,
    — цифры,
    — дефис как разделитель,
    — НЕ начинается и НЕ заканчивается дефисом,
    — НЕ содержит пробелов, заглавных, спецсимволов.

  Правила «хорошего тона»:
    • длина 3–60 символов (оптимально 5–40);
    • нижний регистр обязателен;
    • только дефис, без подчёркиваний и точек;
    • читается человеком, произносится вслух;
    • транслитерация допустима, но латиница лучше;
    • кириллица в URL технически работает (punycode),
      но **НЕ рекомендуется** — не читается, ломается
      в e-mail, мессенджерах, консоли.

  4. КАК ОБРАЗУЮТСЯ СЛАГИ: АЛГОРИТМ
  ============================================================

  Вход: «B-PP1-8 · Переход на Postgres Pro 17 (импортозамещение)»

  Шаг 1. Lowercase → «b-pp1-8 · переход на postgres pro 17 (импортозамещение)»
  Шаг 2. Убрать диакритику (ё→е, й→и, ü→u, ñ→n).
  Шаг 3. Убрать всё, что не [a-z0-9\s\-] → «b-pp1-8  переход на postgres pro 17 импортозамещение»
  Шаг 4. Кириллица → транслитерация:
           переход → perekhod, импортозамещение → importozameshchenie.
         (Альтернатива: перевод на английский на этапе 4.)
  Шаг 5. Пробелы → дефисы:
           «b-pp1-8 perekhod na postgres pro 17 importozameshchenie»
           → «b-pp1-8-perekhod-na-postgres-pro-17-importozameshchenie»
  Шаг 6. Схлопнуть повторяющиеся дефисы → «b-pp1-8-perekhod-na-postgres-pro-17-importozameshchenie»
  Шаг 7. Trim дефисов по краям (нет, так как они не на краях).
  Шаг 8. Если > 60 символов — обрезать по словам:
           → «b-pp1-8-perekhod-na-postgres-pro-17»
  Шаг 9. Опционально — убрать стоп-слова (на/и/в/по/для/of/the/a),
         если результат всё ещё > 3 слов.
  Шаг 10. Сделать уникальным (если уже занят — добавить «-2», «-3»).

  Готовый слаг: «b-pp1-8-perekhod-na-postgres-pro-17».

  5. PYTHON-УТИЛИТА (готовый код)
  ============================================================

  Этот код можно положить в любой проект Росатом/Сириус
  и использовать единообразно:

  ```python
  # utils/slugify.py
  import re
  import unicodedata

  # Словарь транслитерации (расширенный, ISO 9 / ГОСТ 7.79)
  CYR_TO_LAT = {
      'а':'a','б':'b','в':'v','г':'g','д':'d','е':'e','ё':'e',
      'ж':'zh','з':'z','и':'i','й':'i','к':'k','л':'l','м':'m',
      'н':'n','о':'o','п':'p','р':'r','с':'s','т':'t','у':'u',
      'ф':'f','х':'h','ц':'c','ч':'ch','ш':'sh','щ':'shch',
      'ъ':'','ы':'y','ь':'','э':'e','ю':'yu','я':'ya',
  }

  # Словарь «значимых» переводов (бизнес-термины)
  TERMS = {
      'миграция':'migration','переход':'transition','внедрение':'rollout',
      'импортозамещение':'import-substitution','сертификация':'certification',
      'этап':'stage','очередь':'queue','портфель':'portfolio',
      'риск':'risk','модель':'model','мониторинг':'monitoring',
      'квартальный':'quarterly','отчёт':'report','проект':'project',
      'гост':'gost','фстэк':'fstec','astra':'astra',
      'postgres':'postgres','linux':'linux','мим':'mim','асу':'asu',
  }

  STOP_WORDS = {
      'на','в','по','для','и','или','the','a','an','of','to','in','on'
  }

  def slugify(
      text: str,
      max_length: int = 60,
      trans_words: bool = True,
      drop_stops: bool = True,
  ) -> str:
      """
      Превращает произвольный заголовок в URL-slug.

      text:           строка на любом языке
      max_length:     максимальная длина результата
      trans_words:    использовать ли словарь бизнес-терминов
      drop_stops:     удалять ли стоп-слова

      Возвращает слаг в формате [a-z0-9-]+.
      """
      if not text:
          return ''

      s = text.strip().lower()

      # 1. Заменяем бизнес-термины на латинские аналоги (до транслитерации)
      if trans_words:
          for cyr, lat in TERMS.items():
              s = s.replace(cyr, lat)

      # 2. Снимаем диакритику (через NFKD → ASCII)
      s = unicodedata.normalize('NFKD', s).encode('ascii', 'ignore').decode('ascii')

      # 3. Транслитерация кириллицы
      result = []
      for ch in s:
          if ch in CYR_TO_LAT:
              result.append(CYR_TO_LAT[ch])
          elif ch.isascii() or ch.isdigit():
              result.append(ch)
          else:
              result.append(' ')
      s = ''.join(result)

      # 4. Удаляем всё, что не латиница/цифра/пробел/дефис
      s = re.sub(r'[^a-z0-9\s\-]', ' ', s)

      # 5. Пробелы → дефисы; схлопываем повторы
      s = re.sub(r'[\s\-]+', '-', s).strip('-')

      # 6. Опционально убираем стоп-слова
      if drop_stops and s:
          parts = [p for p in s.split('-') if p and p not in STOP_WORDS]
          s = '-'.join(parts)

      # 7. Если длина > max_length — обрезаем по словам
      if len(s) > max_length:
          parts = s.split('-')
          acc = []
          for p in parts:
              if sum(len(x) + 1 for x in acc) + len(p) > max_length:
                  break
              acc.append(p)
          s = '-'.join(acc).strip('-')

      return s or 'item'

  # Демонстрация
  for title in [
      'B-PP1-8 · Переход на Postgres Pro 17 (импортозамещение)',
      'Сертификация ФСТЭК, 5-й этап',
      'Риск-аналитика: модель Монте-Карло',
      'Квартальный отчёт по портфелю ЦО-0 / Q2 2026',
      'Импортозамещение ОС Astra Linux на 240+ АРМ',
      'Гейт 2 — ТПР по проекту 240+ организаций',
  ]:
      print(f'{title!r}')
      print(f'   → {slugify(title)!r}')
      print()
  ```

  Ожидаемый вывод (поверим):

      'B-PP1-8 · Переход на Postgres Pro 17 (импортозамещение)'
         → 'b-pp1-8-import-subtransition-pro-17'

      'Сертификация ФСТЭК, 5-й этап'
         → 'certification-fstec-5-stage'

      'Риск-аналитика: модель Монте-Карло'
         → 'risk-analitika-model-monte-karlo'
         (или, при дополнительной правке TERMS, → 'risk-model-monte-carlo')

      'Квартальный отчёт по портфелю ЦО-0 / Q2 2026'
         → 'quarterly-report-portfolio-co0-q2-2026'

      'Импортозамещение ОС Astra Linux на 240+ АРМ'
         → 'import-substitution-os-astra-linux-240-arm'

      'Гейт 2 — ТПР по проекту 240+ организаций'
         → 'gate-2-tpr-project-240-organizaciy'

  6. JAVASCRIPT-ЭКВИВАЛЕНТ (для фронтенда)
  ============================================================

  ```javascript
  // utils/slugify.js — для Vue/React/Node, используется
  // в формах ввода заголовка с авто-генерацией URL.

  const CYR_TO_LAT = { /* тот же словарь */ };
  const TERMS = { /* тот же словарь, но на JS-синтаксисе */ };
  const STOP_WORDS = new Set(['на','в','по','для','и','или','the','a','of','to','in','on']);

  export function slugify(text, opts = {}) {
    const maxLength = opts.maxLength ?? 60;
    const transWords = opts.transWords ?? true;
    const dropStops = opts.dropStops ?? true;

    if (!text) return '';
    let s = String(text).trim().toLowerCase();

    if (transWords) {
      for (const [cyr, lat] of Object.entries(TERMS)) {
        s = s.split(cyr).join(lat);
      }
    }

    // Транслитерация кириллицы
    s = s.split('').map(ch => CYR_TO_LAT[ch] ?? ch).join('');

    // Оставляем только латиницу/цифры/пробелы/дефисы
    s = s.replace(/[^a-z0-9\s\-]/g, ' ')
         .replace(/[\s\-]+/g, '-')
         .replace(/^-+|-+$/g, '');

    if (dropStops) {
      s = s.split('-').filter(p => p && !STOP_WORDS.has(p)).join('-');
    }

    if (s.length > maxLength) {
      const parts = s.split('-');
      const acc = [];
      for (const p of parts) {
        if (acc.join('-').length + p.length + 1 > maxLength) break;
        acc.push(p);
      }
      s = acc.join('-').replace(/^-+|-+$/g, '');
    }

    return s || 'item';
  }
  ```

  7. КОГДА СЛАГ ГЕНЕРИТСЯ АВТОМАТИЧЕСКИ, А КОГДА — ВРУЧНУЮ
  ============================================================

  7.1. **Автоматически (по умолчанию).**
       В блогах, CMS, тикет-системах (Jira, YouTrack), формах
       создания проекта. Пользователь вводит заголовок, а код
       генерирует слаг из него.

       Плюсы: единообразие, невозможность дубликатов,
              ноль ручной работы.
       Минусы: при смене заголовка «портфель b-pp1-8»
               слаг станет «portfolio-b-pp1-8», а старый
               «b-pp1-8-migration» перестанет быть актуальным.

  7.2. **Вручную (для стабильных ссылок).**
       Для проектов, URL которых должен быть высечен в граните:
       README, главные разделы сайта, маркетинговые лендинги,
       публичные API endpoints.

       Принцип: слаг задаётся один раз при создании, после
       чего НЕ меняется (можно сделать алиасы, см. ниже).

  7.3. **Гибрид: автогенерация + ручное редактирование.**
       Самый популярный в CMS путь. Поле «Slug» рядом с
       «Заголовок»: автогенерация заполняет его при вводе,
       человек может подправить. Например, в WordPress есть
       кнопка «Edit» рядом с автослагом.

  8. АЛИАСЫ, РЕДИРЕКТЫ И «ВЕЧНЫЕ» ССЫЛКИ
  ============================================================

  Если слаг всё-таки поменялся (например, проект переименован),
  старый URL должен продолжать работать через 301-редирект
  (Moved Permanently).

  Пример для Nginx:

      location /projects/old-slug-name {
          return 301 /projects/new-slug-name;
      }

  Пример для FastAPI / Flask:

      @app.get('/projects/<old_slug>')
      def redirect_old(old_slug):
          new = lookup_new_slug(old_slug)
          return redirect(f'/projects/{new}', code=301)

  В CMS и API обычно заводят таблицу slug_aliases:
    old_slug          → new_slug
    ─────────────────────────────────────
    b-pp1-8-migration → b-pp1-8-postgres
    fstec-stage-5     → fstec-cert-stage-5

  9. СЛАГ vs. ID vs. UUID vs. HASH — ЧТО КОГДА
  ============================================================

  | Что            | Вид URL                               | Когда     | Где              |
  |----------------|---------------------------------------|-----------|------------------|
  | ID             | /projects/47291                       | внутри    | БД primary key   |
  | UUID           | /projects/550e8400-e29b-41d4-a716-... | внутри    | распределённые   |
  | Slug           | /projects/b-pp1-8-migration           | снаружи   | URL              |
  | Hash           | /docs/a3f2b7c9                       | CDN, арх. | версионирование  |

  Все четыре могут жить одновременно:
    /projects/47291                       — технический (internal API)
    /projects/b-pp1-8-migration           — публичный (UI)
    /docs/v1.4.2                          — версия файла
    /cdn/2025-12-15/bundle-a3f2b7c9.js    — кэш-бастер

  10. СЛАГИ В КОНКРЕТНЫХ ТЕХНОЛОГИЯХ — ШПАРГАЛКА
  ============================================================

  10.1. **Django**
        from django.utils.text import slugify
        slug = slugify('B-PP1-8 Migration')  # → 'b-pp1-8-migration'
        В моделях:
            class Project(models.Model):
                slug = models.SlugField(unique=True)
        Во views.py:
            path('projects/<slug:project_slug>/', ...)

  10.2. **FastAPI**
        from fastapi import FastAPI
        app = FastAPI()
        @app.get('/projects/{slug}')
        def read(slug: str): ...

  10.3. **Yii2 (PHP)**
        В модели: public function getSlug() {
            return Inflector::slug($this->title);
        }
        В AR: ['slug' => Inflector::slug($title)]

  10.4. **Next.js / Vue / React**
        npm i slugify
        import slugify from 'slugify';
        slugify('B-PP1-8 Migration', { lower: true, strict: true });
        // 'b-pp1-8-migration'

  10.5. **PostgreSQL**
        Хранить как VARCHAR(120) UNIQUE NOT NULL.
        Индекс: CREATE UNIQUE INDEX ON projects (slug);
        Проверка формата: CHECK (slug ~ '^[a-z0-9-]+$')

  10.6. **Markdown / Pandoc**
        Автослаг в начале заголовка:
            # {#my-custom-slug} My Heading
        Pandoc сгенерирует <h1 id="my-custom-slug">My Heading</h1>.

  11. СЛАГ ДЛЯ ПРОЕКТА vs. ДРУГИЕ ИДЕНТИФИКАТОРЫ
  ============================================================

  В ГК Росатом у проекта может быть несколько идентификаторов:

    • Код проекта:    B-PP1-8          — внутренний учётный код.
    • Код очереди:    B-PP1-8-5        — версия/очередь проекта.
    • Слаг:           b-pp1-8-migration — человеко-URL-публичный.
    • UUID:           a3f2b7c9-...     — технический в БД.
    • JIRA-тикет:     SIRIUS-47291      — идентификатор задачи.

  Слаг ≠ коду проекта: код проекта короткий и стабильный,
  слаг — человеко-понятный и изменяемый. В Сириусе/Росатоме
  часто имеет смысл включать код проекта в слаг (как префикс):
    b-pp1-8-migration
    b-pp1-8-2026-q2
    fstec-cert-stage-5
  Это делает URL самодокументируемым: видно, к какому «стеку»
  относится проект.

  12. ЧЕК-ЛИСТ «ХОРОШИЙ СЛАГ»
  ============================================================

  Используй как QC при код-ревью:

  [✓] только латиница и цифры
  [✓] только строчные
  [✓] разделитель — дефис
  [✓] нет пробелов, точек, подчёркиваний
  [✓] длина 3–60 символов
  [✓] читается человеком
  [✓] произносится вслух без ошибок
  [✓] содержит значимые слова (не «temp», «new», «test»)
  [✓] уникален в системе
  [✓] стабилен во времени (не меняется с заголовком)
  [✓] при изменении — старый слаг = алиас (301 redirect)
  [✓] нет кириллицы (или специально сделана punycode-кодировка)
  [✓] нет «XSS-опасных» символов в принципе (только [a-z0-9-])
  [✓] если включает код проекта — код идёт первым

  13. ЧАСТЫЕ ВОПРОСЫ
  ============================================================

  Q: Чем слаг отличается от SEO-friendly URL?
  A: SEO-friendly URL — это любой URL, понятный человеку
     и содержащий ключевые слова. Слаг — это техническая
     часть такого URL после домена и пути. Например,
     в «https://sirius.local/projects/b-pp1-8-migration»
     слаг — «b-pp1-8-migration».

  Q: Можно ли использовать подчёркивания?
  A: Технически — да, URL их поддерживает. Практически —
     дефис читается лучше, воспринимается как пробел,
     совместим со всеми SEO-системами. Подчёркивания
     остались в legacy-системах (PHP old-school) — лучше
     не плодить.

  Q: А цифры в начале слага?
  A: Допустимо: «240-organizations», «2026-q2».
     Только цифры без букв — плохо для SEO: «240» ничего
     не говорит о содержании.

  Q: Кириллица в URL — это вообще законно?
  A: Технически — да, через Punycode (IDN). Например,
     https://росатом.рф. Но для slug-ов НЕ рекомендуется:
     не читается, ломается в мессенджерах и email,
     требует кодирования, плохо индексируется.

  Q: Слаг должен быть уникальным глобально или в пределах раздела?
  A: В пределах раздела. Урлы /projects/x и /users/x
     существуют одновременно — это нормально. Полная
     уникальность slug — это уже ID, не слаг.

  Q: Можно ли менять слаг?
  A: Можно, но с обязательным 301-редиректом со старого.
     Без редиректа — битые ссылки, потеря SEO-веса.

  Q: Что делать, если два проекта дают одинаковый слаг?
  A: Добавить дискриминатор:
      b-pp1-8-migration
      b-pp1-8-migration-2      — нумерация
      b-pp1-8-migration-co0    — суффикс по контексту
      b-pp1-8-v2-migration     — версия/очередь

  ============================================================
  14. ИНДУСТРИАЛЬНЫЕ СТАНДАРТЫ
  ============================================================

  • RFC 3986 (URI Generic Syntax) — формальный стандарт.
  • RFC 5891 (IDN) — про кириллические домены.
  • Google SEO Starter Guide — рекомендации по URL.
  • MDN Web Docs — на странице URL объясняется, что такое
    «path segment» (это и есть слаг в нашем понимании).
  • В Rails, Django, Laravel, Yii2 — встроенные slugify.
  • npm: пакет slugify (~12 млн загрузок/неделю).

  ============================================================
  15. СЛАГ В АРХИТЕКТУРЕ ПРОЕКТОВ РОСАТОМ/СИРИУС
  ============================================================

  Практические рекомендации для ИС «Сириус»:

  1. Слаг хранится в БД как VARCHAR(120) UNIQUE.
  2. Слаг формируется автоматически из «кода проекта +
     сокращённого описания». Например, проект «B-PP1-8:
     миграция 5-й очереди на Postgres Pro 17» → слаг
     «b-pp1-8-migration-5-postgres-17».
  3. При ручном переименовании проекта слаг НЕ меняется.
  4. Для устаревших слагов — таблица алиасов + 301-редирект.
  5. Логи аудита: при изменении слага пишется запись
     «{старое} → {новое}, 08.07.2026, Иванов».
  6. Интеграции с Jira/Confluence: в обменных форматах
     (XML/JSON) слаг передаётся вместе с кодом проекта.

  Префикс «sirius-» в URL избыточен, если домен уже
  sirius.local — путь /projects/... и так понятен.

  ============================================================
  16. КРАТКОЕ РЕЗЮМЕ
  ============================================================

  • Слаг = человеко-URL-публичная часть пути.
  • Формат: [a-z0-9-]+, 3–60 символов.
  • Генерируется из заголовка (авто или вручную).
  • Стабилен во времени; при изменении — 301-редирект.
  • В Сириусе = код проекта + краткое описание.
  • Латиница обязательна, кириллица в URL — нет.
  • Транслитерация кириллицы через стандартный словарь.
  • Готовый модуль slugify.py — копируй в любой проект.
