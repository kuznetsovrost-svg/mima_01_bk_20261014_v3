# Курс подготовки архитектора агентов для выпускника школы РФ

## 0. Главный принцип

Архитектор агентов — это инженер-архитектор на стыке Computer Science, AI и продуктовой инженерии. Это **не промптер и не ML-исследователь**. Это человек, который проектирует multi-agent оркестрацию, выбирает фреймворк, отвечает за надёжность и связывает бизнес-задачу с LLM-возможностями и инфраструктурой.

Архитектор агентов = 70% CS-инженер + 30% AI-инженер. Без глубокого CS-фундамента потолок карьеры — middle. С ним — senior/principal в течение 5–7 лет.

---

## 1. Кто такой архитектор агентов (роль и границы)

### Что делает
- Проектирует multi-agent оркестрацию: кто за что отвечает, как координируются.
- Выбирает фреймворк: LangGraph, CrewAI, AutoGen, Hermes, Temporal + LLM.
- Проектирует tool-calling, RAG, память, контекст-окно, состояние.
- Отвечает за надёжность: evals, guardrails, observability, fallback.
- Связывает бизнес-задачу ↔ LLM-возможности ↔ инфраструктуру.

### Чего НЕ делает
- Не обучает foundation models (это ML-исследователь).
- Не пишет только промпты (это prompt-инженер, нижний уровень).
- Не делает дизайн UI/UX (это продуктовый дизайнер).

### Соседние роли
- **ML Engineer** — обучает модели, строит ML-пайплайны.
- **Data Scientist** — аналитика, эксперименты, A/B-тесты.
- **Backend Engineer** — пишет API и сервисы, но без AI-специфики.
- **DevOps / Platform Engineer** — инфраструктура.
- **Prompt Engineer** — начальный уровень в AI, обычно эволюционирует в архитектора.

## 2. Школьный фундамент (до поступления)

### Обязательный минимум ЕГЭ
| Предмет | Уровень | Зачем |
|---|---|---|
| Русский | 70+ | Базовый |
| Профильная математика | 80+ | Логика, алгоритмы, ML |
| Информатика (КЕГЭ) | 85+ | Программирование, основы |
| Английский | 85+ | Документация,論文, комьюнити |

### Олимпиады (сильно помогают при поступлении)
- **Информатика:** ВсОШ, олимпиады 1 уровня (Перечня) — дают БВИ в топ-вузы.
- **Математика:** ВсОШ — прокачивает абстрактное мышление.
- **Физика** (опционально) — если планируется ML-железо / оптимизация инференса.

### Что освоить самостоятельно ДО 1 курса
1. Python — уверенно (async, типизация, тесты).
2. Git + GitHub — портфолио с 2–3 проектами.
3. Основы Linux + терминал (важно для agent runtime).
4. Базовый английский технический (читать доки, RFC, arXiv-препринты).
5. 1–2 pet-project с LLM API (Telegram-бот / CLI-помощник / RAG-поисковик).

## 4. Технические треки, обязательные к освоению (1–4 курс)

### Трек A: Computer Science фундамент
- Алгоритмы и структуры данных (LeetCode Medium → Hard).
- Операционные системы (процессы, потоки, память).
- Сети и распределённые системы (TCP/IP, REST, gRPC, очереди).
- Базы данных (реляционные + NoSQL + векторные).
- Архитектура ПО (монолит, микросервисы, event-driven).

### Трек B: Software Engineering
- Языки: Python (основной) + TypeScript (агенты в браузере) + Go (бэкенд runtime).
- Тестирование: pytest, property-based, integration, e2e.
- CI/CD: GitHub Actions, Docker, базовый Kubernetes.
- Observability: логи, метрики, трейсы (OpenTelemetry).

### Трек C: AI/ML и агенты
- LLM API: OpenAI, Anthropic, Yandex GPT, GigaChat, локальные модели.
- Prompt engineering: few-shot, chain-of-thought, structured outputs.
- Function/Tool calling — паттерны и ограничения.
- RAG: эмбеддинги, чанкование, гибридный поиск, реранкер.
- Фреймворки агентов: LangChain, LangGraph (stateful agents), CrewAI, AutoGen, Haystack.
- Memory: краткосрочная (контекст), долгосрочная (vector store, графы).
- Evals: написание тестов для LLM-систем (LLM-as-judge, golden sets).
- Fine-tuning vs prompting vs tool-use — когда что применять.
- Безопасность: prompt injection, jailbreaks, red-teaming.

### Трек D: Платформа и инфраструктура
- Docker / Docker Compose / Kubernetes (базово).
- Облака: Yandex Cloud, VK Cloud, AWS basics.
- Очереди: Kafka, RabbitMQ, NATS.
- Векторные БД: Qdrant, Milvus, pgvector, Chroma.
- Хранилища: S3-совместимые, кэши (Redis).

### Трек E: Продукт и домен
- Основы продуктового мышления (метрики, JTBD, A/B-тесты).
- UX для AI-агентов (UX ≠ для обычных приложений — disambiguation, transparency).
- Бизнес-домен (финтех, edtech, ecom — хотя бы один глубоко).
- Стоимость LLM и оптимизация (кэш, model cascade, distillation).

## 5. Soft skills и мета-навыки

- Системное мышление — видеть агента как часть системы (не изолированно).
- Чтение документации и исходников (большая часть знаний — в GitHub-репо).
- Письменная коммуникация (архитектурные документы, RFC, ADR).
- Презентация решений — продать архитектуру стейкхолдерам.
- Критическое мышление — не верить маркетингу LLM-вендоров.
- Английский на уровне чтения arXiv / блогов — 90% передовых материалов на английском.
- Менторство / код-ревью — учит формализовывать знания.

## 6. Дорожная карта по годам

### 1 курс (фундамент)
- Закрыть пробелы по CS (алгоритмы, ОС, сети).
- Освоить Python на уровне middle (typing, async, packaging).
- Первый pet-project с LLM API (Telegram-бот или CLI).
- 1 курс по ML (Andrew Ng, ШАД, ВШЭ).
- Участие в хакатонах (Sber, VK, AI Journey).

### 2 курс (глубина)
- RAG-система с нуля (Qdrant + FastAPI + Streamlit UI).
- Второй язык (TypeScript или Go).
- Стажировка в AI-команде (Яндекс, Сбер, Т-Банк, Avito).
- Open-source контрибьюция (любой агентный фреймворк).
- Прохождение курса по LLM (DAIR.AI, DeepLearning.AI).

### 3 курс (специализация)
- Серьёзный проект: multi-agent система с оркестрацией.
- Публикация в Telegram-канале / на Хабре / GitHub (портфолио).
- Курс по MLOps / Evals / Observability.
- Стажировка в продуктовой AI-команде.
- Чтение arXiv: agentic systems, tool-use, planning.

### 4 курс (job-ready)
- Диплом как production-grade агентная система.
- Сеть контактов: конференции (AI Journey, Datafest, Conversations).
- Подготовка портфолио из 5+ проектов.
- Собеседования в AI-команды уровня Middle/Senior.
- Pet-проект с open-source вкладом (не менее 50 звёзд).

## 10. Ключевые риски

- Динамика сферы — фреймворки устаревают за 6–12 месяцев; учить принципы, а не API.
- Перегрев зарплат — рынок может скорректироваться; не гнаться за $.
- Эффект "промптера" — не скатиться в "клею LangChain по туториалу"; глубина в CS и системном дизайне.
- Vendor lock-in — избегать привязки к одному вендору; понимать альтернативы.
- Этические/правовые риски — GDPR (152-ФЗ в РФ), генерация контента, ответственность за решения агента.

## 12. Итоговая оценка

Архитектор агентов в 2026–2030 — одна из самых перспективных ролей на стыке CS, AI и продуктовой инженерии. В РФ рынок только формируется, конкуренция среди junior-уровня высокая, среди middle/senior — дефицит.

Главные ставки:
1. Глубокий CS-фундамент (не "только LLM").
2. Production-опыт (а не только pet-проекты).
3. Системное мышление (видеть агента как часть системы).
4. Портфолио на GitHub (лучше диплома).
5. Сеть контактов в AI-сообществе РФ.

Чего НЕ делать:
- Не идти только ради LLM-промптинга (это нижний уровень).
- Не игнорировать CS-фундамент (иначе потолок карьеры).
- Не пропускать инфраструктуру (DevOps, observability — must-have).
- Не забывать продукт (архитектор без бизнес-понимания = дорогой промптер).
