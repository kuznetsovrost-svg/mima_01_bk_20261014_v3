ДЕЙСТВИЯ
================================================================================

1) СНЕСЛИ СТАРЫЙ HERMES_GATEWAY
   DELETE /_matrix/client/v3/devices/HERMES_GATEWAY
   Требовал UIA m.login.password (HTTP 401 → получили session →
   повторили с auth в теле) → HTTP 200, device удалён.

2) СОЗДАЛИ НОВЫЙ DEVICE через POST /_matrix/client/v3/login
   type: m.login.password
   identifier: { type: m.id.user, user: "@oc_hermes:..." }
   initial_device_display_name: "hermes-bot-clean-2026-06"
   (device_id не передавали — HS создал свежий автоматически)
   → HTTP 200
   → device_id:    IRGTQXZUZU
   → access_token: <новый, записан в /root/.hermes/.env>

3) УДАЛИЛИ ОСТАВШИЕСЯ ДВА DEVICE с новым токеном
   • DELETE /devices/EDDAIOUMIP  (Element iOS)   → HTTP 200
   • DELETE /devices/OTBJLBEADG  (Chrome)        → HTTP 200

4) УДАЛИЛИ МУСОРНЫЙ DEVICE TQSVPUCPSI
   В первой попытке phase B скрипт упал на `UID: readonly variable`
   (UID — встроенная переменная bash) ПОСЛЕ того, как login уже
   отработал и зарегистрировал на HS device TQSVPUCPSI. Этот
   device был "голым" — без сессии, без IP, бесполезным. Удалили
   его отдельным DELETE с UIA m.login.password → HTTP 200.

5) ПРОВЕРИЛИ, ЧТО НОВЫЙ DEVICE ЧИСТЫЙ (НЕ ЗАШИФРОВАННЫЙ)
   GET /_matrix/client/v3/keys/query/@oc_hermes:...
   → device_keys для нашего user_id: пусто
   → failures: пусто
   → ВЫВОД: новый device НЕ опубликовал ed25519/curve25519 ключи,
     считается "incapable of E2EE", что и требовалось.

6) ОБНОВИЛИ .env
   • Бэкап:  /root/.hermes/.env.bak.20260614-173444
   • Правка:  MATRIX_ACCESS_TOKEN=syt_...  (ротирован)
