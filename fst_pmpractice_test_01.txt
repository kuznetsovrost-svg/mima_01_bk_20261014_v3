3.2. describe_entity
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
  Возвращает JSON-схему - модель сущности, перечень полей и допустимые
  значения.
  ПАРАМЕТРЫ:
  - entityName: Системное имя сущности.
  - data_id: Идентификатор сущности: если не указан, используется 'new',
  если указан то доступ к полям и доступные значения рассчитывается.
  - defaultProperties: Значения полей по умолчанию для режима 'new'.
  Пример: {"PointKind":"task","ProfileId":7} или {"ProfileId":7}
  - show_allowed_values: Перечень полей/ролей, для которых нужно
  получить допустимые значения.
  Если не передан — справочники не подгружаются.
  Если передан — справочники подгружаются только для полей и ролей,
  найденных в списке.
  Специальное значение "__all__" — подгрузить справочники для всех полей
  и ролей выбора.
  Пример: ["ParentId", "ResponsibleId"]' допустимые значения будут в
  allowed_values["ParentId"] и allowed_values["ResponsibleId"].
  ВАЖНО ДЛЯ АГЕНТА:
  Всегда вызывай этот инструмент ПЕРЕД тем, как пытаться создать или
  обновить сущность (через save_entity).
  Без этого ты не будешь знать список доступных полей (атрибутов).

  Параметры (inputSchema):
    • entityName (string) — ✓ обязательный
    • data_id (any) —   опциональный [anyOf]
    • defaultProperties (any) —   опциональный [anyOf]
    • show_allowed_values (any) —   опциональный [anyOf]

  Возвращает: object

3.3. save_entity
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
  Универсальный метод для создания или обновления любой сущности.
  ПАРАМЕТРЫ:
  - entityName: Системное имя сущности (например, 'Project',
  'Contract').
  - id: ID записи для редактирования. Используй слово 'new' для создания
  новой записи.
  - data: Словарь (JSON объект) с данными.
  АЛГОРИТМ ДЛЯ АГЕНТА:
  1. Сначала вызови describe_entity(entityName).
  2. Проанализируй вернувшиеся поля (attributes).
  3. Сформируй объект data, заполняя только нужные поля из запроса
  пользователя.
  4. Вызови этот метод (save_entity).
  ФОРМАТ ПОЛЕЙ:
  - date dd.mm.yyyy
  - datetime ISO 8601

  Параметры (inputSchema):
    • entityName (string) — ✓ обязательный
    • id (string) — ✓ обязательный
    • data (object) — ✓ обязательный

  Возвращает: object

3.4. delete_entity
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
  Универсальный метод для удаления любой записи сущности.
  ПАРАМЕТРЫ:
  - remove - список словарей с данным:
  - entityName: Системное имя сущности (например, 'Project',
  'Contract').
  - dataIds: массив ID записей сущности.
  - cascade_delete: параметр удаления, если он равен true
  , то произойдет форсированное удаление записи со всеми связанными
  обязательными объектами.
  , если false, возвращает список словарей с основными данными о
  косвенно или опосредованно связанных объектах с удаляемым
  в иерархичном виде(айди объекта и его родителя, доступ к удалению,
  системное имя сущности), на основе этих данных можно
  будет совершить повторный вызов метода для удаление(форсированного или
  нет) связанных объектов и самой записи,
  при возврате связанных объектов нужно показать их пользователю и
  уточнить нужно ли их удалять вместе с исходным.
  remove формируется так: сначала группируем по entityName записи
  с результатом группировки в виде словаря со свойствами entityName И
  dataIds
  , значением которого будет список с ади сущностей, группируемых по
  entityName
  - Если cascade_delete=false и сервер вернул дерево только с исходными
  объектами
  (без связанных), инструмент автоматически повторит удаление с
  cascade_delete=true.

  Параметры (inputSchema):
    • remove (array) — ✓ обязательный
    • cascade_delete (any) —   опциональный [anyOf]

  Возвращает: object

3.6. upload_entity_file
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
  Загружает файл документа сущности.
  ПАРАМЕТРЫ:
  - entityName: Системное имя сущности (например, 'Project').
  - dataId: ID карточки (например, '121760' или 'new').
  - documentId: ID документа (например, 60072) можно получить из
  представления DocumentView.
  - uploadedFileName: Имя файла с расширением (например, "report.xlsx").
  - uploadedFileContentBase64: Содержимое файла в base64.
  - activityPhaseId: ID стадии ЖЦ (например, 40032). Необязательный
  параметр.

  Параметры (inputSchema):

    • uploadedFileName (string) — ✓ обязательный

3.9. get_view
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
  Метод загружает данные представления
  ПАРАМЕТРЫ:
  - entityName: Системное имя сущности.
  - viewName: Системное имя представления.
  - limit: Ограничение количества возвращаемых записей (__limit__).
  - offset: Смещение первой возвращаемой записи (__offset__).
  - filters: JSON-объект с условиями фильтрации, например:
  {"ProjectId": 196723, "ActivityId": 196723, "Name": "Внедрение MCP"}.
  Каждый атрибут отправляется на бэкенд отдельным полем верхнего уровня.
  Доступные фильтры перечислены в описании представления.
  Нужно заполнить хотя бы один параметр: entityName или viewName.
  Если заполнен viewName, то загружается данные представления viewName.
  Если заполнен entityName, то загружается данные первого представления
  сущности entityName.
  Если заполнены оба параметра, то загружается данные представления
  viewName.

  Параметры (inputSchema):
    • entityName (any) —   опциональный [anyOf]
    • viewName (any) —   опциональный [anyOf]
    • limit (any) —   опциональный [anyOf]
    • offset (any) —   опциональный [anyOf]
    • filters (any) —   опциональный [anyOf]

  Возвращает: object
