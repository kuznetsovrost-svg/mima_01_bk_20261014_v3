# Правила IDEF0 (FIPS 183)

IDEF0 (Integration DEFinition for Function Modeling) — стандарт
функционального моделирования, FIPS 183 (США, 1993).

## Элементы

- **Function (Activity)** — прямоугольник, изображает функцию
- **Input (I)** — стрелка входит слева, что преобразуется
- **Control (C)** — стрелка входит сверху, правила, стандарты
- **Output (O)** — стрелка выходит справа, результат
- **Mechanism (M)** — стрелка входит снизу, ресурсы, исполнители

## Уровни

- **A-0** — контекстная диаграмма (один блок)
- **A0** — декомпозиция A-0
- **A1, A2, ...** — декомпозиция блоков A0
- **A11, A12, ...** — декомпозиция блоков A1

## ICOM-коды

Каждая стрелка имеет уникальный код в пределах диаграммы:
- I1, I2, I3, ... (Inputs)
- C1, C2, ... (Controls)
- O1, O2, ... (Outputs)
- M1, M2, ... (Mechanisms)

## Каталог объектов (Arrow Catalogue)

Обязательная таблица для каждой диаграммы:

| Имя | Источник | Получатель | Тип |
|-----|----------|-------------|-----|

- Источник/Получатель: имя блока или "Граница"
- Тип: I, C, O, M

## Описание листа (Node Description)

Гуманизированный текст по шаблону:

```
Блок {номер}. {Имя}.
На основании {Controls},
получает {Inputs},
выдаёт {Outputs},
опираясь на {Mechanisms}.
```

## ICOM Consistency Check

Число, имена и род ICOM блока на parent должны совпадать с
ICOM всей child диаграммы (граничные стрелки).

## Туннели

Стрелка с парой круглых скобок ( ) у точки привязки.
Проходит сквозь всю child диаграмму, попадает в ICOM листа.

## Что НЕ входит в IDEF0

- ❌ Межстраничные стрелки (используются ICOM-коды)
- ❌ Backward edges (обратные связи как стрелки — отдельная
  нотация)
- ❌ Динамические процессы (это BPMN-процессы)

## Стандарт

FIPS 183 — Integration Definition for Function Modeling.
Опубликован NIST, 1993.
