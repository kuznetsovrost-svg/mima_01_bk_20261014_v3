# Playbook: Excalidraw Grid Analyzer

Подробное руководство по использованию скилла `excalidraw-grid-analyzer`.

## 1. Название и вызов

**Скилл:** `excalidraw-grid-analyzer`
**Расположение:** `/root/.hermes/skills/creative/excalidraw-grid-analyzer/`
**Тип:** глобальный (доступен всем профилям Hermes)
**Категория:** creative

### Когда подключать

Подключай этот скилл, если в Excalidraw файле есть таблица навыков/сущностей и нужно:
- узнать, какие навыки описаны;
- найти навыки без описания;
- найти описания без навыка;
- получить описание конкретного навыка;
- проверить покрытие (что у всех сущностей есть описания).

### Как вызвать

CLI запускается из каталога `scripts/`:

```bash
cd /root/.hermes/skills/creative/excalidraw-grid-analyzer/scripts
python3 grid_analyzer.py <команда> [NNN] <файл.excalidraw>
```

## 2. Какие задачи решает

### 2.1. Информационные запросы

- **«Расскажи про скилл #003»** → `get-skill 003`
- **«Покажи все скиллы»** → `list-skills`
- **«Покажи все описания»** → `list-descriptions`
- **«Приведи описание #003»** → `get-description 003` (только текст)
- **«Общая статистика»** → `summary`

### 2.2. Валидационные запросы

- **«Проверь, что у всех сущностей таблицы есть описания»** → `find-missing-descriptions`
- **«Проверь, что у всех описаний есть сущности в таблице»** → `find-orphan-descriptions`
- **«Найди расхождения в именах»** → `find-name-mismatches`
- **«Проверь покрытие»** → `coverage`
- **«Полная валидация»** → `validate` (все проверки + exit code)

### 2.3. Структурный анализ

- Определение размеров таблицы (`cell_width × cell_height`) из имени Frame
- Подсчёт реального количества строк и столбцов по позициям групп
- Обнаружение пустых клеток
- Полный JSON-отчёт (`match-skills`)

## 3. Как правильно оформлять таблицу и описания

### 3.1. Frame «Таблица WxH»

**Обязательное имя:** `Таблица WxH` (например, `Таблица 500x300`).

Распознаваемые форматы:
- `Таблица 500x300`
- `Таблица 500х300` (русская «х»)
- `Таблица 500X300` (заглавная)
- `Таблица 500 x 300` (с пробелами вокруг x)

`W` — ширина одной клетки в пикселях, `H` — высота одной клетки в пикселях.

Frame должен вмещать все клетки сетки. Для таблицы 3×3 при `WxH=500x300` Frame должен быть `1500×900` плюс отступы.

### 3.2. Клетки внутри таблицы

Каждая клетка — это **группа из 3-х элементов** с одним общим `groupIds[0]`:

1. **Прямоугольник** (background) — фон клетки
2. **Текст `##NNN`** — номер сущности (regex `^#+\s*(\d+)\s*$`)
3. **Текст с наименованием** — имя сущности. **НЕ должно начинаться с `#`**

Все 3 элемента должны иметь один и тот же `groupIds[0]` (например, `["g1"]`).

### 3.3. Frame с описаниями

Описания могут быть:
- в отдельном Frame (например, `Описание`)
- или вообще вне Frame — любая группа из 4-х элементов считается описанием

Порядок описаний **произвольный**.

**Каждое описание — группа из 4-х элементов:**

1. **Прямоугольник** (background)
2. **Текст `##NNN`** — номер (тот же regex)
3. **Текст с `#Наименование`** — имя. **ОБЯЗАНО начинаться с `#`** (но не `##NNN`)
4. **Многострочный текст** — само описание (самый длинный текст в группе, не начинающийся с `#`)

### 3.4. Правило сопоставления (двойная проверка)

Скилл сопоставляет сущность таблицы с её описанием по **двум условиям одновременно**:

1. `##NNN` совпадает (после нормализации ведущих нулей)
2. Имя (после снятия `#`) совпадает с именем в таблице

Если оба выполнены — пара matched. Если только одно — это **расхождение**. Если ни одного — orphan/missing.

**Важный нюанс:** Если NNN не совпал — это уже orphan/missing, не both_mismatch. Подробнее см. gotcha #17 в `excalidraw-json-gotchas`.

Имена сравниваются после нормализации: trim → lower → снятие ведущих `#` → схлопывание пробелов.

## 4. Примеры команд

### Получить описание навыка
```bash

```

```
Преобразует Markdown в HTML/PDF.
Поддерживает таблицы, код-блоки, mermaid.

```

```bash
python3 grid_analyzer.py find-orphan-descriptions my-skills.excalidraw
```

```bash
python3 grid_analyzer.py validate my-skills.excalidraw

```

```bash
python3 grid_analyzer.py summary my-skills.excalidraw
```

## 6. Troubleshooting

### 6.1. Frame таблицы не найден

**Симптом:** `Ошибка: Frame 'Таблица WxH' не найден`

**Причина:** имя Frame не соответствует regex `^Таблица\s+(\d+)\s*[xхХX]\s*(\d+)\s*$`.

**Решение:**
- Frame должен называться именно `Таблица` (кириллица, заглавная)
- После `Таблица` — пробел
- Размеры — два числа через `x`, `х`, `X` или `Х`
- Пример: `Таблица 500x300`

### 6.2. Все сущности показывают «нет описания», хотя описания есть

**Причина:** описания не разделены на группы, либо все элементы описания в одной группе с элементами таблицы.

**Решение:**
- Каждое описание — **отдельная группа** (свой уникальный `groupIds[0]`)
- Элементы описания НЕ должны иметь того же `groupIds`, что и клетки
- Прямоугольник, номер, имя и текст описания имеют **один общий `groupIds`**

### 6.3. Покрытие 0%, хотя сущности и описания есть

**Решение:**
- Запустите `find-name-mismatches`
- Проверьте, что в описании имя начинается с `#`, а в таблице — БЕЗ `#`
- Сравнение регистронезависимо, игнорирует пробелы

### 6.4. Команда `validate` возвращает exit=0, но есть проблемы

**Симптом:** `validate` пишет «✅ ВСЁ ОК», хотя orphan/missing есть.

**Причина:** orphan/missing отображаются в выводе, но не считаются критическими для exit code.

**Решение:** используйте exit code в связке с проверкой вывода через `grep`:

```bash
output=$(python3 grid_analyzer.py validate file.excalidraw 2>&1)
if echo "$output" | grep -q "❌"; then
    echo "Проблемы найдены"
    exit 1
fi
```

### 6.5. Имя Frame распознаётся как другой формат

`SkillsTable 500x300` не распознаётся. Скилл ожидает именно `Таблица`. Если нужен другой язык, добавьте алиас в `grid_parser.py:TABLE_FRAME_NAME_PATTERN`.

### 6.6. Тесты не запускаются

**Симптом:** `ModuleNotFoundError: No module named 'grid_parser'`

**Решение:**
```bash
cd /root/.hermes/skills/creative/excalidraw-grid-analyzer/tests
python3 run_tests.py
```

### 6.7. Описание не распознаётся как имя

**Симптом:** в `list-descriptions` `NNN` есть, а `#Имя` — пусто.

**Причина:** текст имени либо `##NNN` (считается номером), либо не начинается с `#`.

**Решение:**
- Имя в описании должно начинаться с `#`: `#Git синхронизация`
- Не должно быть просто `##NNN`
- Минимальная длина имени (без `#`) — 2 символа

## 7. Минимальный набор правил оформления

1. Имя Frame таблицы: `Таблица WxH` (например, `Таблица 500x300`)
2. В каждой клетке — группа из 3-х: прямоугольник + `##NNN` + имя (без `#`)
3. Каждое описание — группа из 4-х: прямоугольник + `##NNN` + `#Имя` + текст
4. Все элементы одной сущности/описания имеют общий `groupIds[0]`
5. `##NNN` одинаковые в таблице и описании (с точностью до ведущих нулей)
6. Имя после снятия `#` одинаковое в таблице и описании (без учёта регистра)
