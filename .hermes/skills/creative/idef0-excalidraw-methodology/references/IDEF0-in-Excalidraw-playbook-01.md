Введение
========

IDEF0 (Integration DEFinition for Function Modeling) — стандарт
функционального моделирования процессов (FIPS 183, 1993).

Цель playbook:
1. Описать правила IDEF0
2. Согласовать разметку в Excalidraw
3. Описать процедуры валидации
4. Подготовить почву для автоматизации (скилл `idef0-excalidraw-methodology`)


Часть I. Основы IDEF0
=====================


Глава 1. Элементы IDEF0
-----------------------

1.1 Function (Activity)

    Прямоугольник, изображает функцию/действие.
    Содержит:
    - Имя функции (по центру)
    - Номер блока (в нижнем левом углу)

1.2 Стрелки ICOM

    I — Input (слева)         — что преобразуется
    C — Control (сверху)      — правила, стандарты
    O — Output (справа)       — результат
    M — Mechanism (снизу)     — ресурсы, исполнители

1.3 ICOM-коды

    Соглашение: каждая стрелка имеет уникальный код в пределах
    диаграммы (I1, I2, C1, O1, M1, ...)

1.4 Уровни декомпозиции

    A-0 — контекстная (один блок, общая картина)
    A0 — декомпозиция A-0
    A1, A2, ... — декомпозиция блоков A0
    A11, A12, ... — декомпозиция блоков A1
    и т.д.


Глава 2. Соглашения по именованию блоков
----------------------------------------

2.1 Структура блока

    Канонический вид:

    ┌─────────────────────────┐
    │                         │
    │   Имя функции           │  ← функция (центр)
    │                         │
    │ A1.2                    │  ← номер (нижний левый угол)
    └─────────────────────────┘

2.2 Реализация в Excalidraw

    Блок = группа из 3 элементов:

    {
      "id": "block-A1-2",
      "type": "rectangle",
      "x": 100, "y": 100,
      "width": 200, "height": 100,
      "groupIds": ["group-A1-2"]
    },
    {
      "id": "func-A1-2",
      "type": "text",
      "text": "Разработка чертежей",
      "x": 120, "y": 140,
      "width": 160, "height": 20,
      "textAlign": "center",
      "groupIds": ["group-A1-2"]
    },
    {
      "id": "num-A1-2",
      "type": "text",
      "text": "A1.2",
      "x": 105, "y": 175,
      "width": 30, "height": 15,
      "textAlign": "left",
      "groupIds": ["group-A1-2"]
    }

2.3 Соглашения по ID

    block-<N>      прямоугольник
    func-<N>       текст функции
    num-<N>        текст номера
    group-<N>      имя группы

2.4 Размеры текста

    Функция: 16-20 px
    Номер: 10-12 px


Глава 3. Уровни диаграммы (Frame)
----------------------------------

3.1 Каждый уровень = Frame

    Имя Frame включает:
    - Код уровня (A-0, A0, A1, ...)
    - Описание функции
    - Parent (родительский блок)

    Формат имени: "A<n> <Описание> (parent: A<m>-<код>)"

3.2 Примеры имён

    "A-0 Контекст"
    "A0 (parent: A-0)"
    "A1 Обработка заявки (parent: A0-2)"

3.3 Связь parent-child

    В имени Frame указывается parent:
    - Frame "A1" связан с блоком A0-2
    - При валидации ICOM consistency проверяем
      соответствие ICOM блока A0-2 и ICOM диаграммы A1


Часть 4. Стрелки ICOM
----------------------

4.1 Грани стрелок

    Каждая стрелка присоединена к ОДНОЙ из граней блока:
    - левая (Input)
    - правая (Output)
    - верхняя (Control)
    - нижняя (Mechanism)

4.2 Определение грани (алгоритм)

    Конец стрелки:
    end_x = arrow.x + arrow.points[-1][0]
    end_y = arrow.y + arrow.points[-1][1]

    Блок:
    left = block.x
    right = block.x + block.width
    top = block.y
    bottom = block.y + block.height

    Какая грань ближе всего:
    distances = {
      "left": abs(end_x - left),
      "right": abs(end_x - right),
      "top": abs(end_y - top),
      "bottom": abs(end_y - bottom)
    }
    nearest_side = min(distances, key=distances.get)


Часть 5. ICOM Consistency Check (связность parent ↔ child)
-----------------------------------------------------------

5.1 Что проверяется

    Число, имена и род ICOM блока на parent должны совпадать
    с ICOM всей child диаграммы.

5.3 Алгоритм

    def check_icom_consistency(parent_block, child_frame):
        parent_icom = extract_icom_from_block(parent_block)
        child_icom = extract_icom_from_frame(child_frame)
        errors = []
        for role in ["input", "control", "output", "mechanism"]:
            if set(parent_icom[role]) != set(child_icom[role]):
                errors.append(...)
        return errors


Часть 6. Туннелирование
------------------------

6.1 Что такое туннель

    Стрелка, которая НЕ декомпозируется в child диаграмме
    как обычно — она "проходит насквозь" и попадает в ICOM
    листа.

6.2 Нотация

    Визуально: пара круглых скобок ( ) вокруг точки привязки
    стрелки к блоку.

6.3 Разметка в Excalidraw

    Туннель обозначается в тексте стрелки:
    - "( I1 входной документ" — туннель на конце стрелки
    - "I1 входной документ )" — туннель на начале
    - "( I1 входной документ )" — туннель с обеих сторон
    - "I1 входной документ" — обычная (не туннель)


Часть 7. Каталог объектов (Arrow Catalogue)
---------------------------------------------

7.1 Что это

    Обязательная таблица для каждой диаграммы, описывающая
    ВСЕ стрелки на этой диаграмме.

7.2 Формат таблицы

    | Имя стрелки    | Источник            | Получатель        | Тип |
    |----------------|---------------------|-------------------|-----|
    | Заявка клиента | Граница             | Блок 1            | I   |
    | Правила        | Граница             | Блок 1, 2, 3      | C   |
    | Отчёт          | Блок 2              | Граница           | O   |


Часть 8. Описание листа диаграммы (Node Description)
-----------------------------------------------------

8.1 Что это

    Связный "гуманизированный" текст, описывающий каждый
    блок диаграммы по стандартному шаблону.

8.2 Шаблон

    "Блок {номер}. {Имя}.
    На основании {Controls — стрелки сверху},
    получает {Inputs — стрелки слева},
    выдаёт {Outputs — стрелки справа},
    опираясь на {Mechanisms — стрелки снизу}."

8.6 Пример результата

    "Блок 1. Обработка заявки. На основании "Правила работы"
    и "Стандарты", получает "Заявка клиента", выдаёт
    "Заявка проверенная", опираясь на "Менеджер"."


Часть 9. Чеклист валидной IDEF0 диаграммы в Excalidraw
--------------------------------------------------------

[ ] Все блоки = группа из 3 элементов (rect + func + num)
[ ] Все блоки имеют уникальные номера в пределах диаграммы
[ ] Все стрелки имеют ICOM-коды (I1, C1, ...)
[ ] Стрелки присоединены к граням блоков (не к углам)
[ ] Каждый уровень = отдельный Frame
[ ] Frame содержит "(parent: ...)" для parent-child связи
[ ] Каталог объектов присутствует внутри каждого Frame
[ ] Туннели обозначены скобками ( ) в тексте стрелки
[ ] Граничные стрелки корректно размещены у границ Frame
[ ] ICOM consistency между parent и child проверена
