#SPA Анализ одиночного файла программы обучения для подготовки архитекторов AI-агентов в ВУЗе

## Назначение

Анализ программы обучения в ВУЗ для подготовки AI-архитекторов на предмет соответствия её требованиям подготовки архитекторов агентов с составлением отчета по указанному шаблону.

## When to Use

Загружай навык, когда требуется проанализировать файл с описанием программы обучения для подготовки архитекторов AI агентов на предмет соответствия её требованиям подготовки архитекторов агентов.

**Применять, когда:**
- Пользователь прислал файл (PDF, DOCX, TXT, MD) с описанием учебной программы ВУЗа.
- Цель анализа — оценить, насколько программа готовит именно архитекторов AI-агентов (а не, например, data-аналитиков или ML-инженеров общего профиля).
- Нужен структурированный отчёт по заданному шаблону (см. «Формат результата»).

**Не применять для:**
- Оценки качества преподавания в целом (общий рейтинг ВУЗа, качество лекторов, условия в аудиториях).
- Сравнения нескольких программ между собой (skill работает с одним файлом за раз).
- Программ, не связанных с AI/ML/агентами (например, чистая frontend-разработка или бизнес-информатика).
- Программ, где нет перечня предметов по семестрам — в этом случае skill запишет «трудно оценить» для §7–§8.

## Основные правила

1. Опирайся на свои знания о требованиях к будущим архитекторам AI агентов, которые будут работать, например с HERMES.
2. При анализе курса опирайся только на данные с описанием программы обучения из полученного файла, ничего не придумывай.
3. Будь осторожен в оценках. Если нет достаточно ясной картины — запиши «трудно оценить».
4. Говори только по делу и аргументировано. Не более 2-3 предложений на тезис.

### Правило 5 — верификация ссылок при отсутствии веб-доступа

Процедура §7–§9 требует 2–3 надёжных ссылки на каждый тезис. Это конфликтует с правилом 2 («не выдумывай»), если в сессии нет доступа к `web_search` / `browser_navigate`. Применяй следующий fallback:

- **Если есть `web_search` или `browser_navigate`** — верифицируй каждый URL перед включением в отчёт. В отчёте ссылки подаются как обычно, без пометки.
- **Если веб-доступа нет** (или он заведомо неуспешен: `browser_navigate` возвращает пустоту, `web_search` не подключён) — НЕ отказывайся от ссылок и НЕ молча выдумывай. Действуй так:
  1. Перед запуском длительной серии отчётов (5+ файлов) один раз спроси пользователя через `clarify`: «Web-поиск недоступен. Применять ссылки из моих знаний (не верифицированы) или сократить отчёт до §1–§6 без ссылок?»
  2. Если пользователь выбрал «из моих знаний» — включай ссылки в отчёт, но **каждую помечай суффиксом `([не верифицировано])`** в одной строке с URL.
  3. В отдельный блок `## Disclaimer о ссылках` в начале отчёта добавь: «Все ссылки приведены из общих знаний модели и не верифицированы веб-поиском в этой сессии. Перед использованием рекомендуется проверить доступность и актуальность.»
  4. Если пользователь выбрал «сократить отчёт» — пропусти §7–§9, оставь §1–§6 и §10 как «Раздел опущен: верификация ссылок недоступна».
- **Никогда** не включай URL, который ты не можешь назвать источником хотя бы по памяти. «Наверное это где-то есть» — это выдумка.

## Procedure

### Общий анализ данных программы обучения
1. Прочитай файл с описанием программы обучения.
2. Выдели аспекты, соответствующие требованиям к подготовке архитекторов AI агентов.
3. Укажи на преимущества данной программы обучения для подготовке архитекторов AI агентов с твоей точки зрения.
4. Укажи на слабые места данной программы обучения. Обоснуй каждое утверждение.
5. Сделай предварительный вывод о том, насколько данная программа в целом подходит подготовки архитекторов AI агентов. Обоснуй свои выводы. Приведи ссылки.
6. Оцени, насколько хороши места прохождения практик для подготовки архитекторов AI агентов.
7. Оцени, насколько типовые профессии, предлагаемые выпускникам, близки к задаче стать архитектором AI агентов.
   - **Completion criterion:** если в файле явно не указан перечень профессий или направлений трудоустройства — запиши в §6 отчёта «трудно оценить: во входных данных не указан список профессий» и перечисли, какие именно поля отсутствуют. Не додумывай.

### Работа со списком предметов программы обучения по описанию из файла
1. Найди в файле из Inputs список предметов (по семестрам) в описании учебного курса в файле.
2. Выдели 10 наиболее важных предметов из курса для будущего архитектора AI агентов. Для каждого из важных предметов подбери 2-3 надёжных ссылки, доказывающих его нужность.
3. Оцени, насколько много внимания уделяется наиболее важным предметам.
4. Укажи 10-15 недостающих предметов (которые следует отдельно доучивать вне программы обучения чтобы стать архитектором AI агентов). Для каждого из недостающих предметов подбери 2-3 надёжных ссылки, доказывающих его нужность.

## Формат результата
```markdown
## 1. Общая информация о программе подготовки
## 2. Какое структурное подразделение института проводит программу подготовки
## 3. Ключевые преимущества программы подготовки
## 4. Слабые места программы подготовки
## 5. Привлекательность мест предлагаемого прохождения практик
## 6. Близость типовых профессий, предлагаемых выпускникам, к задаче стать архитектором AI агентов
## 7. Наиболее важные предметы из программы подготовки архитектора AI агентов
## 8. Акцент (объем по семестрам) на наиболее важных предметах программы подготовки
## 9. Недостающие предметы программы подготовки для архитектора AI агентов
## 10. Суммарный реестр ссылок для обоснований
```

## Common Pitfalls

- Зациклиться на одном параметре курса обучения, упуская общую картину подготовки будущего архитектора AI агентов.
- Рассматривать перечень изучаемых предметов и не обратить внимание на продолжительность изучения каждого предмета по семестрам (сколько семестров делается акцент на предмете).
- Принимать на веру само название курса подготовки и возможные профессии и не обращать внимание на фактически изучаемые предметы на курсе.
- Не учитывать вариации в названии одного и того же предмета.
- Подбирать ссылки низкого качества (нерабочие, рекламные, без автора или даты) — см. verification.
- Молча выдумывать URL, потому что «вроде бы знаю такой сайт» — это нарушает правило §2 «не выдумывай». См. правило 5: либо верифицируй через web-доступ, либо спроси пользователя, либо помечай каждую ссылку `([не верифицировано])` с шапкой-дисклеймером в отчёте.
- Генерировать 5 отчётов подряд в параллельном режиме и перемешать их содержимое — каждый файл из Inputs анализируется в отдельном проходе skill'а, с собственным контекстом и без переноса выводов между файлами. См. `references/batch-patterns.md`.
- **Запускать длинную серию отчётов без `clarify` о политике ссылок.** Если пользователь даёт сразу N файлов и просит «обработай все», правило 5 требует спросить про политику ссылок ДО первого write_file, а не после. Иначе 5-й отчёт уже будет написан по выдуманной политике, и переписывать поздно.
- **Использовать имена из task-файла буквально, не сверяясь с реальным содержимым `Inputs/`.** В этой сессии task указывал `Интеллектуальные системы управления и обработки информации.md` (с пробелами), а на диске лежало `Интеллектуальные_системы_управления_и_обработки_информации.md` (с подчёркиваниями). Перед первым циклом запусти `os.listdir(Inputs/)` и свежие имена используй как источник истины.
- **Считать, что `MEDIA:`-маркер в Telegram превращает `.txt` / `.md` в inline-текст.** Это не так — `.md` и `.txt` явно перечислены в `references/messaging.md` как нативные attachment-расширения. Если пользователь говорит «пришли как файл, а не как текст», проблема не в формате, а в первом впечатлении клиента — повторная отправка после пояснения обычно решает.
- **Обновлять `progress.json` только в начале и в конце.** Для серии из 5+ файлов нужен per-file статус (state: pending → in_progress → done, started_at, finished_at, report_path). Без этого при сбое на 3-м файле невозможно понять, что уже сделано, и придётся переделывать.

## Verification

Перед завершением проверь:

- [ ] Выводы записаны в файл Outputs с названием, соответствующим файлу из Inputs, откуда брались данные.
- [ ] Для выводов о важности предметов подобраны работающие ссылки для обоснования.
- [ ] Для перечня недостающих предметов подобраны работающие ссылки для обоснования.
- [ ] Вывод данных в файл Outputs соответствует требуемому формату результата.
- [ ] **Качество ссылок:** для каждой ссылки в §10 хотя бы одна из 2-3 ссылок по каждому тезису — это первоисточник, официальная документация (ГОСТ/учебный стандарт ВУЗа, официальный сайт фреймворка, рецензируемая статья) или авторитетный справочник. Не должно быть только рекламных/SEO-страниц.
- [ ] **Раздел §6 (профессии):** если перечень профессий отсутствует во входном файле — в отчёте записано «трудно оценить» с указанием, каких данных не хватает.
