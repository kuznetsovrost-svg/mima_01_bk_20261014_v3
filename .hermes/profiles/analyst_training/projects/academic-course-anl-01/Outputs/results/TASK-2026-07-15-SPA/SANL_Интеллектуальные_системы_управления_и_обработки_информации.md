## 2. Какое структурное подразделение института проводит программу подготовки

**Институт искусственного интеллекта РТУ МИРЭА** — структурное подразделение университета, реализующее программу при поддержке **ГосНИИАС**. Это означает, что обучение ведётся в специализированном институте с фокусом на ИИ (а не в общей кафедре ИВТ), а ГосНИИАС выступает индустриальным партнёром — что для архитектора AI-агентов ценно: авиакосмическая отрасль исторически является полигоном для архитектур «sense → decide → act» с жёсткими требованиями к real-time и safety.

## 3. Ключевые преимущества программы подготовки

1. **Глубокий фокус на системах реального времени.** Программа выделяет отдельный блок дисциплин: «Основы программирования систем управления» (сем. 2), «Введение в алгоритмы и структуры данных систем реального времени» (сем. 3), «Передача информации в системах реального времени» (сем. 4), «Встраиваемые информационно-управляющие системы» (сем. 6), «Программирование микропроцессорных систем управления» (сем. 7), «Основы проектирования автоматизированных систем реального времени» (сем. 6), «Системное администрирование информационных и автоматизированных систем реального времени» (сем. 7). Это редкое и очень ценное сочетание для архитектора агентов: agent-loop требует планирования бюджета времени, и понимание real-time даёт архитектору качественное преимущество.

2. **Связка ML + киберфизика + теория управления.** Помимо «Систем искусственного интеллекта и больших данных» (сем. 3–4) и «Методов и технологий ИИ» (сем. 6), программа включает «Нейронечёткое управление» (сем. 7) и «Моделирование систем управления» (сем. 7). Это даёт выпускнику целостную картину «ИИ внутри управляющего контура», что критично для архитектуры агентов, действующих в физическом мире (роботизированные агенты, БПЛА, индустриальные агенты).

3. **Партнёрство с ГосНИИАС** — выход на авиакосмическую отрасль, где архитектуры sense-decide-act исторически проработаны глубже всего (бортовые системы с сертификацией по DO-178C и аналогам). Это даёт выпускникам навык проектирования safety-critical систем — применимо к high-stakes агентам.

4. **Аппаратно-программный трек.** «Архитектура вычислительных средств систем управления» (сем. 4), «Программирование логических интегральных схем» (сем. 6), «Технические средства автоматизации и управления» (сем. 6), «Электромеханические и мехатронные системы» (сем. 7), «Электротехника и электроника» (сем. 3–4) — формируют инженерный фундамент, без которого архитектор AI-агентов для встраиваемых/edge-сценариев остаётся «слепым».

5. **Сильная математическая база.** Линейная алгебра + аналитическая геометрия (сем. 1–2), математический анализ (сем. 1–4 — фактически 4 семестра!), дифференциальные уравнения (сем. 3), теория вероятностей и матстатистика (сем. 4), комплексный анализ (сем. 4), случайные процессы (сем. 5), численные методы (сем. 4), дискретная математика (сем. 1). Это та база, которая нужна для понимания алгоритмов оптимизации, обучения с подкреплением и вероятностных агентских архитектур (POMDP, байесовские подходы).

## 4. Слабые места программы подготовки

1. **Слабый фокус на LLM, prompt-engineering, RAG и современных agentic-patterns.** Программа сфокусирована на «классическом» ML (нейронные сети, нечёткое управление, интеллектуальный анализ данных) и **не упоминает** ни LLM, ни transformer-архитектур, ни prompt-инжиниринга, ни retrieval-augmented generation. Архитектор Hermes-стиля AI-агентов в 2026 году работает преимущественно с LLM-оркестрацией — этого в программе нет.

2. **Отсутствие контекстной инженерии и prompt-design как дисциплины.** Нет курсов по проектированию контекстного окна, по structured-output, по tool-use, по цепочкам рассуждений, по memory-architecture агента. Это ключевой навык для современного архитектора AI-агентов.

3. **Нет дисциплин по оценке и бенчмаркингу AI-систем.** Нет метрик качества агентов, нет red-teaming, нет alignment-оценки. Для архитектора критично уметь измерять поведение агента.

4. **Слабое покрытие data-engineering.** В семестре 4 есть «Проектирование информационных систем и баз данных реального времени», но это RT-БД, а не современный data stack (data lakehouse, vector DB, embeddings pipelines). Для RAG-агентов и memory-систем это критично.

5. **Нет явного трека по multi-agent systems / agent-communication.** Никакого курса по протоколам взаимодействия агентов, по agent-mesh, по иерархическим/кооперативным архитектурам. Hermes и подобные системы — это multi-agent фреймворки.

6. **Языки и стек.** Указаны C/C++ и Python (сем. 6-7 итоговый блок). Для современного AI-агента нужен TypeScript/JavaScript (web-агенты), Python для оркестрации, понимание облачных платформ и container-orchestration. Это всё за рамками программы.

7. **«Основы программирования» появляются только во 2 семестре** («Основы программирования систем управления»). Для архитектора AI-агентов базовая программистская культура нужна с первого курса, иначе теряется год.

8. **Этика и безопасность ИИ не выделены.** «Безопасность жизнедеятельности» (сем. 5) — это охрана труда, не AI safety/alignment. Для архитектора агентов, действующих автономно, понимание рисков — must have.

## 7. Наиболее важные предметы из программы подготовки архитектора AI агентов

Базовая теория для формализации агентных систем, state-machines, дискретных событийных систем.

## 9. Недостающие предметы программы подготовки для архитектора AI агентов

Программа **не покрывает** ряд критически важных для AI-агент архитектора дисциплин. Вот **15 недостающих предметов** с обоснованием (ссылки из общих знаний, не верифицированы):

### 9.1. Основы LLM и трансформерных архитектур
Современный AI-агент строится поверх LLM. Без понимания архитектуры трансформера, механизма внимания, контекстного окна — нельзя проектировать агентов.
- Vaswani et al., «Attention Is All You Need» — https://arxiv.org/abs/1706.03762 ([не верифицировано])
- Andrej Karpathy, «Let's build GPT: from scratch, in code» — https://www.youtube.com/@karpathy ([не верифицировано])
- Stanford CS25 (Transformers United) — https://web.stanford.edu/class/cs25/ ([не верифицировано])

### 9.2. Prompt-инжиниринг и контекстная инженерия
Архитектор агента 80% времени тратит на проектирование контекста, prompt-структур, system-messages, tool-descriptions.
- Anthropic prompt engineering guide — https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview ([не верифицировано])

## Итоговое заключение по программе

**Программа «Интеллектуальные системы управления и обработки информации» МИРЭА — это инженерная программа с сильным фундаментом по теории управления, встраиваемым системам и классическому ML, НО с недостаточным покрытием современной agentic-AI тематики.**

| Аспект | Оценка |
|---|---|
| Математический фундамент | 9/10 |
| Теория управления и real-time | 9/10 |
| Embedded / hardware | 8/10 |
| Классический ML | 6/10 |
| Современный AI / LLM / агенты | **2/10** |
| Software engineering / production | 3/10 |
| AI safety / ethics | 1/10 |
| Соответствие роли «Архитектор AI-агентов» 2026 | **4/10** |

**Рекомендация:** для подготовки архитектора AI-агентов в духе Hermes программу можно рассматривать как **хорошую базу по теории управления и embedded** (это редкое сочетание), но обязательно нужно доучивать вне программы: LLM-стек, prompt-engineering, RAG, agent-patterns, multi-agent, AI safety, MLOps.
