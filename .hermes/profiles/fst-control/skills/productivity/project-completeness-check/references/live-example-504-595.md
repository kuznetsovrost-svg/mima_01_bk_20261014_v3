## ⚠️ Конвенции пользователя `fst-control` (для генерации отчёта)

Эти правила **обязательны** при отправке отчёта пользователю в Telegram:

1. **Файлы >30 строк → `MEDIA:/path`, не inline.** Inline только превью
   + сводка (3–5 строк). Полный отчёт — отдельным файлом.
2. **Имя файла — кириллица + snake_case**, дата в формате `YYYY_MM_DD`,
   постфикс-NN. Пример: `project_504-595_здоровье_V02.md`.
3. **Порядок разделов фиксирован** (см. структуру ниже). Менять только
   по явной просьбе.
4. **Параметры скилла — в конце файла**, в виде Python-словаря
   (`PAYMENT_THRESHOLDS`, `FORECAST_OVERDUE_THRESHOLDS`, `FINANCIAL_THRESHOLDS`,
   `HEALTH_THRESHOLDS`). Это для воспроизводимости.
5. **«Неопределено» — отдельный статус**, не путать с «Нет». Применяется
   когда view недоступен (403) или проект в ранней стадии ЖЦ.

Раздел 5 отчёта (сводка замечаний по срокам) — это **вывод** скилла
`project-timing-control`. V01 был построен только на нём. V02 —

Если проект уже проведён через `project-completeness-check`, раздел 5
заполняется автоматически из тех же данных (Point view + фильтр по
`ParentCode == project_code`).

`SKILL-FST-HOWPROJET.md` (тот, что лежит в `/root/SKILL-FST-HOWPROJET.md`
отдельно от skills/). Версия скилла на момент V02 = **1.3**.

Когда скилл `project-completeness-check` дойдёт до v1.4 (например, добавится
новый индикатор), обнови и V02-шаблон выше.
