# fst-project-health-tests

**Версия:** 1.0.19 — 2026-09-24

Набор автоматических тестов для семейства `fst-project-health-*`. Раннер
вызывает по группам (чтобы не было таймаутов на полном прогоне).

---

## Быстрый старт

```bash
cd ~/.hermes/profiles/fst-control/skills/productivity/fst-project-health-tests

# Список групп:
python3 run_all_tests.py --list

# Запустить одну группу (5 мин):
python3 run_all_tests.py --group mcp

# Все группы (10 мин, может таймаутить):
python3 run_all_tests.py

# Без MCP-тестов:
python3 run_all_tests.py --no-mcp
```

---

## Группы тестов

| Группа | Что проверяет | Время |
|---|---|---|
| `regression` | Уровень 1: live-прогон run_all.py, структура HTML, SHA256 | ~30 с |
| `mcp` | Уровень 4: MCP write/read (16 тестов), требует TEST_PROJECT_CODE | ~70 с |
| `snap_md` | Уровень 2: генератор + логирование (9 тестов) | ~110 с |
| `from_md` | Уровень 3: извлекатель + логирование (15 тестов) | ~110 с |
| `cross_skill` | Уровень 5: цепочка generator→reader→HTML | ~10 с |
| `invariants` | Уровень 6: 4 инварианта устойчивости (статический анализ) | ~1 с |

**Всего:** 50 тестов в 6 группах.

---

## Зачем нужны отдельные группы

Полный прогон всех 50 тестов занимает 5–10 минут и **может таймаутить** на
больших карточках. Разделение на группы позволяет:

- Прогонять в cron **по группам в разные дни/часы** — например,
  regression в воскресенье 3:00, snap_md в 4:00, from_md в 5:00.
- Быстро проверить только нужную часть (например, после правки
  извлекателя — запустить `from_md`).
- Не блокироваться на MCP-flake — если MCP flake в `mcp`, остальные
  группы всё равно работают.

## Тестовый проект (TEST_PROJECT_CODE)

По умолчанию тесты MCP-группы используют код `504-595` (наш рабочий
проект «Космодром Жуковский»). Чтобы изменить:

```python
# tests/test_project.py
TEST_PROJECT_CODE = "504-595"   # ← измените на свой код
```

Если:
1. `TEST_PROJECT_CODE = None` — все MCP-тесты **SKIP**.
2. Код не соответствует формату `NNN-NNN` — все MCP-тесты **SKIP**.
3. Код указан, но нет доступа к карточке — все MCP-тесты **SKIP**.

## Логирование

Каждый прогон `run_all_tests.py` дописывает результаты в
`logs/tests.log` (накопительно). Каждый запуск = отдельная секция
`=== TESTS RUN @ ISO-timestamp ===` с per-test строками.

### Ротация логов

Логи **не ротируются сами**. За это отвечает отдельный скрипт
`scripts/rotate_logs.py` (можно ставить в cron).

Политика (v1.0.19):
- **> 100 дней** (≈3.3 месяца) → gzip + `logs/archive/YYYY-MM/`
- **> 400 дней** (≈13.3 месяцев) → удалить

```bash
# Боевой прогон:
python3 scripts/rotate_logs.py

# Только показать план:
python3 scripts/rotate_logs.py --dry-run

# С другой политикой:
python3 scripts/rotate_logs.py --archive-days 30 --delete-days 180
```

Зачем нужен ротатор:
- Без ротации `logs/tests.log` растёт ~37 KB на прогон. При еженедельном
  cron через год будет 1.5 MB и сотни секций.
- Ротатор держит в `logs/` только последние ~3 месяца, в `archive/` — год.

Cron-пример (ежедневно в 04:00):
```cron
0 4 * * * cd /root/.hermes/profiles/fst-control/skills/productivity/fst-project-health-tests && python3 scripts/rotate_logs.py
```

**Важно:** другие скиллы (`fst-project-health-snap-md`,
`fst-project-health-from-md-snapshot`) имеют собственные `rotate_logs.py`
с **другой** политикой (400d/1500d). Это намеренно — тестовые логи
короткоживущие, им не нужен долгий архив.

## Логи

- `logs/tests.log` — общий лог по всем прогонам (накапливается).
- Каждый запуск добавляет блок `=== TESTS RUN @ ... ===` с per-test результатами.

---

## Коды возврата

| Код | Что значит |
|---|---|
| 0 | Все тесты PASSED (или SKIPPED, но не FAILED) |
| 1 | Есть хотя бы один FAILED |
| 2 | Все MCP-тесты SKIPPED (тестовый проект не настроен) |

Cron-friendly: код 0 = OK, ≠0 = проблема.
