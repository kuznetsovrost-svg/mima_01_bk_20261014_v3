**Дата:** 2026-09-02
**Скилл:** `fst-project-health` v1.0.0

---

## Концепция

Индикатор 6.2 проверяет **СКРЫТУЮ НЕАДЕКВАТНОСТЬ** указанного в карточке состояния ЖЦ проекта. Цель — выявить ситуации, когда:
- стадия проекта указана одна
- а фактическое состояние данных (КТ в календарном плане) — другое
- это значит пользователь не перевёл проект в нужное состояние

**Результат: `"Да <Стадия>"` или `"Нет <Стадия>"`** (стадия выводится для справки).

**Вердикт секции:** агрегат по подпунктам (Норма / Информационное / Существенное / Критическое).

---

## Шаг 1: Пресейл + пустой проект = Норма

### Ситуация

| Параметр | Значение |
|----------|----------|
| Стадия ЖЦ | Пресейл (обязательно — система блокирует перевод) |
| КТ обязательные (Пресейл) | ❌ нет ни одной |
| Календарный план | ❌ нет (КТ и работы не созданы) |
| Причина | пользователь только создал проект, не завёл данные |

### Оценка

| Поле | Значение |
|------|----------|
| Результат | `"Да Пресейл"` |
| Вердикт | **Норма** |
| Замечания | нет (▼ не показывается) |

### Логика

Пользователь **не ведёт** проект или **не успел** завести данные — это **стартовое состояние**, не нарушение. Система **не даст** перевести проект в следующее состояние ЖЦ пока КТ Пресейла не будут созданы, так что стадия = Пресейл = корректна.

### Правило

**Отсутствие обязательных КТ в справочнике для текущей стадии → не показывать как замечание**, если у текущей стадии `stage_index = 0` (т.е. это первая стадия ЖЦ).

```python
# Только КТ предыдущих стадий (если проект УЖЕ должен был их пройти)
if kt_stage_idx < current_stage_idx:
    table.append({"remark": "Не создана КТ '...'", ...})
```

## Шаг 2: Есть КТ в плане + не все обязательные созданы = Существенное

### Ситуация

| Параметр | Значение |
|----------|----------|
| Стадия ЖЦ | Пресейл |
| КТ обязательные (Пресейл) | ❌ нет ни одной (или не все из 3) |
| Календарный план | ✅ есть ("второстепенные" КТ) |

### Проблема

Пользователь **нарушил правила** ведения проекта: прежде чем вводить "второстепенные" КТ, нужно задать сроки обязательных КТ.

### Оценка

| Поле | Значение |
|------|----------|
| Результат | `"Нет Пресейл"` |
| Вердикт | **Существенное** |
| Severity | substantial |
| Замечания | список **отсутствующих** обязательных КТ |

### Формат замечания

```
Не создана КТ 'Пресейл открыт' (требуется для стадии 'Пресейл')
Не создана КТ 'Пресейл закрыт' (требуется для стадии 'Пресейл')
Не создана КТ 'Направлено предложение Заказчику' (требуется для стадии 'Пресейл')
```

### Уточнённая логика (после коррекции пользователя)

Срабатывает когда **не ВСЕ** обязательные КТ есть (не только когда ни одной нет):

```python
# Шаг 2: НЕ ВСЕ обязательные КТ есть (при наличии других КТ в плане)
# В замечаниях показываем только отсутствующие
missing_mandatory = [m for m in mandatory if m not in present_mandatory]
if missing_mandatory:
    for m in missing_mandatory:
        issues.append({
            "type": "mandatory_kt_missing",
            "kt_name": m,
            "stage": actual_stage,
            "severity": "substantial",
        })
```

### Матрица срабатывания

| КТ обязательные | КТ в плане (любые) | Шаг 2 |
|-----------------|---------------------|:-----:|
| 0 из 3 | да | ✅ (3 замечания) |
| 1 из 3 | да | ✅ (2 замечания — недостающие) |
| 2 из 3 | да | ✅ (1 замечание — недостающая) |
| 3 из 3 | да | ❌ (нет замечаний) |
| *любое* | нет (пусто) | ❌ (Шаг 1) |

## Шаг 3: Обязательная КТ просрочена = Критическое

### Ситуация

| Параметр | Значение |
|----------|----------|
| Стадия ЖЦ | любая |
| Обязательная КТ | существует в плане, НЕ выполнена (нет `FactDate`) |
| ForecastDate | < today |

### Оценка

| Поле | Значение |
|------|----------|
| Результат | `"Нет <Стадия>"` |
| Вердикт | **Критическое** |
| Severity | critical |

### Формат замечания (для каждой просроченной КТ)

```
Просрочена обязательная КТ 'Пресейл открыт', 15 дн.
```

### Условие срабатывания (после двух коррекций пользователя)

КТ просрочена ТОЛЬКО если она **НЕ выполнена** (нет `FactDate`). Подтверждение согласующим — это **отдельная проблема**, не влияет на просрочку:

```python
# КТ просрочена ТОЛЬКО если нет FactDate
if fact_date:
    continue  # КТ выполнена → не просрочена
```

### Матрица состояний и просрочка

| Состояние КТ | FactDate есть? | Просрочка? |
|--------------|:--------------:|:----------:|
| "В работе" | ❌ нет | ✅ да если ForecastDate < today |
| "Выполнена" | ✅ есть | ❌ нет |
| "Подтверждена" | ✅ есть | ❌ нет |
| "Отменено" | (любое) | ❌ нет |

### Важно (после коррекции пользователя)

> "Опять неправильно! КТ просрочена если НЕ выполнена (Не подтверждена - это проблема другого рода!)"

"Подтверждена" / "Выполнена" — это **закрыто** (есть факт.дата). Даже если согласующий не подтвердил — КТ уже не просрочена (другая проблема, другой шаг).

## Реализация

Логика всех шагов — в `scripts/lc_stage_kt_registry.py::heuristic_evaluate()`.

| Шаг | severity | issue type | message format |
|:---:|:--------:|------------|----------------|
| 1 | Норма | — | — |
| 2 | substantial | `mandatory_kt_missing` | `"Не создана КТ '<X>' (требуется для стадии '<Y>')"` |
| 3 | critical | `mandatory_kt_overdue` | `"Просрочена обязательная КТ '<X>', <N> дн."` |

## Тестовые сценарии

```python
# Шаг 1: пустой проект в Пресейле → Норма, 0 замечаний
heuristic_evaluate("Пресейл", [])

# Шаг 2: КТ в плане, нет обязательных → Существенное, 3 замечания
heuristic_evaluate("Пресейл", ["Маркетинговые материалы предоставлены"])

# Шаг 2a: одна обязательная из 3 → 2 замечания (только недостающие)
heuristic_evaluate("Пресейл", ["Пресейл открыт"])

# Шаг 2b: все обязательные → 0 замечаний
heuristic_evaluate("Пресейл", ["Пресейл открыт", "Пресейл закрыт", "Направлено предложение Заказчику"])

# Шаг 3: обязательная КТ просрочена → Критическое
heuristic_evaluate("Пресейл", ["Пресейл открыт"],
    kt_with_fact_dates=[{"name": "Пресейл открыт", "FactDate": None, "ForecastDate": "2026-08-15"}],
    kt_with_approvers=[{"name": "Пресейл открыт", "FactDate": None, "ApproverConfirmed": False}])
# → "Просрочена обязательная КТ 'Пресейл открыт', N дн." (critical)
```
