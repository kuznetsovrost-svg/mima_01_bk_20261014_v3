## Что не перенесено и почему

### Hero-блок (Header раздел 1)

В AGPM Hero — отдельная визуальная секция с градиентом, eyebrow,
meta-чипами. По запросу пользователя «примени настройки HERO к разделу 1
Header» — **перенесли**: Header теперь = Hero.

| Hero-элемент | AGPM значение | Применено в Header | Куда |
|---|---|---|---|
| Фон (gradient) | `linear-gradient(135deg, --navy 0%, --hero-middle 56%, --teal 100%)` | ✅ | `.report-header-text`, `.report-indicator` |
| Eyebrow цвет | `--hero-eyebrow = #d7b76a` | ✅ | `.report-header-prefix` (есть в вёрстке как «Target» над заголовком) |
| Eyebrow стиль | `text-transform: uppercase; letter-spacing: 0.5px` | ✅ добавлено | `.report-header-prefix` |
| Meta текст | `rgba(255,255,255,0.82)` | ✅ | `.report-header-meta` |
| Meta `<b>` | `#ffffff` | ✅ | `.report-header-meta b` |
| Тень | `0 20px 44px rgba(16,24,40,0.16)` | ✅ | `.report-header` |
| Decision-блок (border-left gold) | `6px solid var(--gold)` | ❌ нет в нашем отчёте | — |

`--gold` (`#c89b3c`) и `--teal` (`#075f6b`) объявлены как переменные, но
**не используются** в правилах: в нашем отчёте нет decision-блока,
нет отдельного teal-акцента.

### AGPM `--blue` и `--soft`

В AGPM есть `--blue: #1366D6` (ссылки) и `--soft: #EEF4FF` (мягкая
информационная подложка). **Не перенесены** — в `report.css` есть
собственные `#2563EB` (для ссылок, не использовался) и `#DBEAFE`
(informational фон). Перенос не нужен: для нашего отчёта достаточно
того, что есть.

### AGPM 4-статусная модель (green / yellow / red / gray)

В AGPM 4 семантических статуса. В нашем отчёте **5 возможных фонов
строки** (critical / substantial / informational / normal /
`verdict="Норма"` без выделения). Решение пользователя от 2026-09-15:

- `informational` (синий `#dbeafe`) **остаётся как 5-й статус** в
  секции 6 — это отступление от AGPM 4-статусной модели.
- AGPM `--gray-bg/text` добавлены как переменные, но в текущих правилах
  не используются (нет «нет данных» статуса в отчёте — показывается
  через `verdict="Норма"` с белым фоном).

### Severity-фоны индикатора (sick / attention / healthy / unknown)

Это **радиальные градиенты** для круглого индикатора, не плоские
фоны строк. В AGPM нет аналога (там только badge-цвета). Оставлены
как есть:

| Статус | Градиент (текущий) | AGPM эквивалент |
|---|---|---|
| `sick` | `#fca5a5 → #ef4444 → #dc2626` | `--bad` (`#b42318`) — сплошной |
| `attention` | `#fde68a → #f59e0b → #d97706` | `--mid` (`#946200`) — сплошной |
| `healthy` | `#86efac → #22c55e → #16a34a` | `--good` (`#0f7a5f`) — сплошной |
| `unknown` | `#d1d5db → #9ca3af → #6b7280` | `--gray` (`#64748b`) — сплошной |

**Не перенесено** потому что:
- В AGPM индикатор — это badge (плоский цвет + текст), в нашем — это
  круглый индикатор с радиальным градиентом.
- Палитра badge-bg AGPM (green/yellow/red/gray) и палитра градиента
  индикатора разные по концепции (сплошной цвет vs градиент).

## Сводка: токены, объявленные в `:root`

Полный список CSS-переменных, добавленных в начало `templates/report.css`:

```css
:root {
  /* AGPM базовая */
  --bg: #f5f7fb;
  --paper: #ffffff;
  --ink: #101828;
  --muted: #667085;
  --line: #d9e0ea;
  /* AGPM Hero */
  --navy: #071b3a;
  --hero-middle: #09315c;
  --teal: #075f6b;
  --gold: #c89b3c;
  --hero-eyebrow: #d7b76a;
  /* AGPM таблицы */
  --table-head: #0b2145;
  --table-alt: #fbfcff;
  /* AGPM семантика */
  --good: #0f7a5f;
  --mid: #946200;
  --bad: #b42318;
  --gray: #64748b;
  /* AGPM badge */
  --green-bg: #dcfce7;   --green-text: #166534;
  --yellow-bg: #fef3c7;  --yellow-text: #92400e;
  --red-bg: #fee2e2;     --red-text: #991b1b;
  --gray-bg: #f1f5f9;    --gray-text: #475569;
}
```

Из них **используются в текущих правилах CSS**:

- `--bg` — body background
- `--paper` — зарезервирован (карточки пока на `#ffffff` явно, миграция не делалась)
- `--ink` — body color + таблицы
- `--line` — сетка основных таблиц (`#cbd5e1` → `var(--line)`)
- `--navy` — маркер ▼ (был `#1e40af`)
- `--hero-middle`, `--teal` — gradient в Header
- `--hero-eyebrow` — eyebrow в Header

**Не используются** (объявлены для будущего): `--paper`, `--muted`,
`--gold`, `--table-head`, `--table-alt`, `--good`, `--mid`, `--bad`,
`--gray`, `--green-bg/text`, `--yellow-bg/text`, `--red-bg/text`,
`--gray-bg/text`.

## Что НЕ пытаться сделать (anti-patterns)

1. ❌ **Не пытаться** привести ВСЕ 18 AGPM-токенов к активному использованию
   за один проход. Часть токенов объявлена «на будущее» (--gold, --teal,
   --good, --mid, --bad, --gray, --green*, --table-*).
2. ❌ **Не пытаться** заменить все старые hex в `report.css` на AGPM-токены
   «ради консистентности». Если старый hex нет в AGPM (например,
   `#D1CFD7`, `#FAFAFA`, `#1E40AF` остался в 2 местах) — **оставить как
   есть**. Иначе рискуем сломать правила, которые работают.
3. ❌ **Не применять** AGPM-палитру к секции 6 «Показатели проекта»
   как замену severity-фонов. Severity — это семантика отчёта, а не
   палитра reference-документа. Severity-фоны (`#fee2e2 / #fef3c7 /
   #dbeafe / #ffffff`) совпадают с AGPM случайно (для yellow/red),
   и это **нормально** — AGPM просто использует те же базовые
   Tailwind-оттенки.

## Контрольные вопросы (при следующей правке палитры)

1. Есть ли в `:root` ВСЕ токены, которые встречаются в эталоне?
2. Каждое правило CSS, использующее старый hex, либо обновлено на
   `var(--<token>)`, либо явно оставлено со старым значением и комментарием
   «не имеет аналога в AGPM»?
3. Если пользователь говорит «верни как было для Y» — могу ли я по diff
   в `report.css` точно откатить **только** Y, не трогая остальное?
4. Для каждого токена `--<X>` из эталона, который не используется в
   правилах — есть ли он действительно в `:root`? (Если да — зачем
   объявлен без применения? Либо применить, либо удалить.)
