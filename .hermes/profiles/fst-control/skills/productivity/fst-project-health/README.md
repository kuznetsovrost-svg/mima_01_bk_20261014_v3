# fst-project-health

**Версия:** 1.0.19
**Для кого:** коллеги, которые получают этот скилл впервые, и агенты, которые будут его вызывать или поддерживать.
**Что это:** генератор отчёта о здоровье проекта (разделы 3–8) из данных PMForesight MCP.

---

## Что это за скилл — одним абзацем

`fst-project-health` — основной исполнитель отчёта о состоянии проекта из PMForesight. По коду проекта (например, `504-595`) он:

1. Подключается к PMForesight MCP и собирает данные (КТ, бюджет, трудозатраты, платежи, методиатал).
2. Прогоняет **16 показателей** (раздел 6 «Показатели проекта») и **3 финансовых показателя** (раздел 7 «Финансовый статус»).
3. Собирает **MD-отчёт** — это полный source of truth, всё что в HTML, есть в MD (`/tmp/project_<CODE>_report.md`).
4. Из MD рендерит **HTML-отчёт** для человека (`/tmp/project_<CODE>_report.html`).
5. WORD/DOCX генерится **отдельным скиллом** `fst-project-health-word` (опционально, по запросу).

**Принципиально:** MD самодостаточен. HTML рендерится из MD без обращения к MCP. Это позволяет строить исторические отчёты «как тогда выглядел проект» из MD-снапшотов.

## Когда загружать

Загружай этот скилл, если пользователь просит:

- «Отчёт о здоровье проекта», «health of project», «статус проекта 504-595».
- Показ конкретной секции: «покажи секцию 6», «раздел 6.7», «бюджет проекта».
- Диагностика отставания: «почему проект отстаёт по срокам?», «есть ли перерасход?».

Скилл **НЕ загружается** для:

- Исторических отчётов из MD-снапшотов — это делает `fst-project-health-snap-md` (сохранение) + `build_html_report.py --md PATH` (рендер без MCP).
- Трендовых отчётов по неделям — `fst-project-health-snapshot` (JSON для построителя трендов).
- Word-версии — отдельный `fst-project-health-word`.

## Использование

### Способ 1: через Hermes Agent (рекомендуемый)

Сказать: «сделай отчёт о здоровье проекта 504-595». Агент сам:

1. Запустит `scripts/run_all.py --code 504-595`.
2. Получит `/tmp/project_<CODE>_report.md` и `/tmp/project_<CODE>_report.html`.
3. Отправит файлы в чат.

### Способ 2: ручной запуск из CLI

```bash
# Полный прогон: MD + HTML
python3 ~/.hermes/profiles/fst-control/skills/productivity/fst-project-health/scripts/run_all.py \
    --code 504-595

# Без HTML (только MD — быстрее, удобно для снапшотов)
python3 .../run_all.py --code 504-595 --no-html

# Игнорировать кеш MCP (для теста, что данные свежие)
python3 .../run_all.py --code 504-595 --no-cache

# Только HTML из готового MD (для исторических отчётов)
python3 .../scripts/build_html_report.py --md /path/to/snapshot.md
```

### Флаги `run_all.py`

| Флаг | Что делает |
|---|---|
| `--code <CODE>` | **обязателен.** Код проекта, например `504-595`. |
| `--no-cache` | Игнорировать кеш MCP (по умолчанию кеш живёт 5 минут). |
| `--no-html` | Пропустить HTML-рендер, оставить только MD. |
| `--sections "3,4,5"` | Построить только указанные секции. |
| `--generator <NAME>` | Имя генератора для YAML front-matter (для атрибуции). По умолчанию `fst-project-health`. Сателлиты передают своё имя, например `fst-project-health-snap-md`. |
| `--timing` | Показать время по стадиям pipeline. |

```
├── .env.example        # шаблон PMP_TOKEN=<jwt>
├── scripts/

├── templates/
│   ├── report.html    # шаблон HTML-отчёта (с маркерами {{ section_* }})
│   ├── report.css     # стили (CSS-only details/summary, ::-webkit-details-marker)
│   └── styles.css     # дополнительные стили
├── references/        # 79 файлов: pitfalls, секции, таблицы, темы (по вызову)
├── tests/             # 14 тестов: pytest-стиль, не требуют живого MCP
└── project-search/    # дополнительный скилл "найти проект по коду/имени"
```

## Что умеет — содержательно

### Разделы отчёта (нумерация совпадает в MD и HTML)

| Раздел | Содержимое | Источник |
|---|---|---|
| **3. Замечания по срокам** | КТ с просроченными прогнозами, критические/существенные/информационные | `Point/AllMyPoint` |
| **4. Полнота заполнения** | Куратор, РП, паспорт, трудозатраты, график платежей | `Project/MyProject` + `get_effort` + `get_project_budget` |
| **5. Актуальность прогнозов** | КТ с устаревшими прогнозами (план/прогноз/просрочка) | `Point/AllMyPoint` |
| **6. Показатели проекта** | **16 показателей** (юрлицо, ЖЦ, прогнозы, плановые, перегрузка, роли, сроки фин. КТ, бюджет, НДС, метки КП...) | см. ниже |
| **7. Финансовый статус** | Прогноз фин.результата, Δ текущей стоимости, Δ прогноза от плана | `Project/ProjectHealthCostMy` |
| **8. Технические данные** | Пользователь (из JWT), версии скилла/MCP/Core | `get_metamodel` |
| **9. Индикатор (сводка)** | Сводный вердикт + таблица по 6 разделам | агрегат |

### 16 показателей раздела 6

| № | Что | Когда заполнено |
|---|---|---|
| 6.1 | Юрлицо проекта/пресейла | всегда |
| 6.2 | Актуальность состояния ЖЦ | всегда |
| 6.3 | Прогнозы по ресурсам заданы | если есть ресурсы |
| 6.4 | Плановые трудозатраты заданы | если есть план |
| 6.5 | Прогнозы не превышают 100% | если есть прогнозы |
| 6.6 | Нереализованные прогнозы по ролевым | если есть роли |
| 6.7 | Исполнители с превышением > 100% | если есть исполнители |
| 6.8 | Соблюдение сроков фин. КТ | если есть фин. КТ |
| 6.9 | Суммы актов и оплат | если есть платежи |
| 6.10–6.11 | Прямые затраты, НДС | если есть бюджет |
| 6.12 | Сумма НДС расчётная | если есть НДС |
| 6.13 | Бюджет проекта/пресейла | если есть бюджет |
| 6.14 | Расход лимита пресейла | если есть пресейл |
| 6.15 | Утверждённый бюджет | если есть |
| 6.16 | Метки КП (пресейл/проект) | всегда |

### 7 показателей (6.3, 6.4, 6.6, 6.7, 6.8, 6.15, 6.16) могут иметь вложенную таблицу

В HTML это раскрывающийся блок `▼` — клик показывает детальные строки.

## Архитектурные гарантии (важно для понимания)

**MD = полный source of truth.** Любая таблица, число, вердикт в HTML присутствуют в MD. Это даёт:

- **Исторические отчёты:** «как выглядел проект 504-595 2026-09-21?» — читаем MD-снапшот, рендерим HTML, не дёргая MCP.
- **Самодостаточный снапшот:** один MD-файл содержит всю нужную информацию для последующего HTML-рендера.

**HTML не обращается к MCP.** `build_html_report.py` работает только с MD + YAML front-matter. Никакого `mcp_call(get_view, ...)` в HTML-движке.

**`rebuild_report.py` собирает ВСЕ файлы**, на которые ссылается HTML. Если пропустил — HTML сломается. Это защита от регрессий.

**Каждый caller `run_all.py` передаёт `--generator <свой>`** — чтобы в YAML-атрибуции было видно, кто сгенерировал (живой прогон / снапшот / другое).

**Нумерация разделов в MD и HTML совпадает:** 3/4/5/6(показатели)/7(финансы)/8(тех)/9(сводка).

## Установка

```bash
# 1. Уже стоит в fst-control профиле; на новом сервере:
scp -r fst-project-health/ user@server:/opt/skills/

# 2. Зависимости (минимальные — только requests)
pip install -r requirements.txt

# 3. .env
cp .env.example .env
nano .env   # PMP_TOKEN=<jwt-токен от PMForesight>

# 4. Проверка
python3 scripts/run_all.py --code 504-595
```

## Что **НЕ** делает

- ❌ Не пишет в MCP (read-only по своей сути).
- ❌ Не строит WORD — это отдельный скилл `fst-project-health-word`.
- ❌ Не сохраняет исторические срезы — это `fst-project-health-snap-md`.
- ❌ Не рисует тренды — это `fst-project-health-snapshot` (JSON) + будущий построитель трендов.

## Связь с другими скиллами

```
fst-project-health (этот)
   │
   ├─→ PMForesight MCP (read-only запросы)
   │
   ├─→ fst-project-health-word       (опционально: MD→DOCX)
   ├─→ fst-project-health-snap-md    (сохранение MD в карточку MCP)
   ├─→ fst-project-health-snapshot   (сохранение JSON в карточку MCP, для трендов)
   └─→ fst-project-health-from-json  (исторические отчёты из JSON)
```
