# Переезд на другой MCP-сервер Форсайт

## Вопрос (от пользователя)

> Теперь хочу уточнить: чтобы изменить вызов MCP сервера мне нужно теперь поправить скрипт mcp_config.py и config.yaml в профиле. И всё. Правильно?

## Ответ (от Hermes)

Не совсем. Уточню что где.

### Что и где править при смене MCP-сервера

| Что меняется | Где править | Нужно ли менять? |
|--------------|-------------|------------------|
| **URL сервера** (`ppreplica.hera.pmpractice.ru` → другой) | `mcp_config.py` (для Python-скриптов) **+** `config.yaml → mcp_servers.fst_pmpractice.url` (для Hermes-MCP-клиента) | **Оба места** |
| **Только URL для Python-скриптов** | `mcp_config.py → MCP_URL` | Одно место |
| **Только URL для Hermes-агента** | `config.yaml` | Одно место |
| **JWT-токен** | `~/.hermes/profiles/fst-control/.env → PMP_TOKEN=*** | Одно место |
| **Таймауты** | `mcp_config.py` (`TIMEOUT_INITIALIZE`, `TIMEOUT_TOOLS_CALL`) **+** `config.yaml` (`timeout`, `connect_timeout`) | **Оба места** (для Hermes-агента и Python-скриптов) |
| **Заголовки (например новый auth scheme)** | `mcp_config.py → headers_for_call()` **+** `config.yaml → mcp_servers.fst_pmpractice.headers` | **Оба места** |
| **Путь к .env** | `mcp_config.py → ENV_FILE` | Одно место |

### Почему два места, а не одно

В скилле **два независимых** пути вызова MCP:

```
┌─────────────────────────────────────────────────────────┐
│ Путь 1: Hermes-MCP-клиент (агентский)                   │
│                                                         │
│  SKILL.md → mcp__fst_pmpractice__get_view(...)           │
│         ↓                                               │
│  Hermes runtime подставляет URL и токен из config.yaml   │
│         ↓                                               │
│  HTTP POST → MCP-сервер                                 │
│                                                         │
│  Настройка: ~/.hermes/profiles/fst-control/config.yaml   │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│ Путь 2: Python-скрипты (прямой JSON-RPC)                │
│                                                         │
│  find_project_by_code.py                                │
│       ↓                                                 │
│  import mcp_config (MCP_URL, require_token, ...)         │
│       ↓                                                 │
│  HTTP POST → MCP-сервер                                 │
│                                                         │
│  Настройка: scripts/mcp_config.py                       │
└─────────────────────────────────────────────────────────┘
```

Оба пути живут **независимо** — это by design. Если ты используешь **только Python-скрипты** (через `/tmp/run_section_*.py`), то достаточно `mcp_config.py` + `.env`. Если ты ещё и вызываешь `mcp__fst_pmpractice__*` через Hermes-агента — тогда нужен ещё и `config.yaml`.

### Минимальный набор для смены сервера

| Сценарий | Что править |
|----------|-------------|
| **Только Python-скрипты** | `mcp_config.py` (URL) + `.env` (токен) |
| **Только Hermes-агент** | `config.yaml` (URL) + `.env` (токен) |
| **Оба пути** (наш случай) | `mcp_config.py` (URL) **+** `config.yaml` (URL) **+** `.env` (токен) |

### Где **ещё** могут быть захардкодены URL/настройки

Проверил что в других 17 справочных выдержках нет hardcoded URL. Результат:

- `mcp_config.py:52` — `MCP_URL: str = "https://ppreplica.hera.pmpractice.ru/mcp"` — это **основной источник истины** для Python-скриптов.
- `mcp_probe.py:47` — строка документации (`--url URL MCP endpoint (по умолчанию https://...)`). Реальное значение `DEFAULT_URL` импортируется из `mcp_config`.

**Все чисто**. URL захардкоден **только в одном функциональном месте** (плюс строка help-text в `mcp_probe.py`).

### Резюме: правильно ли «поправить mcp_config.py + config.yaml»

**Почти правильно**, но нужно ещё `.env` для токена:

| Что | Где |
|-----|-----|
| URL Python-скриптов | `mcp_config.py` |
| URL Hermes-агента | `config.yaml` |
| JWT-токен | `.env` (`PMP_TOKEN=***`) |

Если ты переезжаешь на новый сервер с **новым токеном** (например, prod-сервер вместо replica), то **3 места**:

1. `scripts/mcp_config.py → MCP_URL` — URL для Python-скриптов.
2. `config.yaml → mcp_servers.fst_pmpractice.url` — URL для Hermes.
3. `.env → PMP_TOKEN=***` — токен (для обоих путей).

Если ты переезжаешь на новый сервер с **тем же токеном** (например, dev-инстанс той же системы), то **2 места**:

1. `scripts/mcp_config.py → MCP_URL`.
2. `config.yaml → mcp_servers.fst_pmpractice.url`.

И ещё одно замечание: **заголовок Authorization** может отличаться между серверами (например, `Bearer` vs `Basic`, или кастомная схема). Если меняется — надо править и `mcp_config.py → headers_for_call()`, и `config.yaml → mcp_servers.fst_pmpractice.headers`. Но это редкий случай.
