# PLAYBOOK — fst-project-health-tests

**Версия скилла:** v1.0.19
**Дата PLAYBOOK:** 2026-09-24
**Назначение:** автоматическое тестирование всего семейства `fst-project-health-*` (6 групп, 50 тестов).

---

## 1. Общий обзор

`fst-project-health-tests` — **тестовый скилл**. Запускает проверки всех скиллов семейства: регрессию, MCP, snap-md, from-md-snapshot, cross-skill, инварианты.

```
run_all_tests.py [--group X] → PASSED / FAILED / SKIPPED
```

**Тестов:** 50 (распределены по 6 группам).
**Свой раннер:** `run_all_tests.py` (**НЕ pytest**) — потому что нужны кастомные политики (транзиентные ошибки MCP, политика SKIP).
**MCP-тесты включены по умолчанию** (по запросу пользователя: «все наши скиллы без работающего MCP немного стоят»).
**Тестовый проект:** НЕ хардкодить — отдельный скрипт `test_project.py`.

## 2. API скилла

### 2.1. CLI-параметры `run_all_tests.py`

```bash
python3 run_all_tests.py [--group <GROUP>] [опции]
```

| Параметр | Обязательный | Описание |
|---|---|---|
| `--group <GROUP>` | ❌ | Запустить только одну группу (см. 2.2). Без флага — все группы. |
| `--log` | ❌ | Включить логирование в файл (по умолчанию — без лога; лог только для CI/cron). |
| `--log-dir <DIR>` | ❌ | Куда писать лог (по умолчанию `<skill>/logs/`). |
| `--project <CODE>` | ❌ | Переопределить тестовый проект (по умолчанию из `test_project.py`). |

### 2.2. Группы тестов

| Группа | Тестов | Назначение | Зависит от MCP? |
|---|---|---|---|
| `regression` | 3 | Базовые проверки: HTML из MD = live, ключевые слова, размер | ❌ |
| `mcp` | 17 | MCP write/read round-trip (upload → list → download) | ✅ |
| `snap_md` | 9 | Генерация слепков, логирование, never-fail | ✅ |
| `from_md` | 15 | Извлечение снапшотов, режимы выбора, HTML из MD | ✅ |
| `cross_skill` | 4 | Кросс-скилл сценарии (цепочки) | ✅ |
| `invariants` | 6 | Статический анализ кода (try/except, never-fail) | ❌ |

## 3. Тестовый проект

Файл: `tests/test_project.py`

```python
# Можно переопределить при переносе на другой стенд.
TEST_PROJECT_CODE = "504-595"
TEST_PROJECT_NAME = "Космодром Жуковский внедрение ИСУП"
```

**Поведение при недоступности тестового проекта:**

| Ситуация | Что произойдёт |
|---|---|
| Проект **не указан** (пусто) | Группа **SKIPPED** целиком |
| Проект **с опечаткой** (404) | Группа **SKIPPED** целиком |
| Проект **указан, но нет доступа** (403) | Группа **SKIPPED** целиком |

Это требование пользователя: «если проект не указан / указан с ошибкой / указан но нет доступа — то эта группа тестов не запускается (пропускается)».

## 4. Устойчивость к MCP flake

### 4.1. Декоратор `@_transient_safe`

Все 17 функций в `tests/test_02_mcp.py` обёрнуты декоратором `@_transient_safe`:

```python
@_transient_safe
def test_4_13_contentmode_bytes_url():
    """contentMode=bytes/url"""
    ...
```

**Логика:**
- Если ответ `ReadTimeout` или `ConnectionError` — **retry 3 раза** с экспоненциальной задержкой.
- Если **2 из 3** попыток транзиентные → тест **SKIPPED** (не FAILED).
- Это защищает от flake при работающем MCP, но с временными проблемами сети.

### 4.2. Функции-хелперы

- `_retry_mcp(fn, max_attempts=3, delay=2)` — обёртка с retry.
- `_is_transient(exc)` — определяет, транзиентная ли ошибка.
- `_is_mcp_bug(exc)` — определяет, баг ли это MCP (а не наш код).

## 6. Методы скилла (для переиспользования)

### 6.1. `run_all_tests.py::main()`

- **Назначение:** CLI-точка входа.
- **Параметры:** см. раздел 2.1.

### 6.2. `run_all_tests.py::TestRunner.run()`

- **Назначение:** запуск одной группы тестов.
- **Параметры:** `group: str`.
- **Когда переиспользовать:** для CI-пайплайна.

### 6.3. `_helpers.py::_transient_safe` (декоратор)

- **Назначение:** обёртка для тестов с устойчивостью к flake.
- **Когда переиспользовать:** в **любых** MCP-тестах, где возможны ReadTimeout.

### 6.4. `_helpers.py::_retry_mcp()`

- **Назначение:** retry для MCP-вызовов.
- **Параметры:** `fn: Callable`, `max_attempts: int = 3`, `delay: int = 2`.
- **Когда переиспользовать:** в продакшен-коде для устойчивости MCP-операций.

### 6.5. `_helpers.py::_is_transient()`

- **Назначение:** определяет транзиентные ошибки (ReadTimeout, ConnectionError).
- **Когда переиспользовать:** в error-handlers.

### 6.6. `scripts/rotate_logs.py::rotate()`

- **Назначение:** архивация старых логов тестов.
- **Политика:** >100 дней → gzip → archive, >400 дней → delete.
- **Когда запускать:** через cron раз в сутки.

## 7. Логирование

**Включено по умолчанию `--log`** (выключено по умолчанию). Используется для CI/cron.

Файлы логов: `<skill>/logs/tests.log` (один большой файл, дописывается).

**Политика ротации** (отличается от других скиллов):
- >**100 дней** → gzip → `archive/`.
- >**400 дней** → delete.

Это **намного дольше**, чем у других скиллов (30/180), потому что тесты — это **история**, а не оперативный лог.

### 7.1. Пример вызова

```bash
# Без лога (разовый прогон)
python3 run_all_tests.py --group regression

# С логом (CI/cron)
python3 run_all_tests.py --log

# Только invariants (быстро)
python3 run_all_tests.py --group invariants
```

### 7.2. cron

```cron
# Тесты раз в сутки в 04:00, с логом
0 4 * * * cd ~/.hermes/.../fst-project-health-tests && python3 run_all_tests.py --log
```

## 8. Тесты в каталогах `tests/` других скиллов

**ВАЖНО:** в скиллах `fst-project-health`, `fst-project-health-snap-md`, `fst-project-health-from-md-snapshot` есть **локальные** `tests/` каталоги — для автономности и переиспользуемости. Они **не имеют собственного логирования** (по требованию пользователя: «кому нужен лог - тот пусть запускает отдельный скилл тестирования»).

То есть:
- Локальные `tests/` в скиллах → автономные, без лога, можно запускать прямо в скилле.
- `fst-project-health-tests/run_all_tests.py` → **главный**, с логом, с ротацией.
