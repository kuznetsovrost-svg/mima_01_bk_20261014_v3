# Style Guide for mi_mg_01 outputs

Применяется ко всем файлам, которые генерирует профиль `mi_mg_01`.
Привязка к пользователю: см. `~/.hermes/profiles/mi_mg_01/memories/USER.md`.

────────────────────────────────────────────────────────────────────────────
1. ЯЗЫК И ТОНАЛЬНОСТЬ
────────────────────────────────────────────────────────────────────────────

- Язык: **русский**.
- Технические термины и команды — на английском в code-блоках.
- Тон: деловой, без шуток (Rost не любит юмор в технических отчётах).
- На «ты». Без подхалимства.
- Без канцелярита («осуществлять», «является», «данный»).

────────────────────────────────────────────────────────────────────────────
2. ФОРМАТ ОТЧЁТОВ
────────────────────────────────────────────────────────────────────────────

- Длина: 1-3 страницы для краткого отчёта, длиннее — разбить на секции.
- Заголовки: H2 (##), подзаголовки H3 (###).
- Без Markdown-таблиц, если отчёт будет отправлен в Telegram (Telegram
  не рендерит таблицы; вместо таблиц — нумерованные списки или
  key/value).
- Code-блоки для путей, команд, JSON, YAML, логов:
  ```bash
  ssh mima-g-01 'systemctl ...'
  ```
- Эмодзи только как severity-маркеры: 🚨 блокер / ⚠️ важно / 💡 идея /
  ✅ ок.
- Без emoji для украшения.

────────────────────────────────────────────────────────────────────────────
3. CSV-выгрузки
────────────────────────────────────────────────────────────────────────────

- UTF-8 с BOM (`\ufeff` в начале), чтобы Excel на Windows читал
  кириллицу.
- Разделитель: запятая.
- Заголовок: первая строка.
- Даты: ISO 8601 (`YYYY-MM-DD` или `YYYY-MM-DDTHH:MM:SS`).
- Числа: точка как десятичный разделитель.
- Без комментариев — это данные, не код.

────────────────────────────────────────────────────────────────────────────
4. ИМЕНА ФАЙЛОВ
────────────────────────────────────────────────────────────────────────────

- Tasks: `TASK-YYYY-MM-DD-kebab-case.md`
- Outputs: `<topic>_v<N>.<ext>` или просто `<topic>.<ext>`.
- Без пробелов в именах (кроме случаев, когда имя — это цитата).
- Расширения — общепринятые: `.md`, `.csv`, `.json`, `.yaml`, `.pdf`.

────────────────────────────────────────────────────────────────────────────
5. ЛОГИ И СТАТУСЫ
────────────────────────────────────────────────────────────────────────────

- Использовать шаблон `task-template.md` для задач.
- Использовать шаблон `report-template.md` для отчётов.
- Каждое изменение состояния фиксировать в `progress.json` /
  plans/<task-id>.md.

────────────────────────────────────────────────────────────────────────────
6. БЕЗОПАСНОСТЬ
────────────────────────────────────────────────────────────────────────────

- **Никогда** не включать в outputs:
  - токены (TELEGRAM_BOT_TOKEN, ANTHROPIC_API_KEY, и т.п.);
  - приватные ключи или их fingerprint'ы;
  - содержимое `/etc/shadow`;
  - данные, требующие авторизации.
- Если в выводе случайно проскочил токен — заменить на `***`.
- В repo не пушить `.env`, `state.db`, `gateway.*`, `*.bak`.
